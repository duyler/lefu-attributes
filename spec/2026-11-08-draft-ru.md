# Lefu — Specification
=====================

Lefu is not another static analyzer
Lefu — строго типизированный диалект PHP. Рождён на острове Лефу, у берегов Хайшэньвэя.

Статус документа: `[DRAFT]` — охват не завершён, но разделы с `[ACCEPTED]` считаются зафиксированными.
Дата: 2026-11-09
Назначение: техническое описание диалекта PHP с закрытой, неподавляемой моделью типов.

## 0. Суть и философия

> **Статус раздела:** `[ACCEPTED]` — все подразделы утверждены.

lefu — **закрытый диалект PHP** с неподавляемой моделью типов.
Не анализатор, а язык с собственными правилами, реализуемый
внешним анализатором и декларативными атрибутами. Код на lefu —
валидный PHP, но подчиняется строгой дисциплине.

Все публичные имена диалекта — в **глобальном namespace** (без
префикса). Имена диалекта — часть синтаксиса, не API пакета.

### 0.1. Ключевые принципы

> `[ACCEPTED]` — принципы 1–10 (исходные) и 11 (добавлен 2026-11-08).

1. **Имя = семантика.** Каждое имя диалекта — полное слово или
   композит полных слов. Сокращения запрещены (R7).
2. **Нет escape hatches.** Нет inline-подавлений, нет `unsafe`,
   нет исключений из правил на уровне файла или строки.
3. **Нет магии.** Всё, что PHP позволяет убрать, — убрано и
   заменено атрибутами. Всё, что PHP требует синтаксически, —
   сохранено как вынужденный заполнитель.
4. **Нет опциональности.** Файл либо в диалекте, либо нет.
   Третьего не дано.
5. **Минимум наследования.** Наследование классов запрещено.
   Только композиция и способности.
6. **Минимум type guards.** Один type guard — `Types::matches`
   с литеральным Type. Narrows только с литералом.
7. **Строгое сравнение.** `==`, `!=`, `<>`, `switch`, `empty()`,
   `?:`, truthy-check — запрещены.
8. **Явность.** Каждый тип, каждая видимость, каждая
   расширяемость — объявлены через атрибуты.
9. **Комментарий — исключительный случай.** Только `//`
   с префиксом и только в теле метода. Всё остальное —
   `#[Doc]` и `#[Throws]`.
10. **Нативное представление.** Публичные имена диалекта —
    в глобальном namespace. `Scalar::Int`, `#[Returns(...)]` —
    без префиксов, без `use`-импортов.
11. **Запрет с путём.** Запреты делятся на два класса:
    - **Дизайнерские** — следствие выбранной парадигмы (нет
      static properties, нет наследования, нет замыканий).
      Замена уже описана в соответствующем правиле (композиция,
      способности, callable-object). Отдельный раздел «Замена»
      не требуется.
    - **Ограничивающие** — закрывают возможность, которая
      не покрыта парадигмой lefu (`@`, `require`, `instanceof`).
      Такой запрет обязан сопровождаться либо
      конструкцией-заменой, либо trust boundary с изолированным
      API. «Нельзя, страдайте» — запрещённый подход.

    **Критерий:** если пользователь может решить задачу в рамках
    парадигмы lefu — запрет дизайнерский. Если не может —
    ограничивающий, и нужен путь.

### 0.2. Цели

> `[ACCEPTED]`

- Дать проектам, готовым к строгой дисциплине, следующий шаг после
  PHPStan/Psalm max level: неподавляемый режим проверки.
- Сделать модель типизации локальных переменных, эквивалентную
  `let`-биндингам в Rust или секции `var` в Pascal.
- Отделить ожидаемые ошибки (`Result`) от исключительных
  (`throw`/`catch`), чтобы бизнес-логика не была control flow.
- Сформулировать спецификацию так, чтобы её можно было целиком
  вставить в system prompt LLM.
- Сохранить полную совместимость с рантаймом PHP.

### 0.3. Не-цели

> `[ACCEPTED]`

- Заменить PHPStan/Psalm для всех проектов.
- Дать математическое доказательство корректности.
- Изменить сам язык PHP или рантайм.
- Поддержать существующий PHP-код без изменений.
- Избегать конфликтов с третьими пакетами (ответственность
  пользователя).


## 1. Требования

> **Статус раздела:** `[PARTIAL]` — §1.1–1.4 `[ACCEPTED]`, §1.5 `[OPEN]`.

### 1.1. Версия PHP

> `[ACCEPTED]`

**PHP 8.5 минимум.** Причины:
- Полный набор target-констант атрибутов, включая `TARGET_CONSTANT`
  и `TARGET_ALL` (значение 127).
- `#[\DelayedTargetValidation]` (8.5).
- Современные возможности языка, необходимые для целостной модели.

### 1.2. Обязательные директивы

> `[ACCEPTED]`

`declare(strict_types=1);` обязателен в каждом файле диалекта.
Отсутствие — ошибка `R0.missing-strict-types`.

### 1.3. Синтаксические возможности

> `[ACCEPTED]`

- `new` в аргументах атрибутов (8.1+) — рабочий механизм.
- Enum (8.1+) — для `Scalar`, `Special`, `Visibility`.
- Readonly properties (8.1+) — **запрещены** в closed (заменены
  `#[Immutable]`).

### 1.4. Установка

> `[ACCEPTED]`

```bash
composer require --dev lefu/attributes
```

Пакет `lefu/attributes` содержит runtime-компоненты в **глобальном
namespace** (без префикса `Lefu\`): enum'ы `Scalar`, `Special`,
`Visibility`; классы `ObjectOf`, `ListOf`, `Map`, `Union`,
`Types`, `Result`, `ThrownValue`, `Output`; интерфейс
`ThrowablePayload`; атрибуты `Property`, `Parameter`, `Variable`,
`Returns`, `Unit`, `Nothing`, `Immutable`, `Cloneable`, `VisibleAs`,
`Throws`, `Doc`; способности `Equatable`/`WithEquatable`,
`Hashable`/`WithHashable`, `Comparable`/`WithComparable`.

**Публичные имена — часть синтаксиса диалекта, не API пакета.**
Использование в глобальном namespace — осознанное решение.
Конфликты с третьими пакетами — ответственность пользователя.
Конфликты с будущими версиями PHP core — принимаемый риск,
решение по мере поступления.

Анализатор устанавливается отдельно как dev-зависимость
(`lefu/analyzer`).

### 1.5. Локальная верификация

> `[OPEN]` — не проведена. Зависит от §15.1.

`case Int` / `case Bool` / `case Null` в enum — требуют проверки
на целевой версии PHP. Если не работают — замена на
`Scalar::IntType`, `Scalar::BoolType`, `Scalar::NullType`
(см. §15.1).


## 2. Терминология

> **Статус раздела:** `[ACCEPTED]` — добавлена заметка о вынужденном заполнителе для stdlib-исключений, Tuple.

- **Диалект** — lefu closed mode. Единственный режим.
- **Closed-файл** — файл диалекта. Активируется конфигом по
  умолчанию, кроме `exclude` и `bridge`.
- **Bridge** — файл на границе мира. Маркер `// lefu: bridge`.
- **Excluded** — файл вне диалекта (vendor, generated, cache).
- **Директива** — управляющий маркер `// lefu: <name>` в начале
  файла. Не является комментарием, R6 на неё не распространяется.
- **Boot-check** — валидация при старте приложения.
- **TSE** (Type State Environment) — отображение
  `variable → current_type` в каждой точке программы.
- **Narrowing** — сужение `current_type` в control flow.
- **Upper bound** — `declared_type`, неизменен.
- **Descriptor** — объект, реализующий `Type`. Используется
  в позиции типа, не является значением домена.
- **Callable-object** — объект с `__invoke`, типизированным
  через атрибуты. Единственный разрешённый callable.
- **Способность (with-ability)** — интерфейс + трейт диалекта
  (`Equatable`/`WithEquatable`, `Hashable`/`WithHashable`,
  `Comparable`/`WithComparable`). Единственный полиморфизм
  в closed-мире.
- **Within** — термин документации для трейтов способностей.
  Слово `Trait` в документации Lefu не используется.
- **Вынужденный заполнитель** — синтаксис, требуемый PHP-движком,
  не несущий семантики диалекта (`var` для свойств).
- **Вынужденный заполнитель (stdlib-исключение)** — `ThrownValue`
  наследует `Exception`; требуется PHP-рантаймом; пользовательский
  код не может наследовать `Exception` (R13).
- **Type guard** — проверка типа значения в рантайме. В closed-мире
  единственный type guard — `Types::matches` с литеральным Type.
  В bridge — нативные `is_*` и `instanceof`.
- **Trust boundary** — точка, где статическая гарантия диалекта
  уступает место runtime-проверке приложения.
- **License block** — единственный разрешённый `/* */` блок
  в начале файла, содержащий SPDX-идентификатор или Copyright.
- **Global namespace** — публичные имена диалекта без префикса
  (`Scalar`, `ObjectOf`, `#[Returns]`, ...).
- **Stdlib** — стандартная библиотека Lefu (`Output`, `Files`,
  `Arrays`, `Strings`, `Result`, `ThrownValue`, `Types`, `DI`,
  `Logger`). Имеет привилегии, которых нет у пользовательского
  кода (§17.3).
- **Tuple** — `[DEFERRED]` (v2). Фиксированная длина, разнородные
  типы. Не в пространстве типов v1 (§15.18). Деструктуризация
  Tuple запрещена (Tuple нет).


## 3. Target-константы атрибутов

> **Статус раздела:** `[ACCEPTED]`

Атрибуты PHP 8.5 могут быть привязаны к следующим сущностям:

| Target | К чему привязывается |
|---|---|
| `TARGET_CLASS` | Классы, интерфейсы, enum'ы |
| `TARGET_FUNCTION` | Именованные функции |
| `TARGET_METHOD` | Методы классов |
| `TARGET_PROPERTY` | Свойства классов |
| `TARGET_CLASS_CONSTANT` | Константы класса |
| `TARGET_PARAMETER` | Параметры функций и методов |
| `TARGET_CONSTANT` | Глобальные константы (`const`) |
| `TARGET_ALL` | Все вышеперечисленные (значение 127) |

Все атрибуты диалекта объявляют свои target-ы явно. Применение
к недопустимому target'у — ошибка `R7.invalid-target`.

**Promoted properties запрещены** (R16). Параметр и свойство —
разные сущности с разными target'ами и разными атрибутами.


## 4. Пространство типов

> **Статус раздела:** `[PARTIAL]` — §4.8 `[PARTIAL]` (способности `[OPEN]` §15.8), остальное `[ACCEPTED]`.

### 4.1. Интерфейс Type

> `[ACCEPTED]`

```php
interface Type
{
    public function describe(): string;
    public function accepts(mixed $value): bool;
}
```

### 4.2. Scalar (enum)

> `[ACCEPTED]` — но см. §15.1 (верификация `case Int` / `case Null`).

```php
enum Scalar: string implements Type
{
    case Int    = 'int';
    case String = 'string';
    case Bool   = 'bool';
    case Float  = 'float';
    case Null   = 'null';

    public function describe(): string { return $this->value; }

    public function accepts(mixed $value): bool
    {
        return match ($this) {
            self::Int    => is_int($value),
            self::String => is_string($value),
            self::Bool   => is_bool($value),
            self::Float  => is_float($value),
            self::Null   => $value === null,
        };
    }
}
```

### 4.3. Special (enum)

> `[ACCEPTED]`

```php
enum Special: string implements Type
{
    case Any    = 'Any';
    case Object = 'object';
    case Array  = 'array';

    public function describe(): string { return $this->value; }

    public function accepts(mixed $value): bool
    {
        return match ($this) {
            self::Any    => true,
            self::Object => is_object($value),
            self::Array  => is_array($value),
        };
    }
}
```

**Подтипы:**
- `Special::Object ⊆ Special::Any`
- `Special::Array ⊆ Special::Any`
- `ObjectOf(Foo) ⊆ Special::Object`
- `ListOf(T) ⊆ Special::Array`
- `Map(K,V) ⊆ Special::Array`
- `T ⊆ Special::Any` для любого T.

`Special::Any` — top type. Использование без сужения — ошибка
`R4.any-without-narrowing`.

### 4.4. ObjectOf

> `[ACCEPTED]`

```php
final class ObjectOf implements Type
{
    public function __construct(public readonly string $className) {}

    public function describe(): string { return $this->className; }

    public function accepts(mixed $value): bool
    {
        return $value instanceof $this->className;
    }
}
```

`$className` может быть именем класса **или интерфейса**.
Семантика:
- `ObjectOf(Class::class)` — «экземпляр класса Class».
- `ObjectOf(Interface::class)` — «объект, реализующий контракт
  Interface».

`accepts()` использует `instanceof` для обоих. Интерфейс —
номинальный тип, не структурный.

### 4.5. Композиты

> `[ACCEPTED]`

```php
final class ListOf implements Type
{
    public function __construct(public readonly Type $item) {}

    public function describe(): string
    {
        return "list<{$this->item->describe()}>";
    }

    public function accepts(mixed $value): bool
    {
        if (!is_array($value) || !array_is_list($value)) {
            return false;
        }
        foreach ($value as $item) {
            if (!$this->item->accepts($item)) {
                return false;
            }
        }
        return true;
    }
}

final class Map implements Type
{
    public function __construct(
        public readonly Type $key,
        public readonly Type $value,
    ) {}

    public function describe(): string
    {
        return "array<{$this->key->describe()}, {$this->value->describe()}>";
    }

    public function accepts(mixed $value): bool
    {
        if (!is_array($value)) {
            return false;
        }
        foreach ($value as $k => $v) {
            if (!$this->key->accepts($k) || !$this->value->accepts($v)) {
                return false;
            }
        }
        return true;
    }
}

final class Union implements Type
{
    /** @var Type[] */
    public readonly array $types;

    public function __construct(Type ...$types)
    {
        if (count($types) < 2) {
            throw new \InvalidArgumentException(
                'Union must have at least 2 types'
            );
        }
        $this->types = $types;
    }

    public function describe(): string
    {
        return implode('|', array_map(
            fn(Type $t) => $t->describe(),
            $this->types,
        ));
    }

    public function accepts(mixed $value): bool
    {
        foreach ($this->types as $type) {
            if ($type->accepts($value)) {
                return true;
            }
        }
        return false;
    }
}
```

### 4.6. Union (правила использования)

> `[ACCEPTED]`

**Разрешён:**
- `Union(Scalar::A, Scalar::B)` — скалярные суммы.
- `Union(T, Scalar::Null)` — nullable (T — скаляр или ObjectOf).
- `Union(ObjectOf(Foo), Scalar::Null)` — nullable объект.

**Запрещён:**
- `Union(ObjectOf(A), ObjectOf(B))` где A ≠ B —
  `R14.union-of-objects-forbidden`.
- Любой Union, содержащий два и более `ObjectOf`.

**Замена:**
- общая способность (если Dog и Cat делают что-то общее);
- enum-дискриминатор (явный класс с `match`, если поведение разное);
- nullable Union (если один из вариантов — null).

### 4.7. Visibility (enum, отдельно от Type)

> `[ACCEPTED]`

```php
enum Visibility: string
{
    case Private   = 'private';
    case Protected = 'protected';
    case Public    = 'public';
}
```

### 4.8. Types — единственный type guard

> `[PARTIAL]` — базовая модель `[ACCEPTED]`, narrowing для способностей `[OPEN]` (§15.8).

```php
final class Types
{
    public static function matches(mixed $value, Type $type): bool
    {
        return $type->accepts($value);
    }
}
```

**Narrowing-правило:** `Types::matches` сужает тип **только если
второй аргумент — литеральный Type-объект**:

```php
// Narrows:
if (Types::matches($x, Scalar::Int)) { /* $x: Scalar::Int */ }
if (Types::matches($x, new ObjectOf(Foo::class))) { /* $x: ObjectOf(Foo) */ }

// НЕ narrows (runtime check):
if (Types::matches($x, $expectedType)) { /* $x: прежний тип */ }
```

`Types::matches($x, Equatable::class)` — проверка способности,
сужает `Special::Object` до `Equatable`. **Статус:** `[OPEN]`,
см. §15.8.

### 4.9. Маркеры возврата и свойств

> `[ACCEPTED]`

```php
#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Unit {}

#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Nothing {}

#[Attribute(Attribute::TARGET_PROPERTY | Attribute::TARGET_CLASS)]
final class Immutable {}

#[Attribute(Attribute::TARGET_CLASS)]
final class Cloneable {}
```

- `#[Unit]` — метод возвращает управление без значения
  (аналог `void`, unit-тип).
- `#[Nothing]` — метод не возвращает управление (throw/exit/
  infinite loop, bottom-тип).
- `#[Immutable]` — свойство (или класс) не переприсваивается
  после инициализации (аналог `readonly`, но через атрибут).
- `#[Cloneable]` — класс разрешает клонирование через `clone`.

**Причина переименования Unit/Nothing:** `void` (PHP 7.1+) и
`never` (PHP 8.1+) зарезервированы в PHP как ключевые слова и
не могут быть именами классов/атрибутов.

### 4.10. Запрещённые типы и конструкции

> `[ACCEPTED]` — добавлен Tuple `[DEFERRED]`.

- `mixed` — запрещён (R4), включая нативный `: mixed`.
- Plain `array` без параметров — не тип (R4).
- `iterable`, `callable`, `resource`, `numeric` — вне scope.
- `void`/`never` как типы значений — только `#[Unit]`/`#[Nothing]`.
- `readonly` — запрещён (R8), заменён `#[Immutable]`.
- Замыкания — запрещены (R9).
- Анонимные классы — запрещены (R11).
- Property hooks — запрещены (R12), кроме accessor-сахара.
- Virtual/computed properties — запрещены (R12).
- Asymmetric visibility — запрещена (R12).
- Нативные модификаторы (`public`/`private`/`protected`/`final`) —
  запрещены (R14).
- Static свойства — запрещены (R15).
- Promoted properties — запрещены (R16).
- Нативные type guards (`is_int`, `is_string`, `is_array`,
  `is_object`, `instanceof`, `is_a`, `is_callable`, `is_iterable`,
  `is_resource`) — запрещены (R14).
- Пользовательские type guards — запрещены (R14).
- `Union` объектов — запрещён (R14).
- `throw` не `ThrownValue` — `R18.throw-not-thrownvalue`.
- `catch` не `ThrownValue` — `R18.catch-native-forbidden`.
- `==`, `!=`, `<>` — запрещены (R17).
- `switch`, `empty()`, `$x ?: $y`, truthy-check — запрещены (R17).
- Наследование классов (`abstract class`, `extends`) — запрещено
  (R13). Исключение — stdlib `ThrownValue` (вынужденный заполнитель).
- `abstract` — запрещён (R13).
- `in_array` без `true`, `array_search` без `true` — запрещены (R17).
- `echo`, `print`, `printf` — запрещены (R5), заменены `Output`.
- `var_dump`, `print_r`, `var_export` — запрещены (R5), заменены
  `Output::debug`.
- `yield` / генераторы — запрещены (R5).
- `Tuple` — `[DEFERRED]`, не в пространстве типов v1 (§15.18).
  Деструктуризация Tuple запрещена.


## 5. Атрибуты диалекта

> **Статус раздела:** `[PARTIAL]` — §5.8 семантика изменена (см. §6), §5.9 `[PARTIAL]` (heredoc §15.14), остальное `[ACCEPTED]`.

Все атрибуты принимают **позиционные аргументы** (named arguments
опциональны, но не рекомендуются). Сигнатуры:

```php
#[Attribute(Attribute::TARGET_PROPERTY)]
final class Property
{
    public function __construct(public readonly Type $type) {}
}

#[Attribute(Attribute::TARGET_PARAMETER)]
final class Parameter
{
    public function __construct(
        public readonly string $name,
        public readonly Type $type,
    ) {}
}

#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Variable
{
    public function __construct(
        public readonly string $name,
        public readonly Type $type,
    ) {}
}

#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Returns
{
    public function __construct(public readonly Type $type) {}
}

#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Unit {}

#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Nothing {}

#[Attribute(Attribute::TARGET_PROPERTY | Attribute::TARGET_CLASS)]
final class Immutable {}

#[Attribute(Attribute::TARGET_CLASS)]
final class Cloneable {}

#[Attribute(
    Attribute::TARGET_PROPERTY
    | Attribute::TARGET_METHOD
    | Attribute::TARGET_CLASS_CONSTANT
)]
final class VisibleAs
{
    public function __construct(public readonly Visibility $visibility) {}
}

#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Throws
{
    public function __construct(public readonly ObjectOf $exception) {}
}

#[Attribute(
    Attribute::TARGET_CLASS
    | Attribute::TARGET_METHOD
    | Attribute::TARGET_FUNCTION
    | Attribute::TARGET_PROPERTY
    | Attribute::TARGET_CLASS_CONSTANT
)]
final class Doc
{
    public function __construct(public readonly string $text) {}
}
```

### 5.1. `#[Variable]`

> `[ACCEPTED]`

Объявляет локальную переменную метода или функции.

```php
#[Variable('total', Scalar::Int)]
#[Variable('user', new ObjectOf(User::class))]
#[Variable('items', new ListOf(new ObjectOf(OrderItem::class)))]
#[Variable('map', new Map(Scalar::String, new ListOf(new ObjectOf(Order::class))))]
function process($user)
{
    $total = 0;
    $items = [];
    $map   = [];
    // ...
}
```

### 5.2. `#[Returns]`

> `[ACCEPTED]`

Объявляет возвращаемый тип значения. Не используется для
`Unit`/`Nothing` (для них — маркеры).

```php
#[Returns(Scalar::Int)]
#[Returns(new ObjectOf(User::class))]
#[Returns(new Union(Scalar::Int, Scalar::Null))]
#[Returns(Special::Any)]
#[Returns(Special::Object)]
#[Returns(Special::Array)]
function foo() { ... }
```

### 5.3. `#[Parameter]`

> `[ACCEPTED]`

Объявляет тип параметра метода или функции.

```php
#[Parameter('user', new ObjectOf(User::class))]
#[Parameter('count', Scalar::Int)]
function foo($user, $count) { ... }
```

### 5.4. `#[Property]`

> `[ACCEPTED]`

Объявляет тип свойства класса.

```php
#[Property(new ObjectOf(OrderRepository::class))]
var $orderRepository;
```

Target — только `PROPERTY`. На параметре — `R7.invalid-target`.
Promoted properties запрещены (R16).

### 5.5. `#[Immutable]`

> `[ACCEPTED]`

Свойство (или все свойства класса) не переприсваивается после
инициализации.

```php
#[Immutable]
class Config
{
    #[Property(Scalar::String)]
    var $name;

    #[Parameter('name', Scalar::String)]
    function __construct($name)
    {
        $this->name = $name;
    }
}
```

`#[Immutable]` на классе — все свойства immutable.
Per-property `#[Immutable]` на классе с `#[Immutable]` — ошибка
`R8.redundant-marker`.

Строгая семантика: свойство инициализируется **только** в
конструкторе класса, где объявлено. Переприсваивание — ошибка
`R2.immutable-reassign`. Если конструктор не инициализирует —
`R2.immutable-not-initialized`.

### 5.6. `#[Cloneable]`

> `[ACCEPTED]`

Класс разрешает клонирование через `clone`.

```php
#[Cloneable]
class Money
{
    #[Property(Scalar::Int)]
    var $amount;

    #[Parameter('amount', Scalar::Int)]
    function __construct($amount)
    {
        $this->amount = $amount;
    }
}

$m1 = new Money(100);
$m2 = clone $m1;  // OK
```

`clone $x` разрешён, только если тип `$x` — класс с `#[Cloneable]`.
Иначе — `R17.clone-not-cloneable`.

### 5.7. `#[VisibleAs]`

> `[ACCEPTED]`

Устанавливает видимость свойства, метода или константы.

```php
#[Property(Scalar::String)]
#[VisibleAs(Visibility::Private)]
var $name;

#[Returns(Scalar::String)]
#[VisibleAs(Visibility::Protected)]
function formatName() { ... }

#[VisibleAs(Visibility::Private)]
const INTERNAL_KEY = 'secret';
```

Default — `Visibility::Public` (атрибут опускается).
Target — `PROPERTY`, `METHOD`, `CLASS_CONSTANT`. На параметре —
`R7.invalid-target`.

**Константы:** разрешены `Visibility::Public` (default) и
`Visibility::Private`. `Visibility::Protected` на константе —
запрещён (`R14.protected-constant-forbidden`).

### 5.8. `#[Throws]`

> `[ACCEPTED]` — семантика изменена (2026-11-08), см. §6.

Декларация payload, с которым метод или функция может бросить
`ThrownValue`.

```php
#[Throws(new ObjectOf(OrderNotFound::class))]
#[Throws(new ObjectOf(PaymentFailed::class))]
#[Parameter('order', new ObjectOf(Order::class))]
#[Returns(Scalar::Int)]
function process($order) { ... }
```

Target — `METHOD`, `FUNCTION`. Может быть несколько `#[Throws]`
на одном методе. Принимает `ObjectOf(FQCN)` — класс, реализующий
`ThrowablePayload`. Семантика: метод может бросить `ThrownValue`
с payload этого типа.

**Не анализируется в flow analysis.** Это декларация метаинформации
для документации и вызывающего кода. Межпроцедурный анализ
исключений — вне scope диалекта. `#[Throws]` — это **обещание**
разработчика, а не доказательство.

**Не реализует `Type`.** Регистрируется как известный атрибут.

### 5.9. `#[Doc]`

> `[PARTIAL]` — базовая семантика `[ACCEPTED]`, heredoc `[OPEN]` (§15.14).

Документация класса, метода, функции, свойства или константы.

```php
#[Doc('Processes an order and returns the total amount.')]
#[Parameter('order', new ObjectOf(Order::class))]
#[Returns(Scalar::Int)]
function process($order) { ... }

#[Doc('Default timeout in seconds.')]
const TIMEOUT = 30;
```

Target — `CLASS`, `METHOD`, `FUNCTION`, `PROPERTY`,
`CLASS_CONSTANT`. Принимает `string`. Многострочный текст — через
`\n` в строке или heredoc (проверить работоспособность heredoc
в аргументах атрибутов локально, см. §15.14).

**Не реализует `Type`.** Регистрируется как известный атрибут.

**Заменяет докблоки полностью.** Докблоки запрещены (R6.4).

### 5.10. R8 (No Redundancy)

> `[ACCEPTED]`

**В closed-файле нативные хинты запрещены** — `R8.hint-in-closed`.

**В bridge-файле атрибуты Lefu запрещены** —
`R8.attribute-in-bridge`. Хинты и модификаторы обязательны.

**Маркеры vs синтаксис:**
- `#[Unit]` + `: void` — ошибка.
- `#[Nothing]` + `: never` — ошибка.
- `#[Immutable]` + `readonly` — ошибка.

### 5.11. R10 (Type Descriptor Is Not a Value)

> `[ACCEPTED]`

`Scalar::*`, `Special::*`, `ObjectOf(...)`, `ListOf(...)`,
`Map(...)`, `Union(...)` — **дескрипторы типов, не значения**.

Использование дескриптора как значения разрешено **только если
объявленный тип цели — `Special`, `Scalar` или `Type`**.

```php
#[Returns(Special::Any)]
function decode(string $json)
{
    return Special::Any;  // ERROR: R10 — возврат дескриптора
}

#[Returns(new ObjectOf(Special::class))]
function resolve(string $name): Special
{
    return Special::Any;  // OK: метод возвращает дескриптор
}
```

Код: `lefu.R10.type-descriptor-as-value`. Диагностика
образовательная: объясняет разницу, даёт два пути исправления.

### 5.12. R7 (No Abbreviations)

> `[ACCEPTED]`

Имена, **вводимые диалектом**, — полные слова или композиты полных
слов. Сокращения запрещены.

**Исключение: заимствованные имена PHP-типов** (`int`, `bool`,
`float`, `string`, `null`, `void`, `never`, `mixed`, `iterable`,
`object`, `callable`, `array`). Они сохраняются как есть, даже если
являются сокращениями в английском, потому что альтернатива —
дублирование имён и разрыв с тайп-хинтами PHP.

**Операционный тест:** если имя можно заменить на полное слово
**без создания второго имени для того же понятия в PHP** — это
сокращение диалекта, запрещено. Если замена создаёт дублирование
(`Integer` vs `int`) — это заимствование, разрешено.

Примеры:
- `ObjectOf`, `ListOf`, `Map`, `Union`, `Scalar`, `Special`,
  `Variable`, `Returns`, `Parameter`, `Visibility`, `Types`,
  `Throws`, `Doc`, `Output`, `Result`, `ThrownValue` — разрешено.
- `Obj`, `Ref`, `Param`, `Var`, `Inst`, `Cls` — запрещено.


## 6. Модель ошибок

> **Статус раздела:** `[PARTIAL]` — §6.1–6.7 `[ACCEPTED]`, §6.8 (открытые вопросы) `[OPEN]`.

### 6.1. Философия

Lefu различает два класса ошибок:

- **Ожидаемые** (бизнес-ошибки): заказ не найден, оплата не прошла, валидация не удалась. Это часть нормального потока. Для них — `Result`.
- **Исключительные** (системные сбои, bridge, непредвиденное): соединение с БД упало, сторонняя библиотека бросила исключение. Для них — `throw`/`catch`.

Разделение принципиальное:

- `Result` — **значение**. Обрабатывается в обычном коде, без ограничений на количество выражений. Это не control flow.
- `throw`/`catch` — **control flow**. `catch` — только **точка преобразования**, не место восстановления.

Почему не только `Result`: bridge-методы бросают нативные исключения; системные сбои (OOM, `TypeError`) не превращаются в `Result`; `exit()`/`die()` — терминаторы.

Почему не только `throw`: бизнес-ошибки не должны быть control flow. `if ($orderNotFound) { ... }` — нормальный код, а не исключительная ситуация.

Модель ошибок следует принципам §0.1: `Result` — значение, не control flow (принцип 8 — явность); `catch` — только преобразование (принцип 2 — нет escape hatches для бизнес-логики в `catch`); `ThrownValue extends Exception` — вынужденный заполнитель (принцип 3 — нет магии, но PHP-рантайм требует).

### 6.2. ThrowablePayload

```php
interface ThrowablePayload {}
```

Пустой маркер-интерфейс. Класс реализует `ThrowablePayload`, если его экземпляр может быть payload для `ThrownValue`.

Payload — **данные**, не поведение. Он не знает, как его обрабатывать. Никаких `recover()`, `describe()`. Если нужен текст для `getMessage()`, `ThrownValue::__construct` использует `get_class($payload)`.

Payload — `#[Immutable]`-класс. Ошибка не меняется после создания.

### 6.3. ThrownValue

```php
final class ThrownValue extends \Exception
{
    #[Property(new ObjectOf(ThrowablePayload::class))]
    #[VisibleAs(Visibility::Private)]
    #[Immutable]
    var $payload;

    #[Parameter('payload', new ObjectOf(ThrowablePayload::class))]
    function __construct($payload)
    {
        parent::__construct(get_class($payload));
        $this->payload = $payload;
    }

    #[Returns(new ObjectOf(Result::class))]
    function toResult()
    {
        return Result::fail($this->payload);
    }
}
```

- **Наследует `\Exception`** — вынужденный заполнитель (см. §2, §14, §17.3). Пользователь не может наследовать `Exception` (R13), stdlib может. `parent::__construct` разрешён только в stdlib-классах, наследующих `Exception`.
- **Payload** — immutable, set в конструкторе.
- **Создаётся в месте throw**: `throw new ThrownValue(new OrderNotFound($id))`. Трейс корректен (PHP записывает трейс в момент `new`). Reflection не нужен.
- **`toResult()`** — преобразование в `Result` с `error = payload`. Единственный метод.

`ThrownValue` не `#[Cloneable]`: клонирование исключений — ошибка дизайна.

### 6.4. Result

```php
#[Immutable]
final class Result
{
    #[Property(new Union(new ObjectOf(ThrowablePayload::class), Scalar::Null))]
    #[VisibleAs(Visibility::Private)]
    var $error;

    #[Property(Special::Any)]
    #[VisibleAs(Visibility::Private)]
    var $value;

    #[Parameter('error', new Union(new ObjectOf(ThrowablePayload::class), Scalar::Null))]
    #[Parameter('value', Special::Any)]
    #[VisibleAs(Visibility::Private)]
    function __construct($error, $value)
    {
        $this->error = $error;
        $this->value = $value;
    }

    #[Parameter('value', Special::Any)]
    #[Returns(new ObjectOf(Result::class))]
    static function ok($value)
    {
        return new self(null, $value);
    }

    #[Parameter('payload', new ObjectOf(ThrowablePayload::class))]
    #[Returns(new ObjectOf(Result::class))]
    static function fail($payload)
    {
        return new self($payload, null);
    }

    #[Returns(Scalar::Bool)]
    function isOk()
    {
        return $this->error === null;
    }

    #[Returns(Scalar::Bool)]
    function isErr()
    {
        return $this->error !== null;
    }

    #[Returns(Special::Any)]
    #[Throws(new ObjectOf(ThrowablePayload::class))]
    function unwrap()
    {
        if ($this->error !== null) {
            throw new ThrownValue($this->error);
        }
        return $this->value;
    }

    #[Parameter('default', Special::Any)]
    #[Returns(Special::Any)]
    function unwrapOr($default)
    {
        if ($this->error !== null) {
            return $default;
        }
        return $this->value;
    }

    #[Returns(new Union(new ObjectOf(ThrowablePayload::class), Scalar::Null))]
    function error()
    {
        return $this->error;
    }
}
```

- **Один класс, не `Ok`/`Err`.** Без дженериков `Ok`/`Err` не выразить тип значения. Один класс с `error: Union(Payload, Null)` — минимально достаточно.
- **`value: Special::Any`.** Требует сужения через `Types::matches` вне catch, где это разрешено. Альтернатива — дженерики, которых нет.
- **`isOk()`/`isErr()`** — проверка `error === null`. Не `value === null`, потому что Ok-значение может быть null.
- **`unwrap()`** — возвращает значение или бросает `ThrownValue(payload)`. `#[Throws]` декларирует контракт. Это не dependent type: return type всегда `Special::Any`, throw — отдельный control flow.
- **`unwrapOr($default)`** — никогда не бросает.
- **`error()`** — для инспекции payload.

`Result` — `#[Immutable]`. Все свойства set в конструкторе, не переприсваиваются.

**6.4.1. Почему один класс, не `Ok`/`Err` и не `Result<T, E>`.** Без дженериков `T` и `E` не выразить тип значения. `Ok`/`Err` без дженериков не работают. Один класс с `error: Union(Payload, Null)` и `value: Special::Any` — минимально достаточно. `value` требует сужения через `Types::matches` вне catch, где это разрешено.

### 6.5. Правила

**6.5.1. Result-функция.** Функция, возвращающая `Result`: `#[Returns(new ObjectOf(Result::class))]`. Не имеет `#[Throws]`.

```php
#[Parameter('id', Scalar::Int)]
#[Returns(new ObjectOf(Result::class))]
function findOrder($id)
{
    if (/* не найден */) {
        return Result::fail(new OrderNotFound($id));
    }
    return Result::ok($order);
}
```

**6.5.2. Throw-функция.** Функция, бросающая `ThrownValue`: `#[Throws(new ObjectOf(Payload::class))]`. Не возвращает `Result`.

```php
#[Parameter('id', Scalar::Int)]
#[Returns(new ObjectOf(Order::class))]
#[Throws(new ObjectOf(OrderNotFound::class))]
function findOrder($id)
{
    if (/* не найден */) {
        throw new ThrownValue(new OrderNotFound($id));
    }
    return $order;
}
```

**6.5.3. Catch — только преобразование.** Единственная допустимая форма тела catch — `return $e->toResult();` или `throw $e;`. Всё остальное — `R18.catch-not-toresult`.

```php
try {
    $order = $this->findOrder($id);
} catch (ThrownValue $e) {
    return $e->toResult();
}
```

**6.5.4. Запрет смешения.** Функция не может быть Result-функцией и Throw-функцией одновременно: `R18.result-and-throw-mixed`.

**6.5.5. Throw только ThrownValue.** В closed-файле `throw` разрешён только для `ThrownValue`: `R18.throw-not-thrownvalue`. Нативные исключения (из bridge, системные) пробрасываются без `catch` — это trust boundary.

**6.5.6. Catch только ThrownValue.** В closed-файле `catch` разрешён только для `ThrownValue`: `R18.catch-native-forbidden`. Нативные исключения не ловятся в closed — только в bridge или на верхнем уровне приложения.

**6.5.7. ThrownValue создаётся в месте throw.** `throw new ThrownValue(...)` — inline. `$e = new ThrownValue(...); throw $e;` — разрешено, но трейс может указывать на строку `new`, а не `throw`. Рекомендуется inline.

**6.5.8. Bridge — trust boundary.** Bridge-методы могут бросать нативные исключения. Closed-код их не ловит. Если bridge-метод должен возвращать ошибку в closed-мир — он возвращает `Result` (через `toResult()` внутри bridge) или бросает `ThrownValue` (если bridge может создать payload).

**6.5.9. `finally`.** Блок `finally` разрешён в closed-файлах с тремя ограничениями:

- **Нет `return`/`throw` внутри** — `R18.finally-control-flow-forbidden`. `finally` не переопределяет возврат из try/catch.
- **Только `#[Unit]`-вызовы** — `R18.finally-may-throw`. Cleanup-методы не бросают; если cleanup может бросить — это ошибка дизайна cleanup-метода, а не `finally`.
- **Не влияет на TSE** — работает с `declared_types`, не с narrowed. Переменные, объявленные в try, не видны в `finally` (кроме объявленных до try).

`try/finally` без `catch` разрешён: cleanup без перехвата.

`finally` — **базовая конструкция cleanup**. `with`-паттерн в stdlib — сахар над `finally`. Пользователь может писать свой `with` в closed-коде, используя `finally` внутри. Stdlib-методы (`Files::with`, `Transactions::with`) работают через интерфейсы (`Finalizable`, `Transactional`), чтобы покрывать кастомные ресурсы.

Пример:

```php
$file = Files::open($path);
try {
    return $this->parse($file);
} finally {
    $file->close(); // #[Unit], не бросает
}
```

Пример с `catch`:

```php
try {
    $order = $this->findOrder($id);
} catch (ThrownValue $e) {
    return $e->toResult();
} finally {
    $this->logger->flush(); // #[Unit]
}
```

`finally` с `return`/`throw` — `R18.finally-control-flow-forbidden`. `finally` с вызовом, не помеченным `#[Unit]` — `R18.finally-may-throw`.

### 6.6. Коды

- `R18.result-and-throw-mixed` — функция возвращает `Result` и имеет `#[Throws]`.
- `R18.catch-not-toresult` — тело catch не `return $e->toResult();` и не `throw $e;`.
- `R18.catch-native-forbidden` — catch ловит не `ThrownValue` в closed.
- `R18.throw-not-thrownvalue` — throw бросает не `ThrownValue` в closed.
- `R18.finally-control-flow-forbidden` — `finally` содержит `return`/`throw`.
- `R18.finally-may-throw` — `finally` содержит вызов, не помеченный `#[Unit]`.

### 6.7. Примеры

**Result-функция с обработкой:**

```php
$result = $this->findOrder($id);
if ($result->isErr()) {
    $err = $result->error();
    if (Types::matches($err, new ObjectOf(OrderNotFound::class))) {
        // $err: ObjectOf(OrderNotFound)
        return $this->handleNotFound($err);
    }
    throw new ThrownValue($err);
}
$order = $result->unwrap();
```

**Throw-функция с catch:**

```php
try {
    $order = $this->findOrder($id);
} catch (ThrownValue $e) {
    return $e->toResult();
}
```

**Bridge с нативным исключением:**

```php
// bridge-файл
public function fetch(string $url): array
{
    $response = $this->client->get($url);
    if ($response->getStatusCode() !== 200) {
        throw new \RuntimeException('API error');
    }
    return json_decode($response->getBody()->getContents(), true);
}

// closed-файл
try {
    $data = $this->apiClient->fetch($url);
} catch (ThrownValue $e) {
    // Это не поймает RuntimeException из bridge!
    // RuntimeException пробрасывается до верхнего уровня.
}
```

**Bridge, преобразующий нативное исключение в Result:**

```php
// bridge-файл
public function fetch(string $url): Result
{
    try {
        $response = $this->client->get($url);
        if ($response->getStatusCode() !== 200) {
            return Result::fail(new ApiError($url));
        }
        return Result::ok(json_decode($response->getBody()->getContents(), true));
    } catch (\RuntimeException $e) {
        return Result::fail(new ApiError($url));
    }
}
```

## 7. Правила R0–R17 и I0–I3

> **Статус раздела:** `[PARTIAL]` — R5, R12, R13, R14, I0–I3 `[PARTIAL]`, остальные `[ACCEPTED]`.

### R0. Гигиена файла

> `[ACCEPTED]` — добавлен `unsupported-declare`.

- `lefu.R0.missing-strict-types` — нет `declare(strict_types=1)`.
- `lefu.R0.unreachable-code` — недостижимый код после terminator.
- `lefu.R0.unsupported-declare` — `declare`, отличный от `strict_types=1`.

**`declare(strict_types=1);`** — единственный разрешённый `declare`. Обязателен в каждом closed-файле (§1.2). Любой другой `declare` (`ticks`, `encoding`, блочная форма `strict_types`) — `R0.unsupported-declare`.

**Причина:** `ticks` — глобальное состояние через `register_tick_function`, противоречит принципам 3 (нет магии) и 8 (явность). `encoding` — игнорируется в PHP 8.0+. Блочная форма `strict_types` создаёт вариативность «strict/не strict» внутри файла.

### R1. Полная декларация

> `[ACCEPTED]`

- Каждая локальная переменная — в `#[Variable]`.
- Каждый параметр — в `#[Parameter]` (closed mode).
- Каждое свойство — в `#[Property]` (closed mode).
- Возврат — в `#[Returns]` / `#[Unit]` / `#[Nothing]`.

Коды:
- `R1.undeclared-variable`
- `R1.untyped-parameter`
- `R1.untyped-return`
- `R1.untyped-property`
- `R1.undeclared-foreach-var`
- `R1.undeclared-catch-var`
- `R1.missing-return`

Исключения: `$this`, суперглобалы.

### R2. Инвариантность типа (upper bound)

> `[ACCEPTED]`

`declared_type` — верхняя граница. `current_type ⊆ declared_type`.
Присваивание: `expr_type ⊆ declared_type`. Narrowing — refinement,
не смена типа. Join — `Union` `current_types` при слиянии веток.

Коды:
- `R2.type-mismatch`
- `R2.incompatible-assignment`
- `R2.unit-returns-value`
- `R2.unit-result-used`
- `R2.nothing-returns`
- `R2.immutable-reassign`
- `R2.immutable-not-initialized`

**Immutable (строгая семантика):** свойство инициализируется только
в конструкторе класса, где объявлено.

### R3. Запрет переиспользования имён

> `[ACCEPTED]`

В пределах метода имя переменной объявляется один раз.

Коды:
- `R3.duplicate-declaration`
- `R3.reused-name`

### R4. Запрет mixed и Any без сужения

> `[ACCEPTED]`

- `mixed` запрещён, включая нативный `: mixed`.
- `Special::Any` требует сужения перед использованием.
- Plain `array` без параметров — не тип.

Коды:
- `R4.mixed-forbidden`
- `R4.any-without-narrowing`

### R5. Запрет динамических конструкций и подавления

> `[PARTIAL]` — новые коды `[ACCEPTED]`, `Files::requirePhp` `[OPEN]` (§15.17).

Запрещены:
- `extract()`, `parse_str()` (без явного `result`).
- `$$var`, `${...}`.
- `eval()`.
- `compact()` в теле метода.
- `func_get_args()`, `func_num_args()`.
- `global`.
- Ссылки (`&$x`, `use (&$x)`).
- `__get`/`__set`/`__call`/`__callStatic`.
- `__isset`/`__unset`.
- `register_tick_function()` / `unregister_tick_function()` — глобальные функции с побочными эффектами, бессмысленны без `declare(ticks=1)`.
- `var_dump()` / `print_r()` / `var_export()` — отладочный вывод. Замена: `Output::debug` (§17.2).

Код: `lefu.R5.dynamic-construct-forbidden`.

**Дополнительные запреты:**

- **`echo` / `print` / `printf`** — `R5.echo-forbidden`.
  Вывод в stdout/stderr в обход `Output`. Замена: `Output::write` / `Output::error` / `Strings::format` (§17.2).

- **`yield` / генераторы** — `R5.generator-forbidden`.
  В closed-файле генераторы запрещены: в пространстве типов Lefu нет `Generator`, `iterable` вне scope, ленивая итерация не поддерживается. Замена: материальные `ListOf(T)` / `Map(K, V)`. `[DEFERRED]` — пересмотреть после появления `Generator` в пространстве типов.

- **`__destruct`** — `R5.destructor-forbidden`.
  В closed-файле деструктор запрещён: GC непредсказуем, cleanup не гарантирован (не вызывается при `exit()`, может не вызваться вообще). Замена: `try/finally` для block-level cleanup (§6.5.9), `[#finalize]` через DI для application-level cleanup (§11.8). В bridge — разрешён (внешние библиотеки могут полагаться на деструкторы).

- **`@` (error suppression)** — `R5.error-suppression-forbidden`.
  Подавляет ошибки рантайма, что делает поведение кода
  непредсказуемым для анализатора. Замена: явная обработка через
  `try`/`catch` или `#[Throws]`.

- **Backticks (`` `cmd` ``)** — `R5.shell-exec-forbidden`.
  Выполнение произвольной команды вне модели типов. Замена:
  bridge-файл, если shell действительно нужен.

- **`goto`** — `R5.goto-forbidden`.
  Неструктурированный переход, ломающий CFG и TSE. Замена:
  структурированные конструкции (`if`, `match`, `return`).

- **`include`, `include_once`, `require`, `require_once`** —
  `R5.include-forbidden`.
  Загрузка кода вне статического анализа. Замена: autoload
  (composer) для классов; `Files::requirePhp` из стандартной
  библиотеки lefu для PHP-файлов, возвращающих данные
  (в разработке, см. §15.17); bridge — временно, до появления
  `Files::requirePhp`.

### R6. Комментарии, директивы, документация

> `[ACCEPTED]` — все подразделы.

#### R6.1. Директивы

> `[ACCEPTED]`

`// lefu: <name>` — директива анализатора. Разрешена только
в начале файла (после `<?php` и опционального license block,
до `declare(strict_types=1)`). Не считается комментарием,
R6.2–R6.7 на неё не распространяются.

Текущие директивы:
- `// lefu: bridge` — файл-мост.

#### R6.2. Комментарии

> `[ACCEPTED]`

`//` — только в теле метода/функции. Только с префиксом из списка:
`WHY:`, `TODO:`, `FIXME:`, `SEE:`, `NOTE:`.

- `R6.unstructured-comment` — `//` без префикса.
- `R6.comment-outside-body` — `//` с префиксом, но вне тела
  метода/функции.

Примеры разрешённого:
```php
function process($order)
{
    // WHY: This must run before flush to avoid a race condition.
    $this->flush();
    $this->sync();

    // TODO: Refactor to use the new API.
    // FIXME: Handles only the happy path.
    // SEE: https://github.com/org/repo/issues/1234
    // NOTE: The order of calls matters here.
}
```

Примеры запрещённого:
```php
// This method processes the order.     — R6.unstructured-comment

class Foo
{
    // TODO: refactor                     — R6.comment-outside-body
}

const DEFAULTS = [
    'timeout' => 30,  // NOTE: seconds     — R6.comment-outside-body
];
```

#### R6.3. Блочные комментарии запрещены

> `[ACCEPTED]`

`/* ... */` — запрещены везде, кроме license block (R6.8).
`R6.block-comment-forbidden`.

#### R6.4. Докблоки запрещены

> `[ACCEPTED]`

`/** ... */` — запрещены везде, включая license block (для license
используется `/* */`, не `/** */`). `R6.docblock-forbidden`.

Замена: `#[Doc('text')]` и `#[Throws(new ObjectOf(Exception::class))]`.

#### R6.5. `#`-комментарии запрещены

> `[ACCEPTED]`

`# text` — запрещены везде, кроме license block (где `#` — часть
текста лицензии). `R6.hash-comment-forbidden`.

#### R6.6. `@` в комментариях запрещён

> `[ACCEPTED]`

`@` в любом комментарии — `R6.suppression-forbidden`.

Закрывает `@psalm-suppress`, `@phpstan-ignore`, `@var`, `@param`,
`@return`, `@noinspection` и любые другие smuggle-каналы.

Распространяется и на license block. Email → `(at)`.

#### R6.8. License block (единственное исключение)

> `[ACCEPTED]`

**Разрешён один блочный комментарий `/* ... */` в начале файла.**

Правила:

1. **Расположение:** после `<?php`, до `declare(strict_types=1)`.
   Опционально до или после `// lefu: <name>` директивы.
   Если `/* */` блок появляется после `declare` или `namespace` —
   это уже не license block, а обычный блочный комментарий,
   запрещённый `R6.block-comment-forbidden`.

2. **Количество:** не более одного на файл.
   `R6.license-multiple` — больше одного.

3. **Формат:** только `/* ... */`, не `/** ... */`.

4. **Содержимое:**
   - **Освобождено** от `R6.unstructured-comment` (префикс
     не нужен).
   - **Освобождено** от `R6.block-comment-forbidden`.
   - **Освобождено** от `R6.hash-comment-forbidden` (внутри блока
     `#` разрешён).
   - **Не освобождено** от `R6.suppression-forbidden` (`@` запрещён).
   - **Должен содержать** `SPDX-License-Identifier:` ИЛИ
     `Copyright` (case-insensitive). Иначе — `R6.license-invalid`.
   - **Не должен содержать** PHP-код: `<?php`, `?>`, `$`,
     `function`, `class`, `namespace`. Иначе — `R6.license-code`.

5. **Рекомендация:** `SPDX-License-Identifier:` предпочтителен
   (машиночитаемый). Если есть только `Copyright` — info
   `I3.missing-spdx`, не ошибка.

Пример с SPDX:
```php
<?php
```

### R9. Замыкания запрещены

> `[ACCEPTED]`

**Замыкания (включая стрелочные) запрещены.** First-class callable
syntax (`strlen(...)`) тоже создаёт `Closure` и запрещён.

Замена: **callable-object** — объект с `__invoke`, типизированным
через `#[Parameter]` / `#[Returns]`.

```php
#[Immutable]
class DoubleInt
{
    #[Parameter('x', Scalar::Int)]
    #[Returns(Scalar::Int)]
    function __invoke($x) { return $x * 2; }
}

$doubled = Arrays::map($values, new DoubleInt());
```

Код: `lefu.R9.closure-forbidden`.

### R12. Property Hooks — только accessor-сахар

> `[PARTIAL]` — базовая версия `[ACCEPTED]`, реализация accessor-сахара `[OPEN]` (§15.7).

**Полностью запрещены в базовой версии.** Код
`R12.property-hook-forbidden`.

**Разрешены только как типизированные геттеры/сеттеры с backing
store.** Виртуальные свойства, асимметричная видимость, неявные
no-op setters — запрещены.

Правила (после активации):
1. **Backed-only.** `R12.virtual-property-forbidden`.
2. **`#[Property]` обязателен.**
3. **`#[Immutable]` + `set`-хук** — `R12.immutable-with-set-hook`.
4. **Asymmetric visibility** — `R12.asymmetric-visibility-forbidden`.
5. **Неявный no-op setter** — `R12.implicit-noop-setter-forbidden`.

**Иммутабельность R12:** окончательное, не подлежит пересмотру.

### R13. Наследование классов запрещено

> `[PARTIAL]` — базовые запреты `[ACCEPTED]`, реализация способностей `[OPEN]` (§15.2).

**Наследование классов в closed-мире запрещено полностью.**

- `abstract class` — `R13.abstract-class-forbidden`.
- `abstract` метод — `R13.abstract-method-forbidden`.
- `class Foo extends Bar` — `R13.extends-forbidden`.
- Все классы — неявно final. Нативный `final` — `R14.native-modifier-forbidden`.
- **Исключение: stdlib-класс `ThrownValue` наследует `Exception`** — вынужденный заполнитель (§2, §14, §17.3). Пользовательский код не может наследовать `Exception`.

**Замена abstract-классов:**
- Контракт (abstract методы) → `interface`.
- Общая реализация (конкретные методы) → способность
  (интерфейс + `With*` трейт).
- Общее состояние (свойства) → **композиция** (вложить
  объект-помощник).

**Трейты:**

**Полностью запрещены в базовой версии.**
`R13.trait-forbidden`.

**Разрешены только трейты способностей**
(`WithEquatable`, `WithHashable`, `WithComparable`). Остальные —
`R13.foreign-trait-forbidden`.

Правила:
- `use WithXxx` требует явного `implements Xxx` —
  `R13.trait-without-contract`.
- `implements Xxx` требует реализации всех методов контракта —
  `R13.missing-contract-method`.
- Трейт — не тип. `ObjectOf(Trait::class)` —
  `R13.trait-as-type-forbidden`.
- `insteadof` / `as` — `R13.trait-conflict-forbidden`.
- `$this` в трейте — только методы, объявленные в трейте или
  как abstract. Иначе — `R13.trait-untyped-this`.

**Способности (стандартная библиотека lefu):**

- `\Stringable` — нативный интерфейс PHP 8.0+. Ничего не
  создаём.
- `#[Cloneable]` — маркер-атрибут (не способность, не интерфейс).
- `Equatable` / `WithEquatable` (`equals`).
- `Hashable` / `WithHashable` (`hashCode`).
- `Comparable` / `WithComparable` (`compareTo`).

### R14. Нативные модификаторы, type guards, Union объектов

> `[PARTIAL]` — базовые запреты `[ACCEPTED]`, `new $className($args)` `[ACCEPTED]` (§11.3).

**Нативные модификаторы (`public`/`private`/`protected`/`final`)
запрещены в closed-файлах** — `R14.native-modifier-forbidden`.

**Вынужденные синтаксические маркеры:**
- `var` — для свойств (единственный допустимый синтаксис).

**Методы:** без модификатора = public. Видимость — `#[VisibleAs]`.
**Свойства:** `var $x;`. Видимость — `#[VisibleAs]`.
**Константы:** без модификатора = public. Видимость — `#[VisibleAs]`
(`Public` или `Private`; `Protected` запрещён).
**Классы:** без модификатора = неявно final.

**Type guards запрещены:**
- `instanceof` — `R14.instanceof-forbidden` (полностью).
- `is_int`, `is_string`, `is_bool`, `is_float`, `is_null`,
  `is_array`, `is_object`, `is_a`, `is_callable`, `is_iterable`,
  `is_resource` — `R14.native-typeguard-forbidden`.
- Пользовательские type guards — `R14.user-typeguard-forbidden`.
- Единственный разрешённый type guard — `Types::matches`
  с литеральным Type (§4.8).
- `$x === null` / `$x !== null` / `isset($x)` — **не type guards**,
  а сравнения/проверки существования. Разрешены и сужают.

**Union объектов запрещён** (§4.6) —
`R14.union-of-objects-forbidden`.

**Проверки видимости:**
- `#[VisibleAs(Visibility::Private)]` на методе, реализующем
  интерфейс — `R14.interface-method-not-public`.
- `#[VisibleAs(Visibility::Private)]` на `__toString` —
  `R14.tostring-must-be-public`.
- `#[VisibleAs]` на параметре — `R14.visibility-on-parameter`.
- `#[VisibleAs(Visibility::Protected)]` на константе —
  `R14.protected-constant-forbidden`.

**Динамическая инстанциация:**
- `new $className()` где `$className: Scalar::String` —
  **разрешено**. Результат — `Special::Object`.
- Требуется явное сужение через `Types::matches` с литеральным
  Type.
- `new $className($args)` с аргументами — **разрешено**.
  Аргументы конструктора — trust boundary (§11.5). Результат —
  `Special::Object`, требует сужения.

**Bridge:** нативные модификаторы, type guards (`is_*`,
`instanceof`) **обязательны**. Отсутствие модификатора —
`R14.bridge-missing-modifier`.

### R15. Static свойства запрещены

> `[ACCEPTED]`

**Static свойства запрещены навсегда, без альтернатив.**
`R15.static-property-forbidden`.

**Static методы разрешены.** Основа стандартной библиотеки
(`Arrays::map`, `Strings::replace`, `Types::matches`, `Output::write`).

### R16. Promoted properties запрещены

> `[ACCEPTED]`

`R16.promoted-property-forbidden`.

Причина: размывает границу свойство/параметр, требует нативного
модификатора (`var` в параметрах — parse error), создаёт
двусмысленность атрибутов.

### R17. Loose comparison и falsy-магия запрещены

> `[ACCEPTED]`

**Запрещены:**
- `==`, `!=`, `<>` — `R17.loose-comparison-forbidden`.
- `switch` — `R17.switch-forbidden`. Замена: `match`.
- `in_array` без `true` — `R17.in-array-without-strict-forbidden`.
- `array_search` без `true` —
  `R17.array-search-without-strict-forbidden`.
- `empty()` — `R17.empty-forbidden`.
- `$x ?: $y` (elvis) — `R17.elvis-forbidden`.
- `if ($x)` где `$x` не `Scalar::Bool` — `R17.truthy-check-forbidden`.

**Разрешены:**
- `===`, `!==` — strict.
- `match` — использует `===`.
- `in_array($x, $arr, true)`.
- `array_search($x, $arr, true)`.
- `$x ?? $y` — null-coalescing.
- `Types::matches($x, Scalar::Bool)`.
- `if ($x === true)` / `if ($x === false)`.

**Cloneable-проверки:**
- `R17.clone-not-cloneable` — clone без `#[Cloneable]`.

## 8. Режимы файлов и структура файла

> **Статус раздела:** `[ACCEPTED]` — §8.7 обновлён (echo/var_dump запрещены).

### 8.1. Closed mode (по умолчанию)

> `[ACCEPTED]`

Активируется **конфигом**. Всё, что не в `exclude` и не bridge, —
closed.

**Структура файла диалекта:**

```php
<?php
[опционально] /* license block, один, с SPDX или Copyright */
[опционально] // lefu: <name> (директива)
declare(strict_types=1);
[опционально] namespace ...;
[опционально] use ...;

class Foo { /* ... */ }
```

**В closed-файле:**
- Нативные хинты запрещены (R8).
- Нативные модификаторы запрещены (R14).
- Все типы — через атрибуты.
- Все свойства — `var` + `#[Property]` + `#[VisibleAs]`.
- `readonly` запрещён (R8), `#[Immutable]` — замена.
- Замыкания (R9), анонимные классы (R11), property hooks (R12),
  static свойства (R15), promoted properties (R16) — запрещены.
- Нативные type guards запрещены (R14), `Types::matches` —
  единственный type guard.
- Наследование классов запрещено (R13). Исключение — stdlib
  `ThrownValue` наследует `Exception` (§6.3).
- `throw`/`catch` только для `ThrownValue` (R18).
- `finally` с тремя ограничениями (§6.5.9).
- `__destruct` запрещён (R5), `yield` запрещён (R5).
- Loose comparison и falsy-магия запрещены (R17).
- `echo`/`print`/`printf` запрещены (R5), заменены `Output` (§17.2).
- Валидация: boot-check или CLI-check.

### 8.2. Bridge (граница мира)

> `[ACCEPTED]`

```php
<?php
// lefu: bridge
declare(strict_types=1);

namespace App\Integration;

final class ExternalApiClient
{
    public function __construct(
        private readonly \GuzzleHttp\ClientInterface $client,
    ) {}

    public function fetch(string $url): array
    {
        $response = $this->client->get($url);
        if ($response->getStatusCode() !== 200) {
            throw new \RuntimeException('API error');
        }
        return json_decode($response->getBody()->getContents(), true);
    }
}
```

**В bridge-файле:**
- Нативные хинты **обязательны**.
- Нативные модификаторы **обязательны**.
- Нативные type guards (`is_*`, `instanceof`) **обязательны**.
- Атрибуты lefu запрещены (`R8.attribute-in-bridge`).
- `extends` разрешён (включая `Exception`).
- `__destruct` разрешён.
- License block разрешён (R6.8).
- Используется для интеграции с внешним кодом: Composer-зависимости,
  PSR-интерфейсы, сторонние SDK, БД-драйверы.

### 8.3. Excluded (вне диалекта)

> `[ACCEPTED]`

Указывается в `exclude` конфига (vendor, generated, cache).
Не анализируется lefu.

### 8.4. Конфиг проекта: `lefu.toml`

> `[ACCEPTED]`

```toml
# lefu.toml
mode = "closed"

exclude = [
    "vendor/**",
    "var/**",
    "generated/**",
]

[attributes]
# Пользовательские атрибуты, известные lefu (не вызывают I1)
known = [
    "App\\Attribute\\AuditLog",
    "App\\Attribute\\Cacheable",
    "Duyler\\DI\\Attribute\\Finalize",
]
```

### 8.5. Бинарность

> `[ACCEPTED]`

Файл либо closed (по умолчанию), либо bridge (маркер), либо
excluded (конфиг). Третьего нет. Файл исключений не существует.
Миграция — по файлам, не по правилам.

### 8.6. У lefu нет `unsafe`

> `[ACCEPTED]`

Rust `unsafe` — для FFI, raw pointers, transmute. В PHP этого нет.
Граница с внешним кодом — bridge-файлы, а не `unsafe`.

### 8.7. Встроенные функции PHP: переходный период

> `[ACCEPTED]` — обновлено: `echo`/`print`/`printf`/`var_dump` запрещены с v1.

**Текущее состояние:** встроенные функции PHP разрешены, но:
- callable-аргументы — только callable-object, не замыкание (R9);
- `in_array`/`array_search` — только с третьим аргументом `true`
  (R17).

**Целевое состояние:** все встроенные функции PHP запрещены.
Вместо них — статические методы стандартной библиотеки
(`Arrays::map`, `Strings::replace`, `Types::matches`, `Output::write`).
Это решает проблему callable-аргументов полностью: статические
методы принимают типизированные интерфейсы (`Mapper<T, R>`
с `__invoke`), проверяемые lefu.

**Вывод (`echo`, `print`, `printf`)** — **запрещены в closed с v1** (`R5.echo-forbidden`). `Output` в stdlib с v1 (§17.2) — единственный способ вывода. `echo`/`print`/`printf` — второй способ, вариативность. Замена: `Output::write` (stdout), `Output::error` (stderr), `Strings::format` + `Output::write` (форматирование).

**Отладка (`var_dump`, `print_r`, `var_export`)** — запрещены в closed (`R5.dynamic-construct-forbidden`). Замена: `Output::debug` (§17.2).


## 9. Flow analysis

> **Статус раздела:** `[PARTIAL]` — §9.4 и §9.7 `[PARTIAL]`, остальное `[ACCEPTED]`.

### 9.1. Модель

> `[ACCEPTED]`

Flow-sensitive typing with declared upper bound. В каждой точке
программы анализатор ведёт TSE: `variable → current_type`.

Инвариант: `current_type(v) ⊆ declared_type(v)`.

### 9.2. Операции

> `[ACCEPTED]`

- `narrow(tse, cond) → (tse_true, tse_false)`.
- `join(tse1, tse2) → tse`.
- `assign(tse, var, expr_type) → tse'`.
- `check(tse, expr, expected_type) → ok | error`.

### 9.3. Подтипы

> `[ACCEPTED]`

```
Scalar::Int     ⊆ Scalar::Int
Scalar::Int     ⊆ Union(Scalar::Int, ...)
Union(A)        ⊆ Union(A, B)
ObjectOf(Foo)   ⊆ Special::Object
ListOf(T)       ⊆ Special::Array
Map(K,V)        ⊆ Special::Array
Special::Object ⊆ Special::Any
Special::Array  ⊆ Special::Any
T               ⊆ Special::Any   (top type)
ObjectOf(Foo)   ⊆ ObjectOf(Bar)  если:
                                   - Foo = Bar, или
                                   - Foo implements Bar (Bar — интерфейс), или
                                   - Foo extends Bar (Bar — класс), где
                                     extends-цепочка видна lefu
ListOf(T)       ⊆ ListOf(T)      (инвариантно)
Map(K,V)        ⊆ Map(K,V)       (инвариантно)
```

**«Видна lefu»** означает:
- **Bridge:** `class FileLogger extends BaseLogger` — lefu парсит bridge, видит `extends`. Подтипизация работает.
- **Stdlib:** `ThrownValue extends Exception` — lefu видит stdlib. Подтипизация работает (`ObjectOf(ThrownValue) ⊆ ObjectOf(Exception)`).
- **Closed:** `extends` запрещён (R13), цепочки нет. Подтипизация через `extends` для closed не работает — но и не нужна.
- **Native PHP-классы:** иерархия **не видна** lefu (`Exception extends Throwable`, `RuntimeException extends Exception` и т.д.). `ObjectOf(RuntimeException) ⊆ ObjectOf(Exception)` **не выводится**. Если нужен родительский тип — используйте `ObjectOf(Throwable)` явно или `Types::matches` в рантайме.

**Почему native-иерархия не включается:** полная иерархия PHP — большая, версионно-зависимая, и lefu не должен её знать. Пользователь, которому нужен `ObjectOf(Throwable)`, пишет его явно. `ThrownValue` — исключение (stdlib, цепочка видна).

### 9.4. Допустимые сужения (закрытый список)

> `[PARTIAL]` — базовый список `[ACCEPTED]`, narrowing для способностей `[OPEN]` (§15.8).

**`Types::matches($x, $literalType)`:** true → сужает `$x` до
`$literalType`; false → не меняется. **Единственный type guard
с narrowing в closed-мире.**

- `Types::matches($x, Scalar::Int)` → `Scalar::Int`.
- `Types::matches($x, Special::Object)` → `Special::Object`.
- `Types::matches($x, Special::Array)` → `Special::Array`.
- `Types::matches($x, new ObjectOf(Foo::class))` → `ObjectOf(Foo)`.
- `Types::matches($x, new ObjectOf(LoggerInterface::class))` →
  `ObjectOf(LoggerInterface)` (интерфейс — номинальный тип).
- `Types::matches($x, new ListOf(...))` → `ListOf(...)`.
- `Types::matches($x, new Map(...))` → `Map(...)`.
- `Types::matches($x, new Union(...))` → `Union(...)`.

**`Types::matches($x, $variableType)`:** runtime check **без
narrowing**. `$x` остаётся прежним.

**`$x === null` / `$x !== null`:** сравнение.
- `$x !== null` → true: `remove_null(current)`; false: `Scalar::Null`.
- `$x === null` → true: `Scalar::Null`; false: `remove_null(current)`.

**`isset($x)`:** существование.
- true: `remove_null(current)`; false: `Scalar::Null`.

**`assert(Types::matches($x, $literalType))`:** как if без else.

**`&&`, `||`, `??`:** короткое замыкание, сужение в правом операнде.

**Тернарник:** как if/else + join.

**Ранний выход:** `return`, `throw`, `exit()`, `die()` как
terminator. После if с terminator'ом действует отрицание условия.

**Nothing-функции:** вызов `#[Nothing]`-функции — terminator.

**Способности:** `Types::matches($x, Equatable::class)` — `[OPEN]`,
см. §15.8.

### 9.5. НЕ сужается (закрытый список)

> `[ACCEPTED]`

- `instanceof` — запрещён (R14).
- `is_*`, `is_a`, `is_callable`, `is_iterable`, `is_resource` —
  запрещены (R14).
- Пользовательские type guards — запрещены (R14).
- Литеральные типы (`42`, `'foo'`) — не поддерживаются.
- Целочисленные диапазоны — не поддерживаются.
- Сложная булева алгебра (XOR, дистрибуция).
- Инварианты циклов (только join на back-edge).
- Наследование TSE из try в catch (catch начинает с `declared_types`).
- `switch` — запрещён (R17), замена: `match`.
- `array_key_exists`, `property_exists`, `method_exists`.

### 9.6. Если анализатор не сужает

> `[ACCEPTED]`

Пользователь должен **переписать код**, а не подавить ошибку (R6).
Способы:
- Использовать `Types::matches` с литеральным Type.
- Извлечь логику в отдельный метод с явными типами.
- Использовать `assert(Types::matches(...))` для явного сужения.
- Переписать `switch` на явный `if` с `===` или `match`.

### 9.7. Специальные конструкции

> `[PARTIAL]` — базовые конструкции `[ACCEPTED]`, multi-catch `[ACCEPTED]` (запрещён, см. §6), finally `[ACCEPTED]`, деструктуризация `[ACCEPTED]`.

**foreach:**
- `foreach ($expr as $item)`: `$item := element_type(expr_type)`.
  - `ListOf(T)` → `$item: T`.
  - `Map(K, V)` → `$item: V`.
  - `Special::Array` → `$item: Special::Any`.
  - `Special::Any` → `$item: Special::Any`.
- `foreach ($expr as $key => $value)`:
  - `$key := key_type(expr_type)`.
  - `$value := value_type(expr_type)`.
- `&$item` запрещено (R5).

**Деструктуризация (`list()` / `[]`):**

- `[$a, $b] = $list` где `$list: ListOf(T)` → `$a: Union(T, Scalar::Null)`, `$b: Union(T, Scalar::Null)`. `ListOf(T)` не гарантирует длину, элемент может отсутствовать.
- `['x' => $a, 'y' => $b] = $map` где `$map: Map(K, V)` → `$a: Union(V, Scalar::Null)`, `$b: Union(V, Scalar::Null)`. `Map(K, V)` не гарантирует наличие ключа.
- `[$a, $b] = $arr` где `$arr: Special::Array` → `$a: Special::Any`, `$b: Special::Any`. Требует сужения (R4).
- `[$a, $b] = $any` где `$any: Special::Any` → `$a: Special::Any`, `$b: Special::Any`. Требует сужения (R4).
- Пропуски: `[, $b] = $list` → `$b: Union(T, Scalar::Null)`. Первый элемент игнорируется.
- Вложенная: `[[$a, $b], $c] = $nested` — рекурсивно по тем же правилам. `$nested: ListOf(ListOf(T))` → `$a: Union(T, Null)`, `$b: Union(T, Null)`, `$c: Union(ListOf(T), Null)`.
- `foreach ($pairs as [$a, $b])` — деструктуризация элемента. `$pairs: ListOf(ListOf(T))` → `$a: Union(T, Null)`, `$b: Union(T, Null)`.
- Ссылки (`[&$a] = $list`) — запрещены (R5).
- Tuple-деструктуризация — `[DEFERRED]` (§15.18). Tuple нет в пространстве типов v1.

`list()` и `[]` — синонимы, семантика одинаковая. Оба разрешены.

**catch:**
- `catch (ThrownValue $e)` → `$e := ObjectOf(ThrownValue)`. Единственная допустимая форма в closed (§6.5.6).
- `catch (FooException $e)` (нативное исключение) — `R18.catch-native-forbidden`.
- `catch (Foo | Bar $e)` (multi-catch, нативные исключения) — `R18.catch-native-forbidden`. Multi-catch не поддерживается в closed: он порождает `Union(ObjectOf(Foo), ObjectOf(Bar))`, запрещённый R14. Использовать `catch (ThrownValue $e)` + разбор payload через `Result`.
- `catch` без переменной (PHP 8+) — `R18.catch-native-forbidden`.

**try-catch:** catch не наследует TSE из try. Начинает
с `declared_types`.

**finally:**
- `try/finally` без `catch`: TSE после `finally` — `join(TSE_try_exit, TSE_finally_exit)`.
- `try/catch/finally`: TSE после `finally` — `join(TSE_try_exit, TSE_catch_exit, TSE_finally_exit)`.
- `finally` работает с `declared_types`, не с narrowed.
- `finally` не содержит `return`/`throw` (`R18.finally-control-flow-forbidden`).
- `finally` содержит только `#[Unit]`-вызовы (`R18.finally-may-throw`).

**break/continue:** развёртка в CFG с явными рёбрами.

**match:**
- Без `default`: join всех arm (без default path).
- С `default`: join всех arm, включая default.

### 9.8. Терминаторы и достижимость

> `[ACCEPTED]`

Terminator'ы: `return`, `throw`, `exit()`, `die()`, `break`,
`continue`, вызов `#[Nothing]`-функции.

Код после terminator'а в том же блоке — недостижим →
`R0.unreachable-code`.

Функция не-`Unit` без terminator'а на всех путях →
`R1.missing-return`.

`#[Unit]`-функция — обычный return без значения, **не** terminator.

### 9.9. Алгоритм

> `[ACCEPTED]`

1. Построить CFG из AST (`nikic/php-parser`).
2. Инициализировать TSE в entry: `declared_type` для всех
   параметров и `#[Variable]`.
3. Forward pass по CFG:
   - statement → apply effects;
   - if/else → narrow, analyze branches, join;
   - loop → fixpoint (TSE_head = join(TSE_before, TSE_end_body)),
     лимит 10 итераций, превышение — severity 2 (баг lefu);
   - return/throw → check, terminate.
4. Проверить missing return.
5. Собрать diagnostics.

Производительность: O(|CFG| × |TSE| × iterations). Итераций
обычно ≤ 3.


## 10. Диагностика

### 10.1. Схема кодов

> `[ACCEPTED]`

`lefu.<rule>.<error-code>` для R-правил,
`lefu.I<n>.<info-code>` для информационных сообщений.

Коды стабильны после публикации. Новые добавляются, старые
депрекейтятся, не удаляются.

### 10.2. Структура диагностики

## 11. Интеграция с приложением

> **Статус раздела:** `[PARTIAL]` — §11.4, §11.5 `[PARTIAL]`, §11.3 — `[ACCEPTED]`, §11.8 — `[ACCEPTED]` (finalize), остальное `[ACCEPTED]`.

### 11.1. Boot-check

> `[ACCEPTED]`

При старте приложения анализатор вызывается один раз. Ошибки
(`error`) — исключение + exit code 1. Info — лог. Один раз,
амортизировано на весь срок жизни приложения.

### 11.2. DI

> `[ACCEPTED]`

DI-контейнер читает типы из `#[Parameter]`, `#[Property]`,
`#[Returns]` через рефлексию. Нативные хинты в closed-файлах
отсутствуют. Promoted properties отсутствуют (R16).

Autowiring по `ObjectOf(Interface::class)` работает: контейнер
видит интерфейс, ищет биндинг, инжектит.

### 11.3. Динамическая инстанциация

> `[ACCEPTED]` — `new $className($args)` разрешён.

`new $className()` где `$className: Scalar::String` — разрешено.
Результат — `Special::Object`. Lefu не угадывает класс.

Требуется явное сужение через `Types::matches` с литеральным
Type:

```php
#[Parameter('className', Scalar::String)]
#[Returns(Special::Object)]
function make($className)
{
    return new $className();
}

$value = $this->make(MyClass::class);  // Special::Object
if (Types::matches($value, new ObjectOf(MyClass::class))) {
    // $value: ObjectOf(MyClass)
    $value->doSomething();
}
```

**`new $className($args)` с аргументами** — **разрешено**. Результат — `Special::Object`. Аргументы конструктора — **trust boundary**: lefu не знает, какой класс будет инстанцирован, значит не знает сигнатуру конструктора, значит не проверяет аргументы. Ответственность пользователя. См. §11.5.

### 11.4. Boot-time code generation

> `[PARTIAL]` — принцип `[ACCEPTED]`, формат invoker `[OPEN]` (§15.13).

Приложения могут генерировать invoker-код при старте. Generated
invoker — **closed-код**, валидируется lefu. Использует
`Types::matches` с **литеральными** Type-объектами → narrowing
работает → статическая гарантия.

Пример generated invoker:

```php
// Generated: App\Generated\Flow\Step2
#[Parameter('result', new ObjectOf(Result::class))]
#[Returns(new ObjectOf(CartId::class))]
function extractCartId($result)
{
    if ($result->isErr()) {
        throw new ThrownValue($result->error());
    }
    if (!Types::matches($result->unwrap(), new ObjectOf(CartId::class))) {
        throw new ThrownValue(new TypeMismatch());
    }
    return $result->unwrap();  // narrowed: ObjectOf(CartId)
}
```

### 11.5. Trust boundary

> `[PARTIAL]` — принцип `[ACCEPTED]`, кэширование `[OPEN]` (§15.13).

Единственное динамическое место — распаковка значений с типом
`Special::Any` (например, `Result::unwrap()`). Распаковка в
generated invoker с литеральными Type → narrowing работает.

**Аргументы конструктора при динамической инстанциации** —
trust boundary. `new $className($args)`: lefu не знает
`$className`, значит не знает сигнатуру конструктора, значит
не проверяет аргументы. Если аргументы не совпадают с
сигнатурой — рантайм-ошибка (`TypeError`), как `$array[$key]`
с неверным ключом. Модель типов её не ловит и не должна.
Пользователь, которому нужны статические гарантии, использует
фабрику с типизированным интерфейсом (когда stdlib её
предоставит) или bridge.

Всё остальное (вызов методов, wiring) — статически проверено
boot-check (config ↔ класс ↔ flow).

### 11.6. Конфиг приложения

> `[ACCEPTED]`

Конфиг приложения (build-конфиг, декларации) — **closed-файлы**.
Если конфиг использует class-strings (`MyClass::class`),
это `Scalar::String`. Приложение конвертирует их в `Type`-объекты
внутренне.

### 11.7. Bridge — только внешние библиотеки

> `[ACCEPTED]`

Bridge используется для интеграции с внешним кодом:
- Composer-зависимости, не переписанные на lefu.
- PSR-интерфейсы (PSR-7, PSR-15, PSR-11).
- Сторонние SDK.
- БД-драйверы (PDO, mysqli).

Всё остальное (фреймворк, приложение, конфиги, DI) — closed.
Bridge-методы могут возвращать `Result` для интеграции с
closed-миром (§6.5.8).

### 11.8. Внешние атрибуты

> `[ACCEPTED]` — добавлен абзац про `[#finalize]`.

Сторонние атрибуты (ORM, DI, сериализация) регистрируются
в `[attributes].known` конфига. Lefu не анализирует их поведение
и не гарантирует корректность. Если атрибут не зарегистрирован —
`I1.unknown-attribute` с образовательным текстом.

**Поведенческие атрибуты не приветствуются.** Если атрибут
меняет поведение бизнес-логики — это нарушение принципа
«имя = семантика». Lefu рекомендует декларативное описание
(через конфиг, билдеры) вместо поведенческих атрибутов.

**`[#finalize]`** — application-level cleanup через DI (stdlib).
Регистрируется в `[attributes].known`. Инфраструктурный атрибут,
не поведенческий: не меняет бизнес-логику, только вызывает
`finalize()` при завершении приложения. Не конфликтует с
`finally`/`with`: `finally` — block-level cleanup (§6.5.9),
`[#finalize]` — application-level cleanup.

### 11.9. Документация

> `[ACCEPTED]`

`#[Doc]` и `#[Throws]` — источник документации. Генератор
документации читает атрибуты через рефлексию. Докблоки запрещены
(R6.4), поэтому phpDocumentor и аналоги не используются.


## 12. Ориентация на LLM

> **Статус раздела:** `[ACCEPTED]`

### 12.1. Спецификация как system prompt

> `[ACCEPTED]`

R0–R17 и I0–I3 целиком вставляются в prompt. Минимум исключений,
ортогональность правил, отсутствие «зависит от контекста».

### 12.2. Простые и полные правила

> `[ACCEPTED]`

- **Простые:** LLM ошибается на границах правил, а не внутри.
- **Полные:** если есть конструкция, не покрытая правилом, LLM
  использует её как дыру.
- **Максимализм:** «объявляй все переменные» предпочтительнее
  «объявляй только невыводимые».

### 12.3. Диагностика для LLM

> `[ACCEPTED]`

JSON с `code`, `expected`, `actual`, `hint`. LLM исправляет
по диагностике, а не гадает. Для R10 и I1 — образовательные
сообщения.

### 12.4. Ключевые правила для system prompt

> `[ACCEPTED]` — добавлены правила про вывод, bridge-подтипизацию, `new $className($args)`, деструктуризацию.

- «`Scalar::*`, `Special::*`, `ObjectOf(...)`, `ListOf(...)`,
  `Map(...)`, `Union(...)` — дескрипторы типов, не значения.»
- «В closed-файлах нет нативных хинтов, нет нативных модификаторов,
  нет `readonly`. Все типы — через атрибуты, видимость —
  `#[VisibleAs]`.»
- «Свойства — только `var $x;` в теле класса. Никаких promoted,
  никаких static.»
- «Методы — без модификатора = public. Видимость — `#[VisibleAs]`.»
- «Замыкания запрещены. Callable — только объекты с `__invoke`.»
- «Анонимные классы запрещены. Только именованные классы.»
- «`#[Unit]` — возврат без значения. `#[Nothing]` — не возвращает
  управление.»
- «Type guards: только `Types::matches($x, $literalType)`.
  Нативные `is_*` и `instanceof` запрещены. `$x === null` /
  `isset($x)` — не type guards, разрешены.»
- «`Union` — только для nullable и скаляров. `Union` объектов
  запрещён.»
- «Наследование классов запрещено. Нет `abstract`, нет `extends`.
  Исключение: stdlib `ThrownValue extends Exception` —
  вынужденный заполнитель.»
- «`ObjectOf(Foo) ⊆ ObjectOf(Bar)` если `Foo = Bar`,
  `Foo implements Bar`, или `Foo extends Bar` (extends-цепочка
  видна lefu в bridge/stdlib). Native PHP-иерархия не включается:
  используй `ObjectOf(Throwable)` явно.»
- «`new $className($args)` разрешён: результат `Special::Object`,
  аргументы — trust boundary, требуют сужения результата.»
- «Деструктуризация `[$a, $b] = $list` где `$list: ListOf(T)`
  → `$a: Union(T, Null)`, `$b: Union(T, Null)`. `ListOf`
  не гарантирует длину, элемент может отсутствовать.»
- «Деструктуризация `['x' => $a] = $map` где `$map: Map(K, V)`
  → `$a: Union(V, Null)`. `Map` не гарантирует ключ.»
- «Деструктуризация `[$a, $b] = $arr` где `$arr: Special::Array`
  → `$a: Special::Any`, `$b: Special::Any`. Требует сужения
  через `Types::matches`.»
- «Tuple — `[DEFERRED]` для v1. Не в пространстве типов.
  Деструктуризация Tuple запрещена.»
- «`==`, `!=`, `<>`, `switch`, `empty()`, `?:`, truthy-check
  запрещены. Используй `===`, `match`, `??`, явные проверки.»
- «`in_array`/`array_search` — только с третьим аргументом `true`.»
- «`clone` разрешён только для классов с `#[Cloneable]`.»
- «Два мира: `Result` (ожидаемые ошибки) и `throw`/`catch`
  (исключительные). Catch — только `return $e->toResult();`
  или `throw $e;`.»
- «Result-функция: `#[Returns(new ObjectOf(Result::class))]`,
  без `#[Throws]`. Throw-функция: `#[Throws(new ObjectOf(Payload::class))]`,
  не возвращает `Result`. Смешение запрещено.»
- «`throw` только для `ThrownValue`: `throw new ThrownValue(new Payload(...))`.
  `catch` только для `ThrownValue`. Нативные исключения — bridge.»
- «`#[Throws]` указывает payload (класс, реализующий
  `ThrowablePayload`), не Throwable.»
- «`finally` — только для cleanup, без `return`/`throw`, только
  `#[Unit]`-вызовы. `try/finally` без `catch` разрешён.»
- «`__destruct` запрещён в closed. `yield` запрещён. `declare` —
  только `strict_types=1`.»
- «Вывод — только через `Output::write` / `Output::error` /
  `Output::debug`. `echo`, `print`, `printf`, `var_dump`,
  `print_r`, `var_export` запрещены.»
- «Форматирование — через `Strings::format`, не `sprintf`.
  Логирование — через `Logger` (stdlib, в разработке), не
  `Output::debug`.»
- «Встроенные функции PHP разрешены, но callable-аргументы —
  только callable-object.»
- «Неизвестные атрибуты — info-сообщение, не ошибка.»
- «Property hooks запрещены, кроме accessor-сахара.»
- «Машиночитаемые комментарии запрещены. Комментарии — только
  `//` с префиксом (`WHY:`, `TODO:`, `FIXME:`, `SEE:`, `NOTE:`)
  и только в теле метода.»
- «Документация — через `#[Doc]`. Исключения — через `#[Throws]`.
  Докблоки запрещены.»
- «Директива `// lefu: bridge` — в начале файла (не комментарий).»
- «License block — один `/* */` в начале файла, с SPDX или
  Copyright.»
- «Все классы неявно final. Для переиспользования — композиция
  или способности.»
- «Публичные имена lefu (Scalar, ObjectOf, Variable, Returns,
  Property, Parameter, VisibleAs, Immutable, Cloneable, Unit,
  Nothing, Throws, Doc, Types, Visibility, Special, ListOf, Map,
  Union, Result, ThrownValue, ThrowablePayload, Output,
  Equatable, WithEquatable, Hashable, WithHashable, Comparable,
  WithComparable) — в глобальном namespace, без префиксов,
  без `use`-импортов.»


## 13. Архитектура реализации

> **Статус раздела:** `[ACCEPTED]`

### 13.1. Composer-структура

> `[ACCEPTED]`

- **`lefu/attributes`** — runtime. Все имена в **глобальном
  namespace**: `Scalar`, `Special`, `Visibility`, `ObjectOf`,
  `ListOf`, `Map`, `Union`, `Types`, `Result`, `ThrownValue`,
  `ThrowablePayload`, `Output`, `Property`, `Parameter`,
  `Variable`, `Returns`, `Unit`, `Nothing`, `Immutable`,
  `Cloneable`, `VisibleAs`, `Throws`, `Doc`, `Equatable`,
  `WithEquatable`, `Hashable`, `WithHashable`, `Comparable`,
  `WithComparable`.
- **`lefu/analyzer`** — dev: парсер, CFG, TSE, CLI, boot-check,
  генерация диагностики.

**Autoloading:** classmap (не PSR-4), т.к. глобальный namespace.
Настройка `composer.json`:

```json
{
  "autoload": {
    "classmap": ["src/"]
  }
}
```

**Пре-флайт проверка конфликтов** — рекомендуется как
composer-плагин (`lefu/conflict-checker`), но не входит в scope
спецификации диалекта. Инженерная задача пакета, не правило
диалекта.

### 13.2. Компоненты анализатора

> `[ACCEPTED]` — lexer проверяет `echo`/`var_dump`.

1. **Lexer.** Лексический запрет `@` в комментариях (R6.6),
   проверка license block (R6.8), проверка `//` префиксов (R6.2),
   проверка директив (R6.1), проверка `@` в коде (R5),
   проверка `echo`/`print`/`printf` (`R5.echo-forbidden`),
   `var_dump`/`print_r`/`var_export` (`R5.dynamic-construct-forbidden`),
   `declare` (`R0.unsupported-declare`).
2. **Parser.** `nikic/php-parser` (AST).
3. **Type resolver.** Резолвинг атрибутов в Type-объекты.
4. **CFG builder.** Построение CFG из AST.
5. **TSE engine.** Flow analysis (§9).
6. **Rule checker.** R0–R18 (R18 — в §6.6).
7. **Diagnostics formatter.** Текст, JSON, SARIF.
8. **CLI.** `lefu check <path>`, `lefu boot`.
9. **Config reader.** `lefu.toml`.

### 13.3. Производительность

> `[ACCEPTED]`

- `Types::matches` vs нативные `is_*` — не приоритет. Философия
  и однозначность первичны.
- Для hot path — bridge-файл с нативными type guards.
- Fixpoint для циклов: лимит 10 итераций, превышение — severity 2
  (баг lefu).

### 13.4. Интеграция с IDE

> `[ACCEPTED]`

Адаптация `phpactor` для lefu: автокомплит `With*`-способностей,
подсказки по атрибутам, диагностика в реальном времени.


## 14. Закрытые решения

> **Статус раздела:** `[ACCEPTED]` — но раздел пополняется по мере работы.

- Закрытый мир, единственный режим.
- Closed активируется конфигом, не маркером в файле.
- Bridge — маркер `// lefu: bridge` (`//`, не `#`).
- `exclude` — файлы вне диалекта.
- PHP 8.5 минимум.
- Нативные хинты в closed-файлах запрещены.
- Все нативные модификаторы (`public`/`private`/`protected`/
  `final`) в closed-файлах запрещены. `var` — единственный
  заполнитель для свойств.
- **Наследование классов запрещено полностью.** Нет `abstract`,
  нет `extends`. Исключение — stdlib `ThrownValue extends Exception`
  (вынужденный заполнитель, §17.3).
- **Подтипизация `ObjectOf` учитывает `extends` в bridge и stdlib.**
  `ObjectOf(FileLogger) ⊆ ObjectOf(BaseLogger)`, если
  `FileLogger extends BaseLogger` виден lefu (bridge или stdlib).
  Native PHP-иерархия не включается: `ObjectOf(RuntimeException) ⊆
  ObjectOf(Exception)` не выводится, использовать
  `ObjectOf(Throwable)` явно или `Types::matches`.
- **`instanceof` запрещён полностью** в closed. Только
  `Types::matches` с литеральным Type.
- Видимость — только через `#[VisibleAs]`.
- Видимость констант: `Public` и `Private`. `Protected` запрещён.
- `#[Immutable]` + `Visibility::Protected` — разрешено, строгий
  immutable.
- Promoted properties запрещены (R16).
- Static свойства запрещены навсегда (R15). Static методы разрешены.
- `readonly` запрещён, заменён на `#[Immutable]`.
- `void`/`never` → `Unit`/`Nothing`.
- Замыкания запрещены (R9).
- Анонимные классы запрещены (R11).
- Callable — только callable-object с `__invoke`.
- Property hooks — только accessor-сахар (R12), окончательное.
- Машиночитаемые комментарии запрещены.
- **Комментарии — только `//` с префиксом (`WHY:`, `TODO:`,
  `FIXME:`, `SEE:`, `NOTE:`) и только в теле метода.**
- **Директивы — `// lefu: <name>` в начале файла, не считаются
  комментариями.**
- **License block — единственный `/* */`, один в начале файла,
  с SPDX или Copyright.**
- **Докблоки запрещены полностью.** Замена — `#[Doc]` и `#[Throws]`.
- **`#[Throws]` и `#[Doc]` — атрибуты метаинформации, не типы,
  не анализируются в flow analysis.**
- Неизвестные атрибуты — info (I1).
- Регистрация известных атрибутов — `[attributes].known`.
- `Special::Any`, `Special::Object`, `Special::Array` — top types.
- `Types::matches` — единственный type guard в closed.
  Narrows только с литеральным Type.
- `$x === null` / `$x !== null` / `isset($x)` — не type guards.
- `Union` объектов запрещён. Разрешён: nullable, скалярные суммы.
- `Special::Void` / `Special::Never` — удалены.
- `Var` → `Variable`, `Return` → `Returns`, `Param` → `Parameter`,
  `Obj` → `ObjectOf`.
- `Nominal`, `Ref`, `Instance`, `ClassType`, `Moat` — отклонены.
- `mixed` запрещён, включая нативный.
- Файл исключений не существует.
- Бинарность (closed / bridge / excluded).
- Миграция по файлам, не по правилам.
- У lefu нет `unsafe`.
- `strict_types` — требование.
- Severity: `error` (R) и `info` (I). Warning не существует.
- `@` в комментариях запрещён.
- Сокращения в именах диалекта запрещены (кроме заимствований PHP).
- Позиционные аргументы атрибутов — каноничны.
- Встроенные функции PHP разрешены (callable-аргументы — только
  callable-object; `in_array`/`array_search` — только с `true`).
- Маркер `// lefu: strict` не существует.
- Трейты запрещены (кроме `With*`-способностей).
- `==`, `!=`, `<>` запрещены полностью. `switch`, `empty()`,
  `?:`, truthy-check — запрещены. `in_array`/`array_search` —
  только с `true`.
- `#[Cloneable]` — маркер-атрибут, не наследуется.
- Динамический `new $className()` → `Special::Object`. Требуется
  явное сужение через `Types::matches` с литералом.
- **`new $className($args)` разрешён в closed.** Результат —
  `Special::Object`, требует сужения. Аргументы конструктора —
  trust boundary (§11.5). Фабрика с типизированным интерфейсом —
  в stdlib (в разработке).
- Boot-time code generation — closed-код, валидируется lefu.
  Использует `Types::matches` с литеральными Type → narrowing.
- Trust boundary сжатый: только распаковка `Special::Any`
  до конкретного типа, аргументы конструктора `new $className($args)`.
- Способности: `Equatable`/`WithEquatable`, `Hashable`/`WithHashable`,
  `Comparable`/`WithComparable`. `Stringable` — нативный
  `\Stringable`. `Cloneable` — атрибут.
- Документация: трейты способностей называются «withins».
  Слово `Trait` в документации lefu не используется.
- Производительность `Types::matches` vs нативных `is_*` —
  не приоритет.
- **Все публичные имена lefu — в глобальном namespace (без
  префикса `Lefu\`).** Имена диалекта — часть синтаксиса, не API
  пакета. Конфликты с третьими пакетами — ответственность
  пользователя. Конфликты с PHP core — принимаемый риск.
- **Autoloading через classmap**, не PSR-4. Техническая деталь,
  не часть спецификации диалекта.
- **Пре-флайт проверка конфликтов** — рекомендуется, но
  вне scope спецификации.
- **`@`, backticks, `goto`, `include`/`require` запрещены
  в closed.** Замена: явная обработка ошибок, bridge,
  структурированные конструкции, autoload + `Files::requirePhp`
  (stdlib, в разработке).
- **Запрет с путём.** Запреты делятся на дизайнерские (следствие
  парадигмы) и ограничивающие (закрывают возможность, не покрытую
  парадигмой). Ограничивающий запрет обязан сопровождаться
  конструкцией-заменой или trust boundary с изолированным API.
- **Два мира: `Result` (ожидаемые) и `throw`/`catch`
  (исключительные).** Catch — только `return $e->toResult();`
  или `throw $e;`. Result-функции и Throw-функции не смешиваются.
  `ThrownValue extends Exception` — вынужденный заполнитель
  (stdlib).
- **`ThrowablePayload` — пустой маркер-интерфейс.** Payload —
  данные, не поведение. Не имеет `recover()`, `describe()`.
- **`#[Throws]` принимает `ObjectOf(ThrowablePayload)`**,
  указывает payload, не исключение.
- **`throw` только для `ThrownValue`, `catch` только для
  `ThrownValue`** в closed. Нативные исключения — bridge.
- **Multi-catch не поддерживается в closed** (порождает
  `Union` объектов, запрещённый R14). Использовать
  `catch (ThrownValue $e)` + разбор payload через `Result`.
- **`finally` разрешён в closed с тремя ограничениями**
  (нет control flow, только `#[Unit]`, не влияет на TSE).
  `try/finally` без `catch` разрешён.
- **`__destruct` запрещён в closed** (`R5.destructor-forbidden`).
  Замена: `try/finally` (block-level), `[#finalize]` через DI
  (application-level). В bridge разрешён.
- **`with` — сахар в stdlib, не единственный путь.** Stdlib-методы
  работают через интерфейсы (`Finalizable`, `Transactional`),
  чтобы покрывать кастомные ресурсы. Пользователь может писать
  свой `with` с `finally`.
- **`yield` / генераторы запрещены в closed**
  (`R5.generator-forbidden`). Следствие парадигмы: нет `Generator`
  в пространстве типов, `iterable` вне scope. `[DEFERRED]` —
  пересмотреть после появления `Generator`.
- **`declare(strict_types=1);` — единственный разрешённый
  `declare`.** Остальные (`ticks`, `encoding`, блочная форма) —
  `R0.unsupported-declare`.
- **`register_tick_function` / `unregister_tick_function`
  запрещены** (`R5.dynamic-construct-forbidden`). Глобальные
  функции с побочными эффектами.
- **`echo` / `print` / `printf` запрещены в closed с v1**
  (`R5.echo-forbidden`). Замена: `Output::write` / `Output::error` /
  `Strings::format` (§17.2). `Output` в stdlib с v1 — единственный
  способ вывода.
- **`var_dump` / `print_r` / `var_export` запрещены**
  (`R5.dynamic-construct-forbidden`). Замена: `Output::debug`
  (§17.2).
- **`Output` — отдельный модуль stdlib, не часть `Files`.**
  `Files` — про файлы по пути (`Result`), `Output` — про
  stdout/stderr/debug (проглатывание ошибок). Разная семантика.
- **Stdlib имеет привилегии** (`extends Exception`, `fwrite(STDOUT)`,
  `var_dump`, `finally` без ограничений, `require`). Привилегии
  не наследуются пользовательским кодом. Закрытый список (§17.3).
- **Деструктуризация `ListOf`/`Map` — через `Union(T, Scalar::Null)`.**
  `ListOf` не гарантирует длину, `Map` — ключи. Элемент/ключ
  может отсутствовать → nullable.
- **Tuple — `[DEFERRED]` для v1.** Не в пространстве типов.
  Деструктуризация Tuple запрещена (Tuple нет). Внедрение
  Tuple — отдельная тема v2.
- **Вложенная деструктуризация и деструктуризация в `foreach`
  разрешены** — рекурсивно по тем же правилам.


## 15. Открытые вопросы

> **Статус раздела:** `[OPEN]` / `[DEFERRED]` — каждый пункт имеет свой статус.

### 15.1. Верификация enum case'ов

> `[OPEN]`

`case Int` / `case Bool` / `case Null` в enum — работают ли
на целевой версии PHP? Если нет — `Scalar::IntType`,
`Scalar::BoolType`, `Scalar::NullType`.

### 15.2. Способности: каноническая реализация

> `[OPEN]`

- `Equatable`/`WithEquatable` — как реализовать `equals`?
  Рефлексия по свойствам? `===`? Консистентность с `===`.
- `Hashable`/`WithHashable` — как комбинировать хеши? Циклы,
  ресурсы, вложенные объекты. Консистентность с `Equatable`.
- `Comparable`/`WithComparable` — по какому критерию?
- Взаимодействие с `===` и `<=>`. `==`/`<=>` для объектов —
  запрещены (R17).

### 15.3. Composer-структура

> `[OPEN]`

Разделение `lefu/attributes` (runtime) и `lefu/analyzer` (dev).
Как анализатор находит конфиг.

### 15.4. Интеграция с приложением

> `[OPEN]`

- Boot-check: как передаются ошибки (лог + exception + exit code)?
- DI: как читать атрибуты без lefu на этапе boot (Reflection +
  кэш)?
- Bridge-файлы: как анализатор читает хинты для интеропа (AST или
  Reflection)? Предварительно: AST.
- Boot-time code generation: точный формат generated invoker,
  порядок генерации, кэширование.

### 15.5. Неизвестные атрибуты

> `[OPEN]`

Ужесточение I1 до error — дискуссионно. Предварительно: info.

### 15.6. Собственная ORM

> `[DEFERRED]` — часть плана фреймворка, не диалекта.

Сущности описываются декларативно через build-конфиг, без
поведенческих атрибутов. Это часть плана фреймворка, не диалекта.

### 15.7. Property hooks: реализация R12

> `[OPEN]`

- Как анализатор проверяет backing store в теле хука?
- Нужен ли `#[Property]` на backed-свойстве с хуками?
- Совместимость с ORM.

### 15.8. `Types::matches` и способности

> `[OPEN]`

`Types::matches($x, Equatable::class)` — проверка способности,
разрешена. Сужает `Special::Object` до `Equatable`.
Прописать в §9.4 после реализации способностей.

### 15.9. `$this` в трейтах

> `[OPEN]`

Внутри трейта `$this` имеет только методы, объявленные в трейте
или как abstract. Иначе — `R13.trait-untyped-this`.

### 15.10. `#[Cloneable]` и состояние

> `[OPEN]`

Клонирование `#[Immutable]`-класса с объектными свойствами —
shallow clone (PHP по умолчанию). Нужен ли `__clone` в
`WithCloneable`? Или пользователь реализует сам?

### 15.11. Truthy-check в существующем коде

> `[ACCEPTED]` — запрет принят, объём работы открыт.

В существующем коде `if ($x)` встречается часто. Запрет (R17)
означает рефакторинг. Это **принято** (философия первична),
но объём работы — открытый вопрос.

### 15.12. `new $className()` с аргументами

> `[ACCEPTED]` — закрыт. См. §11.3, §11.5.

`new $className($arg1, $arg2)` разрешён в closed. Результат —
`Special::Object`, требует сужения. Аргументы конструктора —
trust boundary: lefu не проверяет их статически (не знает
сигнатуру конструктора). Рантайм-ошибка (`TypeError`) —
ответственность пользователя. Фабрика с типизированным
интерфейсом — в stdlib (в разработке). Bridge-методы используют
нативные правила.

### 15.13. Генерация invoker и кэш

> `[OPEN]`

Generated invoker — кэшируется между запусками или генерируется
при каждом boot? Открыто.

### 15.14. Heredoc в `#[Doc]`

> `[OPEN]`

Работает ли heredoc в аргументах атрибутов для многострочного
`#[Doc]`? Проверить локально. Если нет — только `\n` в строке.

### 15.15. Конфликты имён с PHP core

> `[DEFERRED]` — до появления реального конфликта.

`Map`, `Union`, `Property`, `Parameter`, `Variable`, `Types`,
`Result`, `Output` — высокорисковые имена. Если PHP core введёт
одно из них (например, `Union` в generics RFC, `Result` в error
handling RFC, `Output` в каком-нибудь RFC по потокам),
потребуется решение. Варианты: префиксный вариант пакета,
переименование, алиасинг. Решение откладывается до появления
реального конфликта.

### 15.16. Пре-флайт проверка конфликтов

> `[DEFERRED]` — вне scope спецификации.

Рекомендуется `lefu/conflict-checker` как composer-плагин,
но не входит в scope спецификации. Инженерная задача пакета.

### 15.17. `Files::requirePhp` и стандартная библиотека `Files`

> `[OPEN]`

`include`/`require` запрещены в closed (`R5.include-forbidden`).
Альтернатива — `Files::requirePhp(string $path): Special::Any`
из стандартной библиотеки lefu. Возвращает `Special::Any`,
требует сужения через `Types::matches`. Бросает
`FilesystemException`.

**Статус:** API не спроектирован. Категории функциональности
(чтение как данных, выполнение PHP, запись, метаданные) —
набросок, не финал. Спецификация `Files` — отдельный документ,
вне scope диалекта. Обзор модулей stdlib — §17.4.

**До появления `Files::requirePhp`:** использовать bridge.
После появления — bridge для этого кейса не рекомендуется
(это не внешняя библиотека, а собственный код с внешними
данными).

**Зависимость:** реализация `Files::requirePhp` — приоритет
для stdlib, потому что без неё `R5.include-forbidden` создаёт
неудобство для проектов, начатых на lefu.

### 15.18. Tuple

> `[DEFERRED]` — v2.

`Tuple(T1, T2, ...)` — фиксированная длина, разнородные типы.
Нужен для деструктуризации без `Union(T, Null)`, для возврата
нескольких значений, для `foreach` с разнородными парами.

**Статус:** не в пространстве типов v1. Причины: большая тема
(правила append/unset/merge, special-casing `Tuple::of`,
расширение `#[Variable]` для проверки литерала, arity-check
деструктуризации). Деструктуризация без Tuple работает через
`Union(T, Null)` — не идеально, но не блокер.

**Решение по созданию (когда будет):** литерал +
`#[Variable(new Tuple(...))]` (вариант B). Не `Tuple::of`
(special-casing stdlib), не эвристика разнородных (принцип 8 —
явность).

**Деструктуризация Tuple (когда будет):** arity-check обязателен
(`[$a, $b, $c] = $pair` где `$pair: Tuple(Int, String)` — ошибка).
Частичная деструктуризация (`[$a] = $pair`) — запрещена
(Tuple — контракт «все элементы нужны»).


## 16. Примеры

> **Статус раздела:** `[ACCEPTED]`

### 16.1. Полный класс с зависимостями

> `[ACCEPTED]`

```php
<?php
/*
 * SPDX-License-Identifier: MIT
 * Copyright 2024 ACME Corp.
 */

declare(strict_types=1);

namespace App\Service;

use App\Model\User;
use App\Model\Order;
use App\Model\OrderItem;
use App\Repository\OrderRepository;

class OrderProcessor
{
    #[Property(new ObjectOf(OrderRepository::class))]
    #[VisibleAs(Visibility::Private)]
    #[Immutable]
    var $orderRepository;

    #[Parameter('orderRepository', new ObjectOf(OrderRepository::class))]
    function __construct($orderRepository)
    {
        $this->orderRepository = $orderRepository;
    }

    #[Doc('Returns the total amount for a user across all orders.')]
    #[Throws(new ObjectOf(OrderRepositoryFailure::class))]
    #[Parameter('user', new ObjectOf(User::class))]
    #[Returns(Scalar::Int)]
    #[Variable('total', Scalar::Int)]
    #[Variable('order', new ObjectOf(Order::class))]
    #[Variable('item', new ObjectOf(OrderItem::class))]
    #[Variable('subtotal', Scalar::Int)]
    function totalFor($user)
    {
        $total = 0;
        foreach ($this->orderRepository->byUser($user) as $order) {
            // NOTE: order.items() is cached at the repository level.
            $subtotal = 0;
            foreach ($order->items() as $item) {
                $subtotal += $item->price();
            }
            $total += $subtotal;
        }
        return $total;
    }
}
```

Проверки: license block с SPDX; неявно final; `var` + `#[Property]`
+ `#[VisibleAs]` + `#[Immutable]` для свойства; обычный конструктор;
`#[Parameter]` без хинта; `#[Returns]` без хинта; `#[Doc]` и
`#[Throws]` вместо докблока; `// NOTE:` в теле метода; все
локальные в `#[Variable]`. `#[Throws]` указывает payload
(`OrderRepositoryFailure`, реализующий `ThrowablePayload`).
Нет замыканий, анонимных классов, property hooks, static свойств,
promoted properties, `@`-комментариев, нативных type guards,
наследования, loose comparison.

> `[ACCEPTED]`

```php
{
```
```php
    public function log(string $message): void { /* ... */ }
```

## 17. Stdlib

> **Статус раздела:** `[PARTIAL]` — §17.1–17.3 `[ACCEPTED]`, §17.4 (обзор модулей) `[PARTIAL]`, §17.5 (открытые вопросы) `[OPEN]`.

### 17.1. Философия

> `[ACCEPTED]`

Stdlib — стандартная библиотека Lefu. Публичные имена — в глобальном namespace (§2). Stdlib имеет **привилегии**, которых нет у пользовательского кода: `extends Exception` для `ThrownValue`, `fwrite(STDOUT, ...)` для `Output`, `finally` для `with`-паттерна. Эти привилегии — вынужденные заполнители (§2), требуемые PHP-рантаймом или семантикой cleanup. Они не открывают дверь для пользователя: пользовательский код не может наследовать `Exception` (R13), не может использовать `fwrite` напрямую (R5), не может писать `finally` без ограничений (§6.5.9).

Stdlib — не «ещё один способ». Где stdlib предоставляет метод, прямой доступ к встроенной функции PHP запрещён (R5, R18). `Output::write` вместо `echo`, `Files::writeString` вместо `fwrite`, `Arrays::map` вместо `array_map`.

### 17.2. Output

> `[ACCEPTED]`

Модуль вывода в стандартные потоки и отладки. Отдельный модуль, не часть `Files` (§17.4): `Files` — про файлы по пути, `Output` — про stdout/stderr/debug. Семантика разная: `Files` возвращает `Result` (диск полон — ошибка), `Output` проглатывает ошибки вывода (pipe закрыт — приложение всё равно падает).

```php
#[Immutable]
final class Output
{
    #[Parameter('text', Scalar::String)]
    #[Unit]
    static function write($text);

    #[Parameter('text', Scalar::String)]
    #[Unit]
    static function error($text);

    #[Parameter('value', Special::Any)]
    #[Unit]
    static function debug($value);
}
```

- **`Output::write($text)`** — запись в stdout. Внутри — `fwrite(STDOUT, $text)` (bridge-привилегия). Ошибки вывода проглатываются: `fwrite` возвращает `false` при закрытом pipe, `Output::write` это игнорирует. Причина: вывод в stdout — не бизнес-операция; если pipe закрыт, приложение всё равно падает. Для строгого контроля — `Files::writeString` с `Result`.
- **`Output::error($text)`** — запись в stderr. Внутри — `fwrite(STDERR, $text)` (bridge-привилегия). Ошибки проглатываются, как в `write`.
- **`Output::debug($value)`** — отладочный вывод структуры значения. Внутри — `var_dump($value)` (bridge-привилегия). `Special::Any` — потому что отладка не типизируется. `var_dump`/`print_r`/`var_export` напрямую запрещены (`R5.dynamic-construct-forbidden`).

**Форматирование** — через `Strings::format` (отдельный модуль, §17.4). `Output::write(Strings::format('Hello, %s!', [$name]))`. `sprintf` не нужен.

**Логирование** — через `Logger` (отдельный модуль, в разработке). `Output::debug` — для отладки, не для логирования.

### 17.3. Привилегии stdlib

> `[ACCEPTED]`

Stdlib-классы имеют привилегии, которых нет у пользовательского кода:

| Привилегия | Где | Обоснование |
|---|---|---|
| `extends Exception` | `ThrownValue` (§6.3) | PHP-рантайм требует `extends Exception` для `Throwable`. Вынужденный заполнитель. |
| `fwrite(STDOUT, ...)` | `Output` (§17.2) | Прямая запись в поток. Пользователь использует `Output::write`. |
| `var_dump` | `Output::debug` (§17.2) | Отладочный вывод. Пользователь использует `Output::debug`. |
| `finally` без ограничений | `Files::with`, `Transactions::with` (§6.5.9) | Cleanup в stdlib-методах. Пользователь использует `finally` с тремя ограничениями. |
| `require`/`include` | `Files::requirePhp` (§15.17) | Загрузка PHP-файлов. Пользователь использует `Files::requirePhp`. `[OPEN]` — API не спроектирован. |

Привилегии stdlib **не наследуются** пользовательским кодом. Пользователь не может «стать stdlib» и получить `fwrite` напрямую. Это закрытый список.
