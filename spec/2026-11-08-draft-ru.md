# Lefu — Specification
=====================

Lefu is not another static analyzer
Lefu — строго типизированный диалект PHP. Рождён на острове Лефу, у берегов Хайшэньвэя.

Статус документа: `[DRAFT]` — охват не завершён, но разделы с `[ACCEPTED]` считаются зафиксированными.
Дата: 2026-11-09
Назначение: техническое описание диалекта PHP с закрытой, неподавляемой моделью типов.

## 0. Суть и философия

> **Статус раздела:** `[ACCEPTED]` — все подразделы утверждены.

lefu — **закрытый диалект PHP** с неподавляемой моделью типов.
Не анализатор, а язык с собственными правилами, реализуемый
внешним анализатором и декларативными атрибутами. Код на lefu —
валидный PHP, но подчиняется строгой дисциплине.

Все публичные имена диалекта — в **глобальном namespace** (без
префикса). Имена диалекта — часть синтаксиса, не API пакета.

### 0.1. Ключевые принципы

> `[ACCEPTED]` — принципы 1–10 (исходные) и 11 (добавлен 2026-11-08).

1. **Имя = семантика.** Каждое имя диалекта — полное слово или
   композит полных слов. Сокращения запрещены (R7).
2. **Нет escape hatches.** Нет inline-подавлений, нет `unsafe`,
   нет исключений из правил на уровне файла или строки.
3. **Нет магии.** Всё, что PHP позволяет убрать, — убрано и
   заменено атрибутами. Всё, что PHP требует синтаксически, —
   сохранено как вынужденный заполнитель.
4. **Нет опциональности.** Файл либо в диалекте, либо нет.
   Третьего не дано.
5. **Минимум наследования.** Наследование классов запрещено.
   Только композиция и контракты.
6. **Минимум type guards.** Один type guard — `Types::matches`
   с литеральным Type. Narrows только с литералом.
7. **Строгое сравнение.** `==`, `!=`, `<>`, `switch`, `empty()`,
   `?:`, truthy-check — запрещены.
8. **Явность.** Каждый тип, каждая видимость, каждая
   расширяемость — объявлены через атрибуты.
9. **Комментарий — исключительный случай.** Только `//`
   с префиксом и только в теле метода. Всё остальное —
   `#[Doc]` и `#[Throws]`.
10. **Нативное представление.** Публичные имена диалекта —
    в глобальном namespace. `Scalar::Int`, `#[Returns(...)]` —
    без префиксов, без `use`-импортов.
11. **Запрет с путём.** Запреты делятся на два класса:
    - **Дизайнерские** — следствие выбранной парадигмы (нет
      static properties, нет наследования, нет трейтов, нет
      замыканий). Замена уже описана в соответствующем правиле
      (композиция, контракты, callable-object). Отдельный
      раздел «Замена» не требуется.
    - **Ограничивающие** — закрывают возможность, которая
      не покрыта парадигмой lefu (`@`, `require`, `instanceof`).
      Такой запрет обязан сопровождаться либо
      конструкцией-заменой, либо trust boundary с изолированным
      API. «Нельзя, страдайте» — запрещённый подход.

    **Критерий:** если пользователь может решить задачу в рамках
    парадигмы lefu — запрет дизайнерский. Если не может —
    ограничивающий, и нужен путь.

### 0.2. Цели

> `[ACCEPTED]`

- Дать проектам, готовым к строгой дисциплине, следующий шаг после
  PHPStan/Psalm max level: неподавляемый режим проверки.
- Сделать модель типизации локальных переменных, эквивалентную
  `let`-биндингам в Rust или секции `var` в Pascal.
- Отделить ожидаемые ошибки (`Result`) от исключительных
  (`throw`/`catch`), чтобы бизнес-логика не была control flow.
- Сформулировать спецификацию так, чтобы её можно было целиком
  вставить в system prompt LLM.
- Сохранить полную совместимость с рантаймом PHP.

### 0.3. Не-цели

> `[ACCEPTED]`

- Заменить PHPStan/Psalm для всех проектов.
- Дать математическое доказательство корректности.
- Изменить сам язык PHP или рантайм.
- Поддержать существующий PHP-код без изменений.
- Избегать конфликтов с третьими пакетами (ответственность
  пользователя).


## 1. Требования

> **Статус раздела:** `[ACCEPTED]` — §1.1–1.5.

### 1.1. Версия PHP

> `[ACCEPTED]`

**PHP 8.5 минимум.** Причины:
- Полный набор target-констант атрибутов, включая `TARGET_CONSTANT`
  и `TARGET_ALL` (значение 127).
- `#[\DelayedTargetValidation]` (8.5).
- Современные возможности языка, необходимые для целостной модели.

### 1.2. Обязательные директивы

> `[ACCEPTED]`

`declare(strict_types=1);` обязателен в каждом файле диалекта.
Отсутствие — ошибка `R0.missing-strict-types`.

### 1.3. Синтаксические возможности

> `[ACCEPTED]`

- `new` в аргументах атрибутов (8.1+) — рабочий механизм.
- Enum (8.1+) — для `Scalar`, `Special`, `Visibility`.
- Readonly properties (8.1+) — **запрещены** в closed (заменены
  `#[Immutable]`).

### 1.4. Установка

> `[ACCEPTED]`

```bash
composer require --dev lefu/attributes
```

Пакет `lefu/attributes` содержит runtime-компоненты в **глобальном
namespace** (без префикса `Lefu\`): enum'ы `Scalar`, `Special`,
`Visibility`; классы `ObjectOf`, `ListOf`, `Map`, `Union`,
`Types`, `Result`, `ThrownValue`, `Output`; интерфейсы
`ThrowablePayload`, `Equatable`, `Hashable`, `Comparable`;
атрибуты `Property`, `Parameter`, `Variable`, `Returns`,
`Unit`, `Nothing`, `Immutable`, `Cloneable`, `VisibleAs`,
`Throws`, `Doc`.

**Публичные имена — часть синтаксиса диалекта, не API пакета.**
Использование в глобальном namespace — осознанное решение.
Конфликты с третьими пакетами — ответственность пользователя.
Конфликты с будущими версиями PHP core — принимаемый риск,
решение по мере поступления.

Анализатор устанавливается отдельно как dev-зависимость
(`lefu/analyzer`).

### 1.5. Локальная верификация

> `[ACCEPTED]` — проверено на PHP 8.5 (2026-11-09).

`case Int` / `case Bool` / `case Null` в enum работают.
`Scalar` enum остаётся как в §4.2. См. §15.1.


## 2. Терминология

> **Статус раздела:** `[ACCEPTED]` — «способность» → «контракт», «трейт» — запрещён, вынужденный заполнитель, Tuple.

- **Диалект** — lefu closed mode. Единственный режим.
- **Closed-файл** — файл диалекта. Активируется конфигом по
  умолчанию, кроме `exclude` и `bridge`.
- **Bridge** — файл на границе мира. Маркер `// lefu: bridge`.
- **Excluded** — файл вне диалекта (vendor, generated, cache).
- **Директива** — управляющий маркер `// lefu: <name>` в начале
  файла. Не является комментарием, R6 на неё не распространяется.
- **Boot-check** — валидация при старте приложения.
- **TSE** (Type State Environment) — отображение
  `variable → current_type` в каждой точке программы.
- **Narrowing** — сужение `current_type` в control flow.
- **Upper bound** — `declared_type`, неизменен.
- **Descriptor** — объект, реализующий `Type`. Используется
  в позиции типа, не является значением домена.
- **Callable-object** — объект с `__invoke`, типизированным
  через атрибуты. Единственный разрешённый callable.
- **Контракт** — интерфейс диалекта (`Equatable`, `Hashable`,
  `Comparable`). Единственный полиморфизм в closed-мире.
  Реализуется вручную в каждом классе. Без трейтов, без
  автоматической реализации.
- **Трейт** — запрещён полностью (`R13.trait-forbidden`).
  PHP-трейты — copy-paste кода с неявным `$this`, без типизации,
  с ручным разрешением конфликтов. Против принципа 3
  («Нет магии»).
- **Вынужденный заполнитель** — синтаксис, требуемый PHP-движком,
  не несущий семантики диалекта (`var` для свойств).
- **Вынужденный заполнитель (stdlib-исключение)** — `ThrownValue`
  наследует `Exception`; требуется PHP-рантаймом; пользовательский
  код не может наследовать `Exception` (R13).
- **Type guard** — проверка типа значения в рантайме. В closed-мире
  единственный type guard — `Types::matches` с литеральным Type.
  В bridge — нативные `is_*` и `instanceof`.
- **Trust boundary** — точка, где статическая гарантия диалекта
  уступает место runtime-проверке приложения.
- **License block** — единственный разрешённый `/* */` блок
  в начале файла, содержащий SPDX-идентификатор или Copyright.
- **Global namespace** — публичные имена диалекта без префикса
  (`Scalar`, `ObjectOf`, `#[Returns]`, ...).
- **Stdlib** — стандартная библиотека Lefu (`Output`, `Files`,
  `Arrays`, `Strings`, `Result`, `ThrownValue`, `Types`,
  `Equatable`, `Hashable`, `Comparable`, `DI`, `Logger`).
  Имеет привилегии, которых нет у пользовательского кода (§17.3).
- **Tuple** — `[DEFERRED]` (v2). Фиксированная длина, разнородные
  типы. Не в пространстве типов v1 (§15.18). Деструктуризация
  Tuple запрещена (Tuple нет).


## 3. Target-константы атрибутов

> **Статус раздела:** `[ACCEPTED]`

Атрибуты PHP 8.5 могут быть привязаны к следующим сущностям:

| Target | К чему привязывается |
|---|---|
| `TARGET_CLASS` | Классы, интерфейсы, enum'ы |
| `TARGET_FUNCTION` | Именованные функции |
| `TARGET_METHOD` | Методы классов |
| `TARGET_PROPERTY` | Свойства классов |
| `TARGET_CLASS_CONSTANT` | Константы класса |
| `TARGET_PARAMETER` | Параметры функций и методов |
| `TARGET_CONSTANT` | Глобальные константы (`const`) |
| `TARGET_ALL` | Все вышеперечисленные (значение 127) |

Все атрибуты диалекта объявляют свои target-ы явно. Применение
к недопустимому target'у — ошибка `R7.invalid-target`.

**Promoted properties запрещены** (R16). Параметр и свойство —
разные сущности с разными target'ами и разными атрибутами.


## 4. Пространство типов

> **Статус раздела:** `[PARTIAL]` — §4.8 `[ACCEPTED]` (контракты), §4.10 `[ACCEPTED]` (Tuple `[DEFERRED]`, property hooks запрещены), остальное `[ACCEPTED]`.

### 4.1. Интерфейс Type

> `[ACCEPTED]`

```php
interface Type
{
    public function describe(): string;
    public function accepts(mixed $value): bool;
}
```

### 4.2. Scalar (enum)

> `[ACCEPTED]` — проверено на PHP 8.5 (§15.1).

```php
enum Scalar: string implements Type
{
    case Int    = 'int';
    case String = 'string';
    case Bool   = 'bool';
    case Float  = 'float';
    case Null   = 'null';

    public function describe(): string { return $this->value; }

    public function accepts(mixed $value): bool
    {
        return match ($this) {
            self::Int    => is_int($value),
            self::String => is_string($value),
            self::Bool   => is_bool($value),
            self::Float  => is_float($value),
            self::Null   => $value === null,
        };
    }
}
```

### 4.3. Special (enum)

> `[ACCEPTED]`

```php
enum Special: string implements Type
{
    case Any    = 'Any';
    case Object = 'object';
    case Array  = 'array';

    public function describe(): string { return $this->value; }

    public function accepts(mixed $value): bool
    {
        return match ($this) {
            self::Any    => true,
            self::Object => is_object($value),
            self::Array  => is_array($value),
        };
    }
}
```

**Подтипы:**
- `Special::Object ⊆ Special::Any`
- `Special::Array ⊆ Special::Any`
- `ObjectOf(Foo) ⊆ Special::Object`
- `ListOf(T) ⊆ Special::Array`
- `Map(K,V) ⊆ Special::Array`
- `T ⊆ Special::Any` для любого T.

`Special::Any` — top type. Использование без сужения — ошибка
`R4.any-without-narrowing`.

### 4.4. ObjectOf

> `[ACCEPTED]`

```php
final class ObjectOf implements Type
{
    public function __construct(public readonly string $className) {}

    public function describe(): string { return $this->className; }

    public function accepts(mixed $value): bool
    {
        return $value instanceof $this->className;
    }
}
```

`$className` может быть именем класса **или интерфейса**.
Семантика:
- `ObjectOf(Class::class)` — «экземпляр класса Class».
- `ObjectOf(Interface::class)` — «объект, реализующий контракт
  Interface».

`accepts()` использует `instanceof` для обоих. Интерфейс —
номинальный тип, не структурный.

### 4.5. Композиты

> `[ACCEPTED]`

```php
final class ListOf implements Type
{
    public function __construct(public readonly Type $item) {}

    public function describe(): string
    {
        return "list<{$this->item->describe()}>";
    }

    public function accepts(mixed $value): bool
    {
        if (!is_array($value) || !array_is_list($value)) {
            return false;
        }
        foreach ($value as $item) {
            if (!$this->item->accepts($item)) {
                return false;
            }
        }
        return true;
    }
}

final class Map implements Type
{
    public function __construct(
        public readonly Type $key,
        public readonly Type $value,
    ) {}

    public function describe(): string
    {
        return "array<{$this->key->describe()}, {$this->value->describe()}>";
    }

    public function accepts(mixed $value): bool
    {
        if (!is_array($value)) {
            return false;
        }
        foreach ($value as $k => $v) {
            if (!$this->key->accepts($k) || !$this->value->accepts($v)) {
                return false;
            }
        }
        return true;
    }
}

final class Union implements Type
{
    /** @var Type[] */
    public readonly array $types;

    public function __construct(Type ...$types)
    {
        if (count($types) < 2) {
            throw new \InvalidArgumentException(
                'Union must have at least 2 types'
            );
        }
        $this->types = $types;
    }

    public function describe(): string
    {
        return implode('|', array_map(
            fn(Type $t) => $t->describe(),
            $this->types,
        ));
    }

    public function accepts(mixed $value): bool
    {
        foreach ($this->types as $type) {
            if ($type->accepts($value)) {
                return true;
            }
        }
        return false;
    }
}
```

### 4.6. Union (правила использования)

> `[ACCEPTED]`

**Разрешён:**
- `Union(Scalar::A, Scalar::B)` — скалярные суммы.
- `Union(T, Scalar::Null)` — nullable (T — скаляр или ObjectOf).
- `Union(ObjectOf(Foo), Scalar::Null)` — nullable объект.

**Запрещён:**
- `Union(ObjectOf(A), ObjectOf(B))` где A ≠ B —
  `R14.union-of-objects-forbidden`.
- Любой Union, содержащий два и более `ObjectOf`.

**Замена:**
- общий контракт (если Dog и Cat делают что-то общее);
- enum-дискриминатор (явный класс с `match`, если поведение разное);
- nullable Union (если один из вариантов — null).

### 4.7. Visibility (enum, отдельно от Type)

> `[ACCEPTED]`

```php
enum Visibility: string
{
    case Private   = 'private';
    case Protected = 'protected';
    case Public    = 'public';
}
```

### 4.8. Types — единственный type guard

> `[ACCEPTED]` — базовая модель + narrowing для контрактов.

```php
final class Types
{
    public static function matches(mixed $value, Type $type): bool
    {
        return $type->accepts($value);
    }
}
```

**Narrowing-правило:** `Types::matches` сужает тип **только если
второй аргумент — литеральный Type-объект**:

```php
// Narrows:
if (Types::matches($x, Scalar::Int)) { /* $x: Scalar::Int */ }
if (Types::matches($x, new ObjectOf(Foo::class))) { /* $x: ObjectOf(Foo) */ }

// НЕ narrows (runtime check):
if (Types::matches($x, $expectedType)) { /* $x: прежний тип */ }
```

`Types::matches($x, Equatable::class)` — проверка контракта,
сужает `Special::Object` до `Equatable`. **Статус:** `[ACCEPTED]`,
см. §15.8. Аналогично для `Hashable`, `Comparable`.

### 4.9. Маркеры возврата и свойств

> `[ACCEPTED]`

```php
#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Unit {}

#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Nothing {}

#[Attribute(Attribute::TARGET_PROPERTY | Attribute::TARGET_CLASS)]
final class Immutable {}

#[Attribute(Attribute::TARGET_CLASS)]
final class Cloneable {}
```

- `#[Unit]` — метод возвращает управление без значения
  (аналог `void`, unit-тип).
- `#[Nothing]` — метод не возвращает управление (throw/exit/
  infinite loop, bottom-тип).
- `#[Immutable]` — свойство (или класс) не переприсваивается
  после инициализации (аналог `readonly`, но через атрибут).
- `#[Cloneable]` — класс разрешает клонирование через `clone`.

**Причина переименования Unit/Nothing:** `void` (PHP 7.1+) и
`never` (PHP 8.1+) зарезервированы в PHP как ключевые слова и
не могут быть именами классов/атрибутов.

### 4.10. Запрещённые типы и конструкции

> `[ACCEPTED]` — добавлен Tuple `[DEFERRED]`, property hooks запрещены полностью.

- `mixed` — запрещён (R4), включая нативный `: mixed`.
- Plain `array` без параметров — не тип (R4).
- `iterable`, `callable`, `resource`, `numeric` — вне scope.
- `void`/`never` как типы значений — только `#[Unit]`/`#[Nothing]`.
- `readonly` — запрещён (R8), заменён `#[Immutable]`.
- Замыкания — запрещены (R9).
- Анонимные классы — запрещены (R11).
- Property hooks — запрещены полностью (R12). Accessor-сахар —
  `[DEFERRED]` (v2, §15.7). Замена: явные методы `getX()`/`setX()`
  для инкапсуляции; публичные свойства + `#[Immutable]` для
  value objects; публичные свойства для mutable DTO.
- Virtual/computed properties — запрещены (R12).
- Asymmetric visibility — запрещена (R12).
- Нативные модификаторы (`public`/`private`/`protected`/`final`) —
  запрещены (R14).
- Static свойства — запрещены (R15).
- Promoted properties — запрещены (R16).
- Нативные type guards (`is_int`, `is_string`, `is_array`,
  `is_object`, `instanceof`, `is_a`, `is_callable`, `is_iterable`,
  `is_resource`) — запрещены (R14).
- Пользовательские type guards — запрещены (R14).
- `Union` объектов — запрещён (R14).
- `throw` не `ThrownValue` — `R18.throw-not-thrownvalue`.
- `catch` не `ThrownValue` — `R18.catch-native-forbidden`.
- `==`, `!=`, `<>` — запрещены (R17).
- `switch`, `empty()`, `$x ?: $y`, truthy-check — запрещены (R17).
- Наследование классов (`abstract class`, `extends`) — запрещено
  (R13). Исключение — stdlib `ThrownValue` (вынужденный заполнитель).
- Трейты — запрещены полностью (R13). Никаких исключений.
- `abstract` — запрещён (R13).
- `in_array` без `true`, `array_search` без `true` — запрещены (R17).
- `echo`, `print`, `printf` — запрещены (R5), заменены `Output`.
- `var_dump`, `print_r`, `var_export` — запрещены (R5), заменены
  `Output::debug`.
- `yield` / генераторы — запрещены (R5).
- `Tuple` — `[DEFERRED]`, не в пространстве типов v1 (§15.18).
  Деструктуризация Tuple запрещена.


## 5. Атрибуты диалекта

> **Статус раздела:** `[ACCEPTED]` — §5.8 семантика изменена (см. §6), §5.9 — heredoc проверен.

Все атрибуты принимают **позиционные аргументы** (named arguments
опциональны, но не рекомендуются). Сигнатуры:

```php
#[Attribute(Attribute::TARGET_PROPERTY)]
final class Property
{
    public function __construct(public readonly Type $type) {}
}

#[Attribute(Attribute::TARGET_PARAMETER)]
final class Parameter
{
    public function __construct(
        public readonly string $name,
        public readonly Type $type,
    ) {}
}

#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Variable
{
    public function __construct(
        public readonly string $name,
        public readonly Type $type,
    ) {}
}

#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Returns
{
    public function __construct(public readonly Type $type) {}
}

#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Unit {}

#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Nothing {}

#[Attribute(Attribute::TARGET_PROPERTY | Attribute::TARGET_CLASS)]
final class Immutable {}

#[Attribute(Attribute::TARGET_CLASS)]
final class Cloneable {}

#[Attribute(
    Attribute::TARGET_PROPERTY
    | Attribute::TARGET_METHOD
    | Attribute::TARGET_CLASS_CONSTANT
)]
final class VisibleAs
{
    public function __construct(public readonly Visibility $visibility) {}
}

#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Throws
{
    public function __construct(public readonly ObjectOf $exception) {}
}

#[Attribute(
    Attribute::TARGET_CLASS
    | Attribute::TARGET_METHOD
    | Attribute::TARGET_FUNCTION
    | Attribute::TARGET_PROPERTY
    | Attribute::TARGET_CLASS_CONSTANT
)]
final class Doc
{
    public function __construct(public readonly string $text) {}
}
```

### 5.1. `#[Variable]`

> `[ACCEPTED]`

Объявляет локальную переменную метода или функции.

```php
#[Variable('total', Scalar::Int)]
#[Variable('user', new ObjectOf(User::class))]
#[Variable('items', new ListOf(new ObjectOf(OrderItem::class)))]
#[Variable('map', new Map(Scalar::String, new ListOf(new ObjectOf(Order::class))))]
function process($user)
{
    $total = 0;
    $items = [];
    $map   = [];
    // ...
}
```

### 5.2. `#[Returns]`

> `[ACCEPTED]`

Объявляет возвращаемый тип значения. Не используется для
`Unit`/`Nothing` (для них — маркеры).

```php
#[Returns(Scalar::Int)]
#[Returns(new ObjectOf(User::class))]
#[Returns(new Union(Scalar::Int, Scalar::Null))]
#[Returns(Special::Any)]
#[Returns(Special::Object)]
#[Returns(Special::Array)]
function foo() { ... }
```

### 5.3. `#[Parameter]`

> `[ACCEPTED]`

Объявляет тип параметра метода или функции.

```php
#[Parameter('user', new ObjectOf(User::class))]
#[Parameter('count', Scalar::Int)]
function foo($user, $count) { ... }
```

### 5.4. `#[Property]`

> `[ACCEPTED]`

Объявляет тип свойства класса.

```php
#[Property(new ObjectOf(OrderRepository::class))]
var $orderRepository;
```

Target — только `PROPERTY`. На параметре — `R7.invalid-target`.
Promoted properties запрещены (R16).

### 5.5. `#[Immutable]`

> `[ACCEPTED]`

Свойство (или все свойства класса) не переприсваивается после
инициализации.

```php
#[Immutable]
class Config
{
    #[Property(Scalar::String)]
    var $name;

    #[Parameter('name', Scalar::String)]
    function __construct($name)
    {
        $this->name = $name;
    }
}
```

`#[Immutable]` на классе — все свойства immutable.
Per-property `#[Immutable]` на классе с `#[Immutable]` — ошибка
`R8.redundant-marker`.

Строгая семантика: свойство инициализируется **только** в
конструкторе класса, где объявлено. Переприсваивание — ошибка
`R2.immutable-reassign`. Если конструктор не инициализирует —
`R2.immutable-not-initialized`.

**Исключение: `__clone`.** В `__clone` переприсваивание
`#[Immutable]`-свойств разрешено. Клонирование — «новый объект»,
а не «переприсваивание существующего». `R2.immutable-reassign`
не срабатывает в `__clone` (§5.6).

### 5.6. `#[Cloneable]`

> `[ACCEPTED]` — с `__clone`.

Класс разрешает клонирование через `clone`.

```php
#[Cloneable]
class Money
{
    #[Property(Scalar::Int)]
    #[VisibleAs(Visibility::Private)]
    var $amount;

    #[Parameter('amount', Scalar::Int)]
    function __construct($amount)
    {
        $this->amount = $amount;
    }

    #[Unit]
    function __clone()
    {
        // Глубокое клонирование объектных свойств, если нужно.
        // Переприсваивание immutable — разрешено (исключение R2).
    }
}
```

`clone $x` разрешён, только если тип `$x` — класс с `#[Cloneable]`.
Иначе — `R17.clone-not-cloneable`.

**`__clone` разрешён** в `#[Cloneable]`-классе. Ограничения:

- **`__clone` — `#[Unit]`**, не бросает (`R17.clone-may-throw`).
  Cleanup при клонировании не бросает; если cleanup может бросить —
  это ошибка дизайна cleanup-метода, а не `__clone`.
- **`__clone` может переприсваивать свойства**, включая `#[Immutable]`.
  Это **исключение из R2** для `__clone`: клонирование — «новый
  объект», а не «переприсваивание существующего».
  `R2.immutable-reassign` не срабатывает в `__clone`.
- **`__clone` не может вызывать `#[Throws]`-методы** — только `#[Unit]`.
- **`__clone` не может бросать** — `R17.clone-may-throw`.

### 5.7. `#[VisibleAs]`

> `[ACCEPTED]`

Устанавливает видимость свойства, метода или константы.

```php
#[Property(Scalar::String)]
#[VisibleAs(Visibility::Private)]
var $name;

#[Returns(Scalar::String)]
#[VisibleAs(Visibility::Protected)]
function formatName() { ... }

#[VisibleAs(Visibility::Private)]
const INTERNAL_KEY = 'secret';
```

Default — `Visibility::Public` (атрибут опускается).
Target — `PROPERTY`, `METHOD`, `CLASS_CONSTANT`. На параметре —
`R7.invalid-target`.

**Константы:** разрешены `Visibility::Public` (default) и
`Visibility::Private`. `Visibility::Protected` на константе —
запрещён (`R14.protected-constant-forbidden`).

### 5.8. `#[Throws]`

> `[ACCEPTED]` — семантика изменена (2026-11-08), см. §6.

Декларация payload, с которым метод или функция может бросить
`ThrownValue`.

```php
#[Throws(new ObjectOf(OrderNotFound::class))]
#[Throws(new ObjectOf(PaymentFailed::class))]
#[Parameter('order', new ObjectOf(Order::class))]
#[Returns(Scalar::Int)]
function process($order) { ... }
```

Target — `METHOD`, `FUNCTION`. Может быть несколько `#[Throws]`
на одном методе. Принимает `ObjectOf(FQCN)` — класс, реализующий
`ThrowablePayload`. Семантика: метод может бросить `ThrownValue`
с payload этого типа.

**Не анализируется в flow analysis.** Это декларация метаинформации
для документации и вызывающего кода. Межпроцедурный анализ
исключений — вне scope диалекта. `#[Throws]` — это **обещание**
разработчика, а не доказательство.

**Не реализует `Type`.** Регистрируется как известный атрибут.

### 5.9. `#[Doc]`

> `[ACCEPTED]` — heredoc проверен (2026-11-09, §15.14).

Документация класса, метода, функции, свойства или константы.

```php
#[Doc('Processes an order and returns the total amount.')]
#[Parameter('order', new ObjectOf(Order::class))]
#[Returns(Scalar::Int)]
function process($order) { ... }

#[Doc('Default timeout in seconds.')]
const TIMEOUT = 30;
```

Target — `CLASS`, `METHOD`, `FUNCTION`, `PROPERTY`,
`CLASS_CONSTANT`. Принимает `string`. Многострочный текст — через
`\n` в строке или heredoc. Оба способа эквивалентны.

```php
#[Doc(<<<TEXT
Multi-line
documentation
TEXT)]
function foo() { ... }
```

**Не реализует `Type`.** Регистрируется как известный атрибут.

**Заменяет докблоки полностью.** Докблоки запрещены (R6.4).

### 5.10. R8 (No Redundancy)

> `[ACCEPTED]`

**В closed-файле нативные хинты запрещены** — `R8.hint-in-closed`.

**В bridge-файле атрибуты Lefu запрещены** —
`R8.attribute-in-bridge`. Хинты и модификаторы обязательны.

**Маркеры vs синтаксис:**
- `#[Unit]` + `: void` — ошибка.
- `#[Nothing]` + `: never` — ошибка.
- `#[Immutable]` + `readonly` — ошибка.

### 5.11. R10 (Type Descriptor Is Not a Value)

> `[ACCEPTED]`

`Scalar::*`, `Special::*`, `ObjectOf(...)`, `ListOf(...)`,
`Map(...)`, `Union(...)` — **дескрипторы типов, не значения**.

Использование дескриптора как значения разрешено **только если
объявленный тип цели — `Special`, `Scalar` или `Type`**.

```php
#[Returns(Special::Any)]
function decode(string $json)
{
    return Special::Any;  // ERROR: R10 — возврат дескриптора
}

#[Returns(new ObjectOf(Special::class))]
function resolve(string $name): Special
{
    return Special::Any;  // OK: метод возвращает дескриптор
}
```

Код: `lefu.R10.type-descriptor-as-value`. Диагностика
образовательная: объясняет разницу, даёт два пути исправления.

### 5.12. R7 (No Abbreviations)

> `[ACCEPTED]`

Имена, **вводимые диалектом**, — полные слова или композиты полных
слов. Сокращения запрещены.

**Исключение: заимствованные имена PHP-типов** (`int`, `bool`,
`float`, `string`, `null`, `void`, `never`, `mixed`, `iterable`,
`object`, `callable`, `array`). Они сохраняются как есть, даже если
являются сокращениями в английском, потому что альтернатива —
дублирование имён и разрыв с тайп-хинтами PHP.

**Операционный тест:** если имя можно заменить на полное слово
**без создания второго имени для того же понятия в PHP** — это
сокращение диалекта, запрещено. Если замена создаёт дублирование
(`Integer` vs `int`) — это заимствование, разрешено.

Примеры:
- `ObjectOf`, `ListOf`, `Map`, `Union`, `Scalar`, `Special`,
  `Variable`, `Returns`, `Parameter`, `Visibility`, `Types`,
  `Throws`, `Doc`, `Output`, `Result`, `ThrownValue` — разрешено.
- `Obj`, `Ref`, `Param`, `Var`, `Inst`, `Cls` — запрещено.


## 6. Модель ошибок

> **Статус раздела:** `[ACCEPTED]` — §6.1–6.8 закрыты.

### 6.1. Философия

Lefu различает два класса ошибок:

- **Ожидаемые** (бизнес-ошибки): заказ не найден, оплата не прошла, валидация не удалась. Это часть нормального потока. Для них — `Result`.
- **Исключительные** (системные сбои, bridge, непредвиденное): соединение с БД упало, сторонняя библиотека бросила исключение. Для них — `throw`/`catch`.

Разделение принципиальное:

- `Result` — **значение**. Обрабатывается в обычном коде, без ограничений на количество выражений. Это не control flow.
- `throw`/`catch` — **control flow**. `catch` — только **точка преобразования**, не место восстановления.

Почему не только `Result`: bridge-методы бросают нативные исключения; системные сбои (OOM, `TypeError`) не превращаются в `Result`; `exit()`/`die()` — терминаторы.

Почему не только `throw`: бизнес-ошибки не должны быть control flow. `if ($orderNotFound) { ... }` — нормальный код, а не исключительная ситуация.

Модель ошибок следует принципам §0.1: `Result` — значение, не control flow (принцип 8 — явность); `catch` — только преобразование (принцип 2 — нет escape hatches для бизнес-логики в `catch`); `ThrownValue extends Exception` — вынужденный заполнитель (принцип 3 — нет магии, но PHP-рантайм требует).

### 6.2. ThrowablePayload

```php
interface ThrowablePayload {}
```

Пустой маркер-интерфейс. Класс реализует `ThrowablePayload`, если его экземпляр может быть payload для `ThrownValue`.

Payload — **данные**, не поведение. Он не знает, как его обрабатывать. Никаких `recover()`, `describe()`. Если нужен текст для `getMessage()`, `ThrownValue::__construct` использует `get_class($payload)` — FQCN, машиночитаемо, уникально. Читаемый текст — через `#[Doc]` на payload-классе или через `Logger` (stdlib, в разработке).

Payload — `#[Immutable]`-класс. Ошибка не меняется после создания.

### 6.3. ThrownValue

```php
final class ThrownValue extends \Exception
{
    #[Property(new ObjectOf(ThrowablePayload::class))]
    #[VisibleAs(Visibility::Private)]
    #[Immutable]
    var $payload;

    #[Parameter('payload', new ObjectOf(ThrowablePayload::class))]
    function __construct($payload)
    {
        parent::__construct(get_class($payload));
        $this->payload = $payload;
    }

    #[Returns(new ObjectOf(Result::class))]
    function toResult()
    {
        return Result::fail($this->payload);
    }
}
```

- **Наследует `\Exception`** — вынужденный заполнитель (см. §2, §14, §17.3). Пользователь не может наследовать `Exception` (R13), stdlib может.
- **Payload** — immutable, set в конструкторе.
- **Создаётся в месте throw**: `throw new ThrownValue(new OrderNotFound($id))`. Трейс корректен.
- **`toResult()`** — преобразование в `Result` с `error = payload`. Единственный метод.
- **`getMessage()`** возвращает `get_class($payload)` — FQCN. Читаемый текст — через `#[Doc]` на payload-классе или `Logger`.

`ThrownValue` не `#[Cloneable]`: клонирование исключений — ошибка дизайна.

### 6.4. Result

```php
#[Immutable]
final class Result
{
    #[Property(new Union(new ObjectOf(ThrowablePayload::class), Scalar::Null))]
    #[VisibleAs(Visibility::Private)]
    var $error;

    #[Property(Special::Any)]
    #[VisibleAs(Visibility::Private)]
    var $value;

    #[Parameter('error', new Union(new ObjectOf(ThrowablePayload::class), Scalar::Null))]
    #[Parameter('value', Special::Any)]
    #[VisibleAs(Visibility::Private)]
    function __construct($error, $value)
    {
        $this->error = $error;
        $this->value = $value;
    }

    #[Parameter('value', Special::Any)]
    #[Returns(new ObjectOf(Result::class))]
    static function ok($value)
    {
        return new self(null, $value);
    }

    #[Parameter('payload', new ObjectOf(ThrowablePayload::class))]
    #[Returns(new ObjectOf(Result::class))]
    static function fail($payload)
    {
        return new self($payload, null);
    }

    #[Returns(Scalar::Bool)]
    function isOk()
    {
        return $this->error === null;
    }

    #[Returns(Scalar::Bool)]
    function isErr()
    {
        return $this->error !== null;
    }

    #[Returns(Special::Any)]
    #[Throws(new ObjectOf(ThrowablePayload::class))]
    function unwrap()
    {
        if ($this->error !== null) {
            throw new ThrownValue($this->error);
        }
        return $this->value;
    }

    #[Parameter('default', Special::Any)]
    #[Returns(Special::Any)]
    function unwrapOr($default)
    {
        if ($this->error !== null) {
            return $default;
        }
        return $this->value;
    }

    #[Returns(new Union(new ObjectOf(ThrowablePayload::class), Scalar::Null))]
    function error()
    {
        return $this->error;
    }
}
```

- **Один класс, не `Ok`/`Err`.**
- **`value: Special::Any`.** Требует сужения через `Types::matches` вне catch.
- **`isOk()`/`isErr()`** — проверка `error === null`.
- **`unwrap()`** — возвращает значение или бросает `ThrownValue(payload)`. `#[Throws]` декларирует контракт.
- **`unwrapOr($default)`** — никогда не бросает.
- **`error()`** — для инспекции payload. Не `payload()`: `payload` — термин `ThrownValue`, в `Result` — `error`. `$result->error()` читается как «дай ошибку».
- **`map(callable-object): Result`** — `[DEFERRED]` (v2). Без дженериков `map` — синтаксический сахар, который скрывает `Special::Any`. Пользователь пишет `if ($r->isOk()) { ... }` явно — это честнее.

`Result` — `#[Immutable]`. Все свойства set в конструкторе, не переприсваиваются.

**6.4.1. Почему один класс, не `Ok`/`Err` и не `Result<T, E>`.** Без дженериков `T` и `E` не выразить тип значения. `Ok`/`Err` без дженериков не работают. Один класс с `error: Union(Payload, Null)` и `value: Special::Any` — минимально достаточно.

### 6.5. Правила

**6.5.1. Result-функция.** Функция, возвращающая `Result`: `#[Returns(new ObjectOf(Result::class))]`. Не имеет `#[Throws]`.

```php
#[Parameter('id', Scalar::Int)]
#[Returns(new ObjectOf(Result::class))]
function findOrder($id)
{
    if (/* не найден */) {
        return Result::fail(new OrderNotFound($id));
    }
    return Result::ok($order);
}
```

**6.5.2. Throw-функция.** Функция, бросающая `ThrownValue`: `#[Throws(new ObjectOf(Payload::class))]`. Не возвращает `Result`.

```php
#[Parameter('id', Scalar::Int)]
#[Returns(new ObjectOf(Order::class))]
#[Throws(new ObjectOf(OrderNotFound::class))]
function findOrder($id)
{
    if (/* не найден */) {
        throw new ThrownValue(new OrderNotFound($id));
    }
    return $order;
}
```

**6.5.3. Catch — только преобразование.** Единственная допустимая форма тела catch — `return $e->toResult();` или `throw $e;`.

```php
try {
    $order = $this->findOrder($id);
} catch (ThrownValue $e) {
    return $e->toResult();
}
```

**6.5.4. Запрет смешения.** Функция не может быть Result-функцией и Throw-функцией одновременно: `R18.result-and-throw-mixed`.

**6.5.5. Throw только ThrownValue.** В closed-файле `throw` разрешён только для `ThrownValue`: `R18.throw-not-thrownvalue`.

**6.5.6. Catch только ThrownValue.** В closed-файле `catch` разрешён только для `ThrownValue`: `R18.catch-native-forbidden`.

**6.5.7. ThrownValue создаётся в месте throw.** `throw new ThrownValue(...)` — inline. `$e = new ThrownValue(...); throw $e;` — разрешено, но трейс может указывать на строку `new`, а не `throw`. Рекомендуется inline.

**6.5.8. Bridge — trust boundary.** Bridge-методы могут бросать нативные исключения (`RuntimeException`, `InvalidArgumentException` и т.д.). Closed-код их не ловит. Если bridge-метод должен возвращать ошибку в closed-мир — он возвращает `Result` (создаёт `Result::fail($payload)` внутри bridge). **Bridge не бросает `ThrownValue`:** `ThrownValue` — только closed-код. Bridge бросает только нативные исключения. Смешение двух миров в bridge — `R18.bridge-throws-thrownvalue-forbidden`.

**Причина:** если bridge бросает `ThrownValue`, он смешивает два мира: нативные исключения и `ThrownValue`. Closed-код ловит `ThrownValue`, но не нативные. Если bridge бросает `ThrownValue`, closed-код может его поймать — но bridge также может бросить нативное исключение, которое closed-код не поймает. Это непоследовательно. Bridge — нативные правила, closed — `ThrownValue`.

**6.5.9. `finally`.** Блок `finally` разрешён в closed-файлах с тремя ограничениями:

- **Нет `return`/`throw` внутри** — `R18.finally-control-flow-forbidden`.
- **Только `#[Unit]`-вызовы** — `R18.finally-may-throw`.
- **Не влияет на TSE** — работает с `declared_types`, не с narrowed.

`try/finally` без `catch` разрешён: cleanup без перехвата.

`finally` — **базовая конструкция cleanup**. `with`-паттерн в stdlib — сахар над `finally`.

Пример:

```php
$file = Files::open($path);
try {
    return $this->parse($file);
} finally {
    $file->close(); // #[Unit], не бросает
}
```

Пример с `catch`:

```php
try {
    $order = $this->findOrder($id);
} catch (ThrownValue $e) {
    return $e->toResult();
} finally {
    $this->logger->flush(); // #[Unit]
}
```

### 6.6. Коды

- `R18.result-and-throw-mixed` — функция возвращает `Result` и имеет `#[Throws]`.
- `R18.catch-not-toresult` — тело catch не `return $e->toResult();` и не `throw $e;`.
- `R18.catch-native-forbidden` — catch ловит не `ThrownValue` в closed.
- `R18.throw-not-thrownvalue` — throw бросает не `ThrownValue` в closed.
- `R18.finally-control-flow-forbidden` — `finally` содержит `return`/`throw`.
- `R18.finally-may-throw` — `finally` содержит вызов, не помеченный `#[Unit]`.
- `R18.bridge-throws-thrownvalue-forbidden` — bridge бросает `ThrownValue`.

### 6.7. Примеры

**Result-функция с обработкой:**

```php
$result = $this->findOrder($id);
if ($result->isErr()) {
    $err = $result->error();
    if (Types::matches($err, new ObjectOf(OrderNotFound::class))) {
        // $err: ObjectOf(OrderNotFound)
        return $this->handleNotFound($err);
    }
    throw new ThrownValue($err);
}
$order = $result->unwrap();
```

**Throw-функция с catch:**

```php
try {
    $order = $this->findOrder($id);
} catch (ThrownValue $e) {
    return $e->toResult();
}
```

**Bridge, преобразующий нативное исключение в Result:**

```php
// bridge-файл
public function fetch(string $url): Result
{
    try {
        $response = $this->client->get($url);
        if ($response->getStatusCode() !== 200) {
            return Result::fail(new ApiError($url));
        }
        return Result::ok(json_decode($response->getBody()->getContents(), true));
    } catch (\RuntimeException $e) {
        return Result::fail(new ApiError($url));
    }
}
```

**Bridge, который пытается бросить `ThrownValue` — ошибка:**

```php
// bridge-файл
public function findOrder(int $id): Order
{
    if (/* не найден */) {
        throw new ThrownValue(new OrderNotFound($id));
        // ERROR: R18.bridge-throws-thrownvalue-forbidden
    }
    return $order;
}
```

**Правильно — bridge возвращает `Result`:**

```php
// bridge-файл
public function findOrder(int $id): Result
{
    if (/* не найден */) {
        return Result::fail(new OrderNotFound($id));
    }
    return Result::ok($order);
}
```

### 6.8. Открытые вопросы

> `[ACCEPTED]` — все закрыты (2026-11-09).

- `Result::map(callable-object): Result` — `[DEFERRED]` (v2). Без дженериков `map` скрывает `Special::Any`. Пользователь пишет `if ($r->isOk())` явно — честнее. В v2 — когда будет `Result<T, E>` (если будет).
- `Result::error()` — имя метода. Не `payload()`: `payload` — термин `ThrownValue`, в `Result` — `error`.
- `ThrownValue::__construct` с `get_class($payload)` — достаточно для `getMessage()`. FQCN машиночитаемо, уникально. Читаемый текст — через `#[Doc]` на payload-классе или `Logger`.
- `#[Throws(new ObjectOf(ThrowablePayload::class))]` для `unwrap()` — корректно. `unwrap()` может бросить `ThrownValue` с любым payload; `ThrowablePayload` — единственный корректный тип.
- Bridge, создающий `ThrownValue` — **запрещено** (`R18.bridge-throws-thrownvalue-forbidden`). Bridge возвращает `Result`, не бросает `ThrownValue`.


## 7. Правила R0–R19 и I0–I3

> **Статус раздела:** `[PARTIAL]` — R5, R14, I2 `[PARTIAL]`, остальные `[ACCEPTED]`.

### R0. Гигиена файла

> `[ACCEPTED]` — добавлен `unsupported-declare`.

- `lefu.R0.missing-strict-types` — нет `declare(strict_types=1)`.
- `lefu.R0.unreachable-code` — недостижимый код после terminator.
- `lefu.R0.unsupported-declare` — `declare`, отличный от `strict_types=1`.

**`declare(strict_types=1);`** — единственный разрешённый `declare`. Обязателен в каждом closed-файле (§1.2). Любой другой `declare` (`ticks`, `encoding`, блочная форма `strict_types`) — `R0.unsupported-declare`.

**Причина:** `ticks` — глобальное состояние через `register_tick_function`, противоречит принципам 3 (нет магии) и 8 (явность). `encoding` — игнорируется в PHP 8.0+. Блочная форма `strict_types` создаёт вариативность «strict/не strict» внутри файла.

### R1. Полная декларация

> `[ACCEPTED]`

- Каждая локальная переменная — в `#[Variable]`.
- Каждый параметр — в `#[Parameter]` (closed mode).
- Каждое свойство — в `#[Property]` (closed mode).
- Возврат — в `#[Returns]` / `#[Unit]` / `#[Nothing]`.

Коды:
- `R1.undeclared-variable`
- `R1.untyped-parameter`
- `R1.untyped-return`
- `R1.untyped-property`
- `R1.undeclared-foreach-var`
- `R1.undeclared-catch-var`
- `R1.missing-return`

Исключения: `$this`, суперглобалы.

### R2. Инвариантность типа (upper bound)

> `[ACCEPTED]` — исключение для `__clone`.

`declared_type` — верхняя граница. `current_type ⊆ declared_type`.
Присваивание: `expr_type ⊆ declared_type`. Narrowing — refinement,
не смена типа. Join — `Union` `current_types` при слиянии веток.

Коды:
- `R2.type-mismatch`
- `R2.incompatible-assignment`
- `R2.unit-returns-value`
- `R2.unit-result-used`
- `R2.nothing-returns`
- `R2.immutable-reassign`
- `R2.immutable-not-initialized`

**Immutable (строгая семантика):** свойство инициализируется только
в конструкторе класса, где объявлено. Переприсваивание — ошибка
`R2.immutable-reassign`. Если конструктор не инициализирует —
`R2.immutable-not-initialized`.

**Исключение: `__clone`.** В `__clone` переприсваивание
`#[Immutable]`-свойств разрешено. Клонирование — «новый объект»,
а не «переприсваивание существующего». `R2.immutable-reassign`
не срабатывает в `__clone` (§5.6).

### R3. Запрет переиспользования имён

> `[ACCEPTED]`

В пределах метода имя переменной объявляется один раз.

Коды:
- `R3.duplicate-declaration`
- `R3.reused-name`

### R4. Запрет mixed и Any без сужения

- `eval()`.
- `compact()` в теле метода.

- `global`.
- Ссылки (`&$x`, `use (&$x)`).

**Дополнительные запреты:**

- **`echo` / `print` / `printf`** — `R5.echo-forbidden`. Замена: `Output::write` / `Output::error` / `Strings::format` (§17.2).
- **`yield` / генераторы** — `R5.generator-forbidden`. Замена: материальные `ListOf(T)` / `Map(K, V)`. `[DEFERRED]`.
- **`__destruct`** — `R5.destructor-forbidden`. Замена: `try/finally`, `[#finalize]` через DI (§11.8). В bridge разрешён.
- **`@` (error suppression)** — `R5.error-suppression-forbidden`. Замена: явная обработка через `try`/`catch` или `#[Throws]`.
- **Backticks (`` `cmd` ``)** — `R5.shell-exec-forbidden`. Замена: bridge-файл.
- **`goto`** — `R5.goto-forbidden`. Замена: структурированные конструкции.
- **`include`, `include_once`, `require`, `require_once`** — `R5.include-forbidden`. Замена: autoload (composer); `Files::requirePhp` (stdlib, в разработке, §15.17); bridge — временно.

### R6. Комментарии, директивы, документация

> `[ACCEPTED]` — все подразделы.

#### R6.1. Директивы

> `[ACCEPTED]`

`// lefu: <name>` — директива анализатора. Разрешена только
в начале файла (после `<?php` и опционального license block,
до `declare(strict_types=1)`). Не считается комментарием,
R6.2–R6.7 на неё не распространяются.

Текущие директивы:
- `// lefu: bridge` — файл-мост.

#### R6.2. Комментарии

> `[ACCEPTED]`

`//` — только в теле метода/функции. Только с префиксом из списка:
`WHY:`, `TODO:`, `FIXME:`, `SEE:`, `NOTE:`.

- `R6.unstructured-comment` — `//` без префикса.
- `R6.comment-outside-body` — `//` с префиксом, но вне тела
  метода/функции.

Примеры разрешённого:
```php
function process($order)
{
    // WHY: This must run before flush to avoid a race condition.
    $this->flush();
    $this->sync();
}
```

Примеры запрещённого:
```php
// This method processes the order.     — R6.unstructured-comment
```

#### R6.3. Блочные комментарии запрещены

> `[ACCEPTED]`

`/* ... */` — запрещены везде, кроме license block (R6.8).
`R6.block-comment-forbidden`.

#### R6.4. Докблоки запрещены

> `[ACCEPTED]`

`/** ... */` — запрещены везде, включая license block.
`R6.docblock-forbidden`.

Замена: `#[Doc('text')]` и `#[Throws(new ObjectOf(Exception::class))]`.

#### R6.5. `#`-комментарии запрещены

> `[ACCEPTED]`

`# text` — запрещены везде, кроме license block.
`R6.hash-comment-forbidden`.

#### R6.6. `@` в комментариях запрещён

> `[ACCEPTED]`

`@` в любом комментарии — `R6.suppression-forbidden`.
Закрывает `@psalm-suppress`, `@phpstan-ignore`, `@var`, `@param`,
`@return`, `@noinspection` и любые другие smuggle-каналы.
Распространяется и на license block. Email → `(at)`.

#### R6.7. Сводная таблица

> `[ACCEPTED]`

| Форма | Где | Правило |
|---|---|---|
| `/* SPDX/Copyright ... */` | Начало файла, один | ✅ R6.8 |
| `// WHY/TODO/FIXME/SEE/NOTE: ...` | Только в теле метода | ✅ |
| `// lefu: bridge` | Начало файла | ✅ (директива) |
| `// text` (без префикса) | Где угодно | ❌ R6.unstructured-comment |
| `// PREFIX: ...` | Вне тела метода | ❌ R6.comment-outside-body |
| `/* ... */` (не license) | Где угодно | ❌ R6.block-comment-forbidden |
| `/** ... */` | Где угодно | ❌ R6.docblock-forbidden |
| `# ...` (не license) | Где угодно | ❌ R6.hash-comment-forbidden |
| `@tag` в комментарии | Где угодно | ❌ R6.suppression-forbidden |

#### R6.8. License block (единственное исключение)

> `[ACCEPTED]`

**Разрешён один блочный комментарий `/* ... */` в начале файла.**

Правила:

1. **Расположение:** после `<?php`, до `declare(strict_types=1)`.
2. **Количество:** не более одного на файл. `R6.license-multiple`.
3. **Формат:** только `/* ... */`, не `/** ... */`.
4. **Содержимое:**
   - **Должен содержать** `SPDX-License-Identifier:` ИЛИ `Copyright`. Иначе — `R6.license-invalid`.
   - **Не должен содержать** PHP-код: `<?php`, `?>`, `$`, `function`, `class`, `namespace`. Иначе — `R6.license-code`.
   - **Не освобождено** от `R6.suppression-forbidden` (`@` запрещён).
5. **Рекомендация:** `SPDX-License-Identifier:` предпочтителен. Если есть только `Copyright` — info `I3.missing-spdx`.

Пример с SPDX:
```php
<?php
/*
 * SPDX-License-Identifier: MPL-2.0
 * This Source Code Form is subject to the terms of the Mozilla
 * Public License, v. 2.0. If a copy of the MPL was not distributed
 * with this file, You can obtain one at
 * https://mozilla.org/MPL/2.0/.
 */

// lefu: bridge
declare(strict_types=1);
```

### R12. Property Hooks запрещены

> `[ACCEPTED]` — property hooks запрещены полностью. Accessor-сахар — `[DEFERRED]` (v2, §15.7).

**Полностью запрещены в v1.** Код `R12.property-hook-forbidden`.

**Причина:** проверка backing store неоднозначна. Где граница «прямого доступа»? `get => $this->name` — бесполезно (зачем хук, если он просто возвращает свойство). `get => strtoupper($this->name)` — уже трансформация, не backing store. `#[Immutable]` + `set`-хук — сложная семантика (immutable нарушается через setter). Property hooks — новая фича PHP 8.4+, мало проверена. Вводить в Lefu v1 — риск.

**Accessor-сахар — `[DEFERRED]` (v2).** Когда появится ясность, как анализатор проверяет backing store, — пересмотрим. Пока — `[DEFERRED]`.

**Замена:**
- **Immutable value objects:** публичные свойства + `#[Immutable]`. `$user->id` читается напрямую, `R2.immutable-reassign` ловит переприсваивание. Геттеры не нужны.
- **Mutable DTO:** публичные свойства. Mutation напрямую. Сеттеры не нужны.
- **Инкапсуляция mutable state (редко):** явные методы `getX()`/`setX()`. Многословно, но честно — анализатор видит типы, никакой магии.

**Коды (остаются для будущего, когда accessor-сахар будет активирован):**
- `R12.property-hook-forbidden` — property hooks запрещены.
- `R12.virtual-property-forbidden` — виртуальные свойства запрещены.
- `R12.asymmetric-visibility-forbidden` — асимметричная видимость запрещена.
- `R12.immutable-with-set-hook` — `#[Immutable]` + `set`-хук.
- `R12.implicit-noop-setter-forbidden` — неявный no-op setter.

**В v1** все пять кодов срабатывают на любой property hook (`R12.property-hook-forbidden`). Остальные четыре — резерв для v2.

### R13. Наследование классов и трейты запрещены

> `[ACCEPTED]` — трейты запрещены полностью. Контракты — интерфейсы, без трейтов.

**Наследование классов в closed-мире запрещено полностью.**

- `abstract class` — `R13.abstract-class-forbidden`.
- `abstract` метод — `R13.abstract-method-forbidden`.
- `class Foo extends Bar` — `R13.extends-forbidden`.
- Все классы — неявно final. Нативный `final` — `R14.native-modifier-forbidden`.
- **Исключение: stdlib-класс `ThrownValue` наследует `Exception`** — вынужденный заполнитель (§2, §14, §17.3).

**Замена abstract-классов:**
- Контракт (abstract методы) → `interface`.
- Общая реализация (конкретные методы) → **композиция** (вложить объект-помощник).
- Общее состояние (свойства) → **композиция**.

**Трейты запрещены полностью.** `R13.trait-forbidden`.

**Причина:** PHP-трейты — copy-paste кода с неявным `$this`, без типизации, с ручным разрешением конфликтов (`insteadof`/`as`). Против принципа 3 («Нет магии»). Пользователь, которому нужны трейты, — не целевая аудитория Lefu.

**Никаких `use`-трейтов, никаких `insteadof`/`as`, никаких трейтов способностей.** Трейт — не тип. `ObjectOf(Trait::class)` — `R13.trait-as-type-forbidden`.

**Контракты (стандартная библиотека lefu):**

- `\Stringable` — нативный интерфейс PHP 8.0+. Ничего не создаём.
- `#[Cloneable]` — маркер-атрибут (не контракт, не интерфейс).
- `Equatable` — `equals(mixed $other): bool`. Ручная реализация в каждом классе. Без `WithEquatable`.
- `Hashable` — `hashCode(): int`. Ручная реализация. Без `WithHashable`.
- `Comparable` — `compareTo(mixed $other): int`. Ручная реализация. Без `WithComparable`.

**Контракты — только интерфейсы.** Реализация — вручную в каждом классе. Автоматическая реализация через reflection — магия, против принципа 3. `WithEquatable`/`WithHashable`/`WithComparable` — `[REJECTED]` (§14.1).

### R14. Нативные модификаторы, type guards, Union объектов

> `[PARTIAL]` — базовые запреты `[ACCEPTED]`, `new $className($args)` `[ACCEPTED]` (§11.3).

**Нативные модификаторы (`public`/`private`/`protected`/`final`)
запрещены в closed-файлах** — `R14.native-modifier-forbidden`.

**Вынужденные синтаксические маркеры:**
- `var` — для свойств.

**Методы:** без модификатора = public. Видимость — `#[VisibleAs]`.
**Свойства:** `var $x;`. Видимость — `#[VisibleAs]`.
**Константы:** без модификатора = public. Видимость — `#[VisibleAs]` (`Public` или `Private`; `Protected` запрещён).
**Классы:** без модификатора = неявно final.

**Type guards запрещены:**
- `instanceof` — `R14.instanceof-forbidden`.
- `is_int`, `is_string`, `is_bool`, `is_float`, `is_null`, `is_array`, `is_object`, `is_a`, `is_callable`, `is_iterable`, `is_resource` — `R14.native-typeguard-forbidden`.
- Пользовательские type guards — `R14.user-typeguard-forbidden`.
- Единственный разрешённый type guard — `Types::matches` с литеральным Type (§4.8).
- `$x === null` / `$x !== null` / `isset($x)` — не type guards, разрешены и сужают.

**Union объектов запрещён** (§4.6) — `R14.union-of-objects-forbidden`.

**Проверки видимости:**
- `#[VisibleAs(Visibility::Private)]` на методе, реализующем интерфейс — `R14.interface-method-not-public`.
- `#[VisibleAs(Visibility::Private)]` на `__toString` — `R14.tostring-must-be-public`.
- `#[VisibleAs]` на параметре — `R14.visibility-on-parameter`.
- `#[VisibleAs(Visibility::Protected)]` на константе — `R14.protected-constant-forbidden`.

**Динамическая инстанциация:**
- `new $className()` где `$className: Scalar::String` — разрешено. Результат — `Special::Object`. Требует сужения через `Types::matches`.
- `new $className($args)` с аргументами — разрешено. Аргументы конструктора — trust boundary (§11.5). Результат — `Special::Object`, требует сужения.

**Bridge:** нативные модификаторы, type guards (`is_*`, `instanceof`) **обязательны**. Отсутствие модификатора — `R14.bridge-missing-modifier`.

### R15. Static свойства запрещены

**Static методы разрешены.** Основа стандартной библиотеки.

### R16. Promoted properties запрещены

Причина: размывает границу свойство/параметр, требует нативного
модификатора (`var` в параметрах — parse error), создаёт
двусмысленность атрибутов.

### R17. Loose comparison и falsy-магия запрещены

> `[ACCEPTED]` — добавлен `clone-may-throw`.

**Запрещены:**
- `==`, `!=`, `<>` — `R17.loose-comparison-forbidden`.
- `switch` — `R17.switch-forbidden`. Замена: `match`.
- `in_array` без `true` — `R17.in-array-without-strict-forbidden`.
- `array_search` без `true` — `R17.array-search-without-strict-forbidden`.
- `empty()` — `R17.empty-forbidden`.
- `$x ?: $y` (elvis) — `R17.elvis-forbidden`.
- `if ($x)` где `$x` не `Scalar::Bool` — `R17.truthy-check-forbidden`.

**Разрешены:**
- `===`, `!==` — strict.
- `match` — использует `===`.
- `in_array($x, $arr, true)`.
- `array_search($x, $arr, true)`.
- `$x ?? $y` — null-coalescing.
- `Types::matches($x, Scalar::Bool)`.
- `if ($x === true)` / `if ($x === false)`.

**Cloneable-проверки:**
- `R17.clone-not-cloneable` — clone без `#[Cloneable]`.
- `R17.clone-may-throw` — `__clone` содержит вызов, не помеченный `#[Unit]`, или бросает.

### R19. Неизвестные атрибуты

> `[ACCEPTED]` — error (перенесён из I1).

**`R19.unknown-attribute`** — найден атрибут, неизвестный lefu.
**Error**, блокирует сборку.

**Причина:** Lefu против поведенческих атрибутов. Если атрибут
меняет поведение бизнес-логики — это нарушение принципа
«имя = семантика». Пользователь должен **явно** зарегистрировать
атрибут в `[attributes].known` конфига, осознанно приняв решение.

**Известные атрибуты (не вызывают R19):**
- Все атрибуты lefu (`Variable`, `Parameter`, `Property`, `Returns`,
  `Unit`, `Nothing`, `Immutable`, `Cloneable`, `VisibleAs`,
  `Throws`, `Doc`).
- Встроенные PHP: `\Override`, `\Deprecated`, `\SensitiveParameter`,
  `\DelayedTargetValidation`, `\AllowDynamicProperties`.
- Инфраструктурные атрибуты: `[#finalize]` (DI, §11.8).
- Зарегистрированные в `[attributes].known` конфига.

**Сообщение:**

```
error[lefu.R19.unknown-attribute]
  Unknown attribute: ORM\Column

  lefu does not analyze this attribute and cannot guarantee
  application correctness when it alters behavior.

  Behavioral attributes are discouraged in lefu. If this attribute
  is pure metadata, register it in lefu.toml under
  [attributes].known:

    [attributes]
    known = ["ORM\\Column"]

  If it alters business logic, reconsider using it in lefu.
```

## 8. Режимы файлов и структура файла

> **Статус раздела:** `[ACCEPTED]` — §8.4 обновлён (регистрация обязательна), §8.7 — echo/var_dump запрещены.

### 8.1. Closed mode (по умолчанию)

> `[ACCEPTED]`

Активируется **конфигом**. Всё, что не в `exclude` и не bridge, —
closed.

**Структура файла диалекта:**

```php
<?php
[опционально] /* license block, один, с SPDX или Copyright */
[опционально] // lefu: <name> (директива)
declare(strict_types=1);
[опционально] namespace ...;
[опционально] use ...;

class Foo { /* ... */ }
```

**В closed-файле:**
- Нативные хинты запрещены (R8).
- Нативные модификаторы запрещены (R14).
- Все типы — через атрибуты.
- Все свойства — `var` + `#[Property]` + `#[VisibleAs]`.
- `readonly` запрещён (R8), `#[Immutable]` — замена.
- Замыкания (R9), анонимные классы (R11), property hooks (R12), static свойства (R15), promoted properties (R16) — запрещены.
- Нативные type guards запрещены (R14), `Types::matches` — единственный type guard.
- Наследование классов запрещено (R13). Исключение — stdlib `ThrownValue` наследует `Exception` (§6.3).
- Трейты запрещены (R13). Никаких исключений.
- `throw`/`catch` только для `ThrownValue` (R18).
- `finally` с тремя ограничениями (§6.5.9).
- `__destruct` запрещён (R5), `yield` запрещён (R5).
- Loose comparison и falsy-магия запрещены (R17).
- `echo`/`print`/`printf` запрещены (R5), заменены `Output` (§17.2).
- Валидация: boot-check или CLI-check.

### 8.2. Bridge (граница мира)

> `[ACCEPTED]`

```php
<?php
// lefu: bridge
declare(strict_types=1);

namespace App\Integration;

final class ExternalApiClient
{
    public function __construct(
        private readonly \GuzzleHttp\ClientInterface $client,
    ) {}

    public function fetch(string $url): array
    {
        $response = $this->client->get($url);
        if ($response->getStatusCode() !== 200) {
            throw new \RuntimeException('API error');
        }
        return json_decode($response->getBody()->getContents(), true);
    }
}
```

**В bridge-файле:**
- Нативные хинты **обязательны**.
- Нативные модификаторы **обязательны**.
- Нативные type guards (`is_*`, `instanceof`) **обязательны**.
- Атрибуты lefu запрещены (`R8.attribute-in-bridge`).
- `extends` разрешён (включая `Exception`).
- Трейты разрешены (bridge — нативные правила).
- `__destruct` разрешён.
- License block разрешён (R6.8).
- Bridge не бросает `ThrownValue` (`R18.bridge-throws-thrownvalue-forbidden`) — возвращает `Result`.

### 8.3. Excluded (вне диалекта)

> `[ACCEPTED]`

Указывается в `exclude` конфига (vendor, generated, cache).
Не анализируется lefu.

### 8.4. Конфиг проекта: `lefu.toml`

> `[ACCEPTED]` — регистрация обязательна.

```toml
# lefu.toml
mode = "closed"

exclude = [
    "vendor/**",
    "var/**",
    "generated/**",
]

[attributes]
# Пользовательские атрибуты, известные lefu (не вызывают R19)
known = [
    "App\\Attribute\\AuditLog",
    "App\\Attribute\\Cacheable",
    "Duyler\\DI\\Attribute\\Finalize",
]
```

**Регистрация обязательна:** незарегистрированный атрибут —
`R19.unknown-attribute` (error), сборка блокируется. Это
осознанное решение: Lefu против поведенческих атрибутов,
пользователь должен явно принять риск.

### 8.5. Бинарность

> `[ACCEPTED]`

Файл либо closed (по умолчанию), либо bridge (маркер), либо
excluded (конфиг). Третьего нет. Файл исключений не существует.
Миграция — по файлам, не по правилам.

### 8.6. У lefu нет `unsafe`

> `[ACCEPTED]`

Rust `unsafe` — для FFI, raw pointers, transmute. В PHP этого нет.
Граница с внешним кодом — bridge-файлы, а не `unsafe`.

### 8.7. Встроенные функции PHP: переходный период

> `[ACCEPTED]` — `echo`/`print`/`printf`/`var_dump` запрещены с v1.

**Текущее состояние:** встроенные функции PHP разрешены, но:
- callable-аргументы — только callable-object, не замыкание (R9);
- `in_array`/`array_search` — только с третьим аргументом `true` (R17).

**Целевое состояние:** все встроенные функции PHP запрещены.
Вместо них — статические методы стандартной библиотеки.

**Вывод (`echo`, `print`, `printf`)** — **запрещены в closed с v1** (`R5.echo-forbidden`). `Output` в stdlib с v1 (§17.2) — единственный способ вывода.

**Отладка (`var_dump`, `print_r`, `var_export`)** — запрещены в closed (`R5.dynamic-construct-forbidden`). Замена: `Output::debug` (§17.2).


## 9. Flow analysis

> **Статус раздела:** `[PARTIAL]` — §9.7 `[PARTIAL]`, остальное `[ACCEPTED]`.

### 9.1. Модель

> `[ACCEPTED]`

Flow-sensitive typing with declared upper bound. В каждой точке
программы анализатор ведёт TSE: `variable → current_type`.

Инвариант: `current_type(v) ⊆ declared_type(v)`.

### 9.2. Операции

> `[ACCEPTED]`

- `narrow(tse, cond) → (tse_true, tse_false)`.
- `join(tse1, tse2) → tse`.
- `assign(tse, var, expr_type) → tse'`.
- `check(tse, expr, expected_type) → ok | error`.

### 9.3. Подтипы

> `[ACCEPTED]`

```
Scalar::Int     ⊆ Scalar::Int
Scalar::Int     ⊆ Union(Scalar::Int, ...)
Union(A)        ⊆ Union(A, B)
ObjectOf(Foo)   ⊆ Special::Object
ListOf(T)       ⊆ Special::Array
Map(K,V)        ⊆ Special::Array
Special::Object ⊆ Special::Any
Special::Array  ⊆ Special::Any
T               ⊆ Special::Any   (top type)
ObjectOf(Foo)   ⊆ ObjectOf(Bar)  если:
                                   - Foo = Bar, или
                                   - Foo implements Bar (Bar — интерфейс), или
                                   - Foo extends Bar (Bar — класс), где
                                     extends-цепочка видна lefu
ListOf(T)       ⊆ ListOf(T)      (инвариантно)
Map(K,V)        ⊆ Map(K,V)       (инвариантно)
```

**«Видна lefu»** означает:
- **Bridge:** `class FileLogger extends BaseLogger` — lefu парсит bridge, видит `extends`. Подтипизация работает.
- **Stdlib:** `ThrownValue extends Exception` — lefu видит stdlib. Подтипизация работает.
- **Closed:** `extends` запрещён (R13).
- **Native PHP-классы:** иерархия не видна lefu. `ObjectOf(RuntimeException) ⊆ ObjectOf(Exception)` не выводится. Использовать `ObjectOf(Throwable)` явно или `Types::matches`.

### 9.4. Допустимые сужения (закрытый список)

> `[ACCEPTED]` — базовый список + контракты.

**`Types::matches($x, $literalType)`:** true → сужает `$x` до `$literalType`; false → не меняется.

- `Types::matches($x, Scalar::Int)` → `Scalar::Int`.
- `Types::matches($x, Special::Object)` → `Special::Object`.
- `Types::matches($x, Special::Array)` → `Special::Array`.
- `Types::matches($x, new ObjectOf(Foo::class))` → `ObjectOf(Foo)`.
- `Types::matches($x, new ObjectOf(LoggerInterface::class))` → `ObjectOf(LoggerInterface)`.
- `Types::matches($x, new ListOf(...))` → `ListOf(...)`.
- `Types::matches($x, new Map(...))` → `Map(...)`.
- `Types::matches($x, new Union(...))` → `Union(...)`.

**`Types::matches($x, $variableType)`:** runtime check без narrowing.

**`$x === null` / `$x !== null`:** сравнение.
- `$x !== null` → true: `remove_null(current)`; false: `Scalar::Null`.
- `$x === null` → true: `Scalar::Null`; false: `remove_null(current)`.

**`isset($x)`:** существование.
- true: `remove_null(current)`; false: `Scalar::Null`.

**`assert(Types::matches($x, $literalType))`:** как if без else.

**`&&`, `||`, `??`:** короткое замыкание, сужение в правом операнде.

**Тернарник:** как if/else + join.

**Ранний выход:** `return`, `throw`, `exit()`, `die()` как terminator. После if с terminator'ом действует отрицание условия.

**Nothing-функции:** вызов `#[Nothing]`-функции — terminator.

**Контракты:** `Types::matches($x, Equatable::class)` — `[ACCEPTED]`, см. §15.8. Сужает `Special::Object` до `Equatable`. Аналогично для `Hashable`, `Comparable`.

### 9.5. НЕ сужается (закрытый список)

> `[ACCEPTED]`

- `instanceof` — запрещён (R14).
- `is_*`, `is_a`, `is_callable`, `is_iterable`, `is_resource` — запрещены (R14).
- Пользовательские type guards — запрещены (R14).
- Литеральные типы (`42`, `'foo'`) — не поддерживаются.
- Целочисленные диапазоны — не поддерживаются.
- Сложная булева алгебра (XOR, дистрибуция).
- Инварианты циклов (только join на back-edge).
- Наследование TSE из try в catch (catch начинает с `declared_types`).
- `switch` — запрещён (R17), замена: `match`.
- `array_key_exists`, `property_exists`, `method_exists`.

### 9.6. Если анализатор не сужает

> `[ACCEPTED]`

Пользователь должен **переписать код**, а не подавить ошибку (R6).

### 9.7. Специальные конструкции

> `[PARTIAL]` — базовые конструкции `[ACCEPTED]`, multi-catch `[ACCEPTED]` (запрещён, см. §6), finally `[ACCEPTED]`, деструктуризация `[ACCEPTED]`.

**foreach:**
- `foreach ($expr as $item)`: `$item := element_type(expr_type)`.
  - `ListOf(T)` → `$item: T`.
  - `Map(K, V)` → `$item: V`.
  - `Special::Array` → `$item: Special::Any`.
- `foreach ($expr as $key => $value)`:
  - `$key := key_type(expr_type)`.
  - `$value := value_type(expr_type)`.
- `&$item` запрещено (R5).

**Деструктуризация (`list()` / `[]`):**

- `[$a, $b] = $list` где `$list: ListOf(T)` → `$a: Union(T, Scalar::Null)`, `$b: Union(T, Scalar::Null)`.
- `['x' => $a, 'y' => $b] = $map` где `$map: Map(K, V)` → `$a: Union(V, Scalar::Null)`, `$b: Union(V, Scalar::Null)`.
- `[$a, $b] = $arr` где `$arr: Special::Array` → `$a: Special::Any`, `$b: Special::Any`. Требует сужения (R4).
- Пропуски: `[, $b] = $list` → `$b: Union(T, Scalar::Null)`.
- Вложенная: рекурсивно по тем же правилам.
- `foreach ($pairs as [$a, $b])` — деструктуризация элемента.
- Ссылки (`[&$a] = $list`) — запрещены (R5).
- Tuple-деструктуризация — `[DEFERRED]` (§15.18).

`list()` и `[]` — синонимы.

**catch:**
- `catch (ThrownValue $e)` → `$e := ObjectOf(ThrownValue)`. Единственная допустимая форма в closed (§6.5.6).
- `catch (FooException $e)` (нативное) — `R18.catch-native-forbidden`.
- `catch (Foo | Bar $e)` (multi-catch, нативные) — `R18.catch-native-forbidden`.
- `catch` без переменной (PHP 8+) — `R18.catch-native-forbidden`.

**try-catch:** catch не наследует TSE из try. Начинает с `declared_types`.

**finally:**
- `try/finally` без `catch`: TSE после `finally` — `join(TSE_try_exit, TSE_finally_exit)`.
- `try/catch/finally`: TSE после `finally` — `join(TSE_try_exit, TSE_catch_exit, TSE_finally_exit)`.
- `finally` работает с `declared_types`, не с narrowed.
- `finally` не содержит `return`/`throw` (`R18.finally-control-flow-forbidden`).
- `finally` содержит только `#[Unit]`-вызовы (`R18.finally-may-throw`).

**break/continue:** развёртка в CFG с явными рёбрами.

**match:**
- Без `default`: join всех arm (без default path).
- С `default`: join всех arm, включая default.

### 9.8. Терминаторы и достижимость

> `[ACCEPTED]`

Terminator'ы: `return`, `throw`, `exit()`, `die()`, `break`,
`continue`, вызов `#[Nothing]`-функции.

Код после terminator'а — `R0.unreachable-code`.

Функция не-`Unit` без terminator'а — `R1.missing-return`.

`#[Unit]`-функция — обычный return без значения, **не** terminator.

### 9.9. Алгоритм

> `[ACCEPTED]`

1. Построить CFG из AST (`nikic/php-parser`).
2. Инициализировать TSE в entry: `declared_type` для всех параметров и `#[Variable]`.
3. Forward pass по CFG.
4. Проверить missing return.
5. Собрать diagnostics.

Производительность: O(|CFG| × |TSE| × iterations). Итераций обычно ≤ 3.

## 11. Интеграция с приложением

> **Статус раздела:** `[PARTIAL]` — §11.4, §11.5 `[PARTIAL]`, §11.3 — `[ACCEPTED]`, §11.8 — `[ACCEPTED]` (finalize, R19).

### 11.1. Boot-check

> `[ACCEPTED]`

При старте приложения анализатор вызывается один раз. Ошибки
(`error`) — исключение + exit code 1. Info — лог.

### 11.2. DI

> `[ACCEPTED]`

DI-контейнер читает типы из `#[Parameter]`, `#[Property]`,
`#[Returns]` через рефлексию. Autowiring по `ObjectOf(Interface::class)` работает.

### 11.3. Динамическая инстанциация

> `[ACCEPTED]` — `new $className($args)` разрешён.

`new $className()` где `$className: Scalar::String` — разрешено.
Результат — `Special::Object`. Требуется сужение через `Types::matches`.

**`new $className($args)` с аргументами** — разрешено. Результат — `Special::Object`. Аргументы конструктора — **trust boundary**: lefu не знает, какой класс будет инстанцирован, значит не знает сигнатуру конструктора, значит не проверяет аргументы. Ответственность пользователя. См. §11.5.

### 11.4. Boot-time code generation

> `[PARTIAL]` — принцип `[ACCEPTED]`, формат invoker `[OPEN]` (§15.13).

Приложения могут генерировать invoker-код при старте. Generated
invoker — **closed-код**, валидируется lefu. Использует
`Types::matches` с **литеральными** Type-объектами → narrowing
работает → статическая гарантия.

### 11.5. Trust boundary

> `[PARTIAL]` — принцип `[ACCEPTED]`, кэширование `[OPEN]` (§15.13).

Единственное динамическое место — распаковка значений с типом
`Special::Any` (например, `Result::unwrap()`). Распаковка в
generated invoker с литеральными Type → narrowing работает.

**Аргументы конструктора при динамической инстанциации** —
trust boundary. `new $className($args)`: lefu не знает
`$className`, значит не знает сигнатуру конструктора, значит
не проверяет аргументы. Если аргументы не совпадают с
сигнатурой — рантайм-ошибка (`TypeError`). Модель типов её
не ловит и не должна.

Всё остальное (вызов методов, wiring) — статически проверено
boot-check.

### 11.6. Конфиг приложения

> `[ACCEPTED]`

Конфиг приложения (build-конфиг, декларации) — **closed-файлы**.
Если конфиг использует class-strings (`MyClass::class`),
это `Scalar::String`.

### 11.7. Bridge — только внешние библиотеки

> `[ACCEPTED]`

Bridge используется для интеграции с внешним кодом:
- Composer-зависимости, не переписанные на lefu.
- PSR-интерфейсы.
- Сторонние SDK.
- БД-драйверы.

Всё остальное — closed. Bridge-методы могут возвращать `Result`.

### 11.8. Внешние атрибуты

> `[ACCEPTED]` — R19 вместо I1.

Сторонние атрибуты (ORM, DI, сериализация) регистрируются
в `[attributes].known` конфига. Lefu не анализирует их поведение
и не гарантирует корректность. Если атрибут не зарегистрирован —
`R19.unknown-attribute` (**error**), сборка блокируется.

**Поведенческие атрибуты не приветствуются.**

**`[#finalize]`** — application-level cleanup через DI (stdlib).
Регистрируется в `[attributes].known`. Инфраструктурный атрибут.

### 11.9. Документация

> `[ACCEPTED]`

`#[Doc]` и `#[Throws]` — источник документации. Генератор
документации читает атрибуты через рефлексию.


## 12. Ориентация на LLM

> **Статус раздела:** `[ACCEPTED]`

### 12.1. Спецификация как system prompt

> `[ACCEPTED]`

R0–R19 и I0–I3 целиком вставляются в prompt.

### 12.2. Простые и полные правила

> `[ACCEPTED]`

- **Простые:** LLM ошибается на границах правил.
- **Полные:** если есть конструкция, не покрытая правилом, LLM использует её как дыру.
- **Максимализм:** «объявляй все переменные» предпочтительнее «объявляй только невыводимые».

### 12.3. Диагностика для LLM

> `[ACCEPTED]`

JSON с `code`, `expected`, `actual`, `hint`. LLM исправляет по диагностике.

### 12.4. Ключевые правила для system prompt

> `[ACCEPTED]`

- «`Scalar::*`, `Special::*`, `ObjectOf(...)`, `ListOf(...)`, `Map(...)`, `Union(...)` — дескрипторы типов, не значения.»
- «В closed-файлах нет нативных хинтов, нет нативных модификаторов, нет `readonly`. Все типы — через атрибуты, видимость — `#[VisibleAs]`.»
- «Свойства — только `var $x;` в теле класса. Никаких promoted, никаких static.»
- «Методы — без модификатора = public. Видимость — `#[VisibleAs]`.»
- «Замыкания запрещены. Callable — только объекты с `__invoke`.»
- «Анонимные классы запрещены. Только именованные классы.»
- «`#[Unit]` — возврат без значения. `#[Nothing]` — не возвращает управление.»
- «Type guards: только `Types::matches($x, $literalType)`. Нативные `is_*` и `instanceof` запрещены. `$x === null` / `isset($x)` — не type guards, разрешены.»
- «`Union` — только для nullable и скаляров. `Union` объектов запрещён.»
- «Наследование классов запрещено. Нет `abstract`, нет `extends`. Исключение: stdlib `ThrownValue extends Exception`.»
- «Трейты запрещены полностью (`R13.trait-forbidden`). Никаких `use`-трейтов, никаких `insteadof`/`as`. Контракты (`Equatable`, `Hashable`, `Comparable`) — только интерфейсы, реализация вручную в каждом классе. `WithEquatable`/`WithHashable`/`WithComparable` не существуют (`[REJECTED]`).»
- «`ObjectOf(Foo) ⊆ ObjectOf(Bar)` если `Foo = Bar`, `Foo implements Bar`, или `Foo extends Bar` (extends-цепочка видна lefu в bridge/stdlib). Native PHP-иерархия не включается.»
- «`new $className($args)` разрешён: результат `Special::Object`, аргументы — trust boundary, требуют сужения результата.»
- «Деструктуризация `[$a, $b] = $list` где `$list: ListOf(T)` → `$a: Union(T, Null)`, `$b: Union(T, Null)`. `ListOf` не гарантирует длину.»
- «Деструктуризация `['x' => $a] = $map` где `$map: Map(K, V)` → `$a: Union(V, Null)`. `Map` не гарантирует ключ.»
- «Деструктуризация `[$a, $b] = $arr` где `$arr: Special::Array` → `$a: Special::Any`, `$b: Special::Any`. Требует сужения.»
- «Tuple — `[DEFERRED]` для v1. Не в пространстве типов. Деструктуризация Tuple запрещена.»
- «`==`, `!=`, `<>`, `switch`, `empty()`, `?:`, truthy-check запрещены. Используй `===`, `match`, `??`, явные проверки.»
- «`in_array`/`array_search` — только с третьим аргументом `true`.»
- «`clone` разрешён только для классов с `#[Cloneable]`.»
- «Два мира: `Result` (ожидаемые ошибки) и `throw`/`catch` (исключительные). Catch — только `return $e->toResult();` или `throw $e;`.»
- «Result-функция: `#[Returns(new ObjectOf(Result::class))]`, без `#[Throws]`. Throw-функция: `#[Throws(new ObjectOf(Payload::class))]`, не возвращает `Result`. Смешение запрещено.»
- «`throw` только для `ThrownValue`: `throw new ThrownValue(new Payload(...))`. `catch` только для `ThrownValue`. Нативные исключения — bridge.»
- «`#[Throws]` указывает payload (класс, реализующий `ThrowablePayload`), не Throwable.»
- «`finally` — только для cleanup, без `return`/`throw`, только `#[Unit]`-вызовы. `try/finally` без `catch` разрешён.»
- «`__destruct` запрещён в closed. `yield` запрещён. `declare` — только `strict_types=1`.»
- «Вывод — только через `Output::write` / `Output::error` / `Output::debug`. `echo`, `print`, `printf`, `var_dump`, `print_r`, `var_export` запрещены.»
- «Форматирование — через `Strings::format`, не `sprintf`. Логирование — через `Logger` (stdlib, в разработке), не `Output::debug`.»
- «Встроенные функции PHP разрешены, но callable-аргументы — только callable-object.»
- «Неизвестные атрибуты — **error** (`R19.unknown-attribute`). Регистрируй в `[attributes].known`. Lefu против поведенческих атрибутов.»
- «`__clone` в `#[Cloneable]`-классе: `#[Unit]`, не бросает, может переприсваивать `#[Immutable]` (исключение R2).»
- «Property hooks запрещены полностью. Замена: явные методы `getX()`/`setX()` для инкапсуляции; публичные свойства + `#[Immutable]` для value objects; публичные свойства для mutable DTO.»

- **Трейты запрещены полностью** (`R13.trait-forbidden`). Никаких исключений. PHP-трейты — copy-paste с неявным `$this`, без типизации, с ручным разрешением конфликтов. Против принципа 3.

- **Неизвестные атрибуты — error** (`R19.unknown-attribute`). Явная регистрация в `[attributes].known`.
- `Special::Any`, `Special::Object`, `Special::Array` — top types.
- `Types::matches` — единственный type guard в closed.
- `$x === null` / `$x !== null` / `isset($x)` — не type guards.

- Маркер `// lefu: strict` не существует.
- `==`, `!=`, `<>` запрещены полностью. `switch`, `empty()`, `?:`, truthy-check — запрещены. `in_array`/`array_search` — только с `true`.
- `#[Cloneable]` — маркер-атрибут, не наследуется.
- **`__clone` разрешён в `#[Cloneable]`-классе** с ограничениями: `#[Unit]`, не бросает (`R17.clone-may-throw`), может переприсваивать `#[Immutable]` (исключение R2), не вызывает `#[Throws]`-методы.

- Boot-time code generation — closed-код, валидируется lefu.
- Trust boundary сжатый: распаковка `Special::Any` до конкретного типа, аргументы конструктора `new $className($args)`.
- Производительность `Types::matches` vs нативных `is_*` — не приоритет.
- **Все публичные имена lefu — в глобальном namespace.**
- **Autoloading через classmap**, не PSR-4.

- **`echo` / `print` / `printf` запрещены в closed с v1.**
- **`var_dump` / `print_r` / `var_export` запрещены.**
- **`Output` — отдельный модуль stdlib, не часть `Files`.**

- **Деструктуризация `ListOf`/`Map` — через `Union(T, Scalar::Null)`.**
- **Tuple — `[DEFERRED]` для v1.**
- **Вложенная деструктуризация и деструктуризация в `foreach` разрешены.**

- **`Result::error()` — имя метода.**

### 14.1. Отклонённые решения

> `[REJECTED]` — чтобы не возвращаться.

- **`WithEquatable` / `WithHashable` / `WithComparable` — `[REJECTED]`.** Автоматическая реализация через reflection — магия, против принципа 3. Без reflection — пустой трейт, бесполезен. Пользователь пишет `equals`/`hashCode`/`compareTo` вручную. Многословно, но честно — анализатор видит код.
- **Способности как механизм (интерфейс + трейт) — `[REJECTED]`.** Трейты запрещены (R13), автоматическая реализация — магия. Остались только контракты — интерфейсы без трейтов.
- **`Accessible` / `WithAccessible` — `[REJECTED]`.** Это `__get`/`__set` под другим именем, нарушает R5 (`dynamic-construct-forbidden`) и принцип 3 («Нет магии»). Теряет типы: `$user->get('id')` → `Special::Any`, требует `Types::matches` на каждом обращении. Хуже, чем явный `getId()`.
- **`#[Getter]` / `#[Setter]` — `[REJECTED]`.** Поведенческие атрибуты: меняют поведение (генерируют методы), нарушают принцип «имя = семантика» и R19 (`unknown-attribute`, error). Lefu против поведенческих атрибутов (§11.8).
- **«Магия внутри stdlib» для accessors — `[REJECTED]`.** Привилегии stdlib — закрытый список (§17.3). Добавление `__get`/`__set`/reflection/codegen в stdlib для accessors — расширение списка, нарушение принципа 3. Если пользователь хочет геттеры — явные методы.


## 15. Открытые вопросы

> **Статус раздела:** `[OPEN]` / `[DEFERRED]` — каждый пункт имеет свой статус.

### 15.1. Верификация enum case'ов

> `[ACCEPTED]` — проверено на PHP 8.5 (2026-11-09).

`case Int` / `case Bool` / `case Null` работают. `Scalar::Null->value` возвращает `'null'`. Замена на `IntType`/`BoolType`/`NullType` не нужна.

### 15.2. Контракты: каноническая реализация

> `[ACCEPTED]` — ручная реализация (2026-11-09).

**`Equatable`:** `equals(mixed $other): bool`. Ручная реализация в каждом классе. Пример:

```php
class Money implements Equatable
{
    #[Property(Scalar::Int)]
    #[VisibleAs(Visibility::Private)]
    var $amount;

    #[Parameter('amount', Scalar::Int)]
    function __construct($amount) { $this->amount = $amount; }

    #[Parameter('other', Special::Any)]
    #[Returns(Scalar::Bool)]
    function equals($other)
    {
        if (!Types::matches($other, new ObjectOf(self::class))) {
            return false;
        }
        // $other: ObjectOf(self::class)
        return $this->amount === $other->amount;
    }
}
```

**`Hashable`:** `hashCode(): int`. Ручная реализация. Identity hash через `spl_object_id` — легитимно для identity-семантики. Value hash — комбинация хешей полей, вручную.

**`Comparable`:** `compareTo(mixed $other): int`. Ручная реализация. Критерий сравнения — на усмотрение класса.

**Без `With*`-трейтов.** Автоматическая реализация через reflection — магия, против принципа 3. `WithEquatable`/`WithHashable`/`WithComparable` — `[REJECTED]` (§14.1).

**Семантическая доказуемость `equals`/`hashCode`/`compareTo` невозможна** ни для какого механизма. Анализатор проверяет сигнатуру, не семантику. Это как Rust: `PartialEq` — трейт, компилятор проверяет сигнатуру, не семантику.

**`==`/`<=>` для объектов запрещены** (R17). `equals`/`compareTo` — единственный способ сравнения. `===` — identity, не переопределяется.

### 15.7. Property hooks: реализация R12

> `[ACCEPTED]` — `[DEFERRED]` (v2, 2026-11-09).

**Property hooks запрещены полностью в v1** (R12). Accessor-сахар — `[DEFERRED]` (v2).

**Причина `[DEFERRED]`:** проверка backing store неоднозначна. Где граница «прямого доступа»? `get => $this->name` — бесполезно. `get => strtoupper($this->name)` — трансформация. `#[Immutable]` + `set`-хук — сложная семантика. Property hooks — новая фича PHP 8.4+, мало проверена.

**Когда будет активирован accessor-сахар (v2):**
- Только backed-property (не виртуальное).
- `get => $this->backingProperty` (только прямой доступ, без трансформаций).
- `set => $this->backingProperty = $value` (только прямой доступ).
- `#[Property]` на backing store обязателен.
- `#[Immutable]` + `set` — запрещено (`R12.immutable-with-set-hook`).

**Замена в v1:**
- **Immutable value objects:** публичные свойства + `#[Immutable]`. Геттеры не нужны.
- **Mutable DTO:** публичные свойства. Сеттеры не нужны.
- **Инкапсуляция mutable state (редко):** явные методы `getX()`/`setX()`.

### 15.8. `Types::matches` и контракты

> `[ACCEPTED]` — контракты (2026-11-09).

`Types::matches($x, Equatable::class)` — проверка контракта, разрешена. Сужает `Special::Object` до `Equatable`. Аналогично для `Hashable`, `Comparable`.

Прописать в §9.4 (добавлено). Narrowing работает: `Equatable::class` — литеральный Type-объект (интерфейс известен на этапе компиляции).

**Пример:**

```php
#[Parameter('value', Special::Object)]
#[Unit]
function compare($value)
{
    if (Types::matches($value, Equatable::class)) {
        // $value: Equatable
        $value->equals($other);
    }
}
```

### 15.9. `$this` в трейтах

> `[ACCEPTED]` — трейты запрещены полностью (2026-11-09).

Трейтов нет (`R13.trait-forbidden`). Вопрос `$this` в трейтах неактуален. Пользовательские трейты — `[REJECTED]` (трейты запрещены). Пользовательские контракты — `[OPEN]` (возможно, в будущем, но не в v1).

### 15.10. `#[Cloneable]` + `__clone`

> `[ACCEPTED]` — `__clone` с ограничениями (2026-11-09).

`__clone` разрешён в `#[Cloneable]`-классе. Ограничения (§5.6):

- `__clone` — `#[Unit]`, не бросает (`R17.clone-may-throw`).
- `__clone` может переприсваивать свойства, включая `#[Immutable]`
  (исключение из R2, §7 R2).
- `__clone` не может вызывать `#[Throws]`-методы.

Shallow clone (PHP по умолчанию) опасен для объектных свойств.
Пользователь, которому нужно глубокое клонирование, пишет
`__clone` явно.

### 15.11. Truthy-check в существующем коде

> `[ACCEPTED]` — запрет принят, объём работы открыт.

В существующем коде `if ($x)` встречается часто. Запрет (R17)
означает рефакторинг. Это **принято** (философия первична),
но объём работы — открытый вопрос.

### 15.12. `new $className()` с аргументами

`new $className($arg1, $arg2)` разрешён в closed. Результат —
`Special::Object`, требует сужения. Аргументы конструктора —
trust boundary.

### 15.18. Tuple

> `[DEFERRED]` — v2.

`Tuple(T1, T2, ...)` — фиксированная длина, разнородные типы.

append/unset/merge, special-casing `Tuple::of`, расширение
`#[Variable]` для проверки литерала, arity-check деструктуризации).
Деструктуризация без Tuple работает через `Union(T, Null)`.

**Решение по созданию (когда будет):** литерал +
`#[Variable(new Tuple(...))]`. Не `Tuple::of`, не эвристика.

**Деструктуризация Tuple (когда будет):** arity-check обязателен.
Частичная деструктуризация запрещена (Tuple — контракт «все
элементы нужны»).

### 16.1. Полный класс с зависимостями

> `[ACCEPTED]`

```php
<?php
/*
 * SPDX-License-Identifier: MIT
 * Copyright 2024 ACME Corp.
 */

declare(strict_types=1);

namespace App\Service;

use App\Model\User;
use App\Model\Order;
use App\Model\OrderItem;
use App\Repository\OrderRepository;

class OrderProcessor
{
    #[Property(new ObjectOf(OrderRepository::class))]
    #[VisibleAs(Visibility::Private)]
    #[Immutable]
    var $orderRepository;

    #[Parameter('orderRepository', new ObjectOf(OrderRepository::class))]
    function __construct($orderRepository)
    {
        $this->orderRepository = $orderRepository;
    }

    #[Doc('Returns the total amount for a user across all orders.')]
    #[Throws(new ObjectOf(OrderRepositoryFailure::class))]
    #[Parameter('user', new ObjectOf(User::class))]
    #[Returns(Scalar::Int)]
    #[Variable('total', Scalar::Int)]
    #[Variable('order', new ObjectOf(Order::class))]
    #[Variable('item', new ObjectOf(OrderItem::class))]
    #[Variable('subtotal', Scalar::Int)]
    function totalFor($user)
    {
        $total = 0;
        foreach ($this->orderRepository->byUser($user) as $order) {
            // NOTE: order.items() is cached at the repository level.
            $subtotal = 0;
            foreach ($order->items() as $item) {
                $subtotal += $item->price();
            }
            $total += $subtotal;
        }
        return $total;
    }
}
```

### 16.9. Контракты (Equatable)

```php
<?php
```

### 16.10. Result и ThrownValue

> `[ACCEPTED]`

**Result-функция:**

**Throw-функция:**



## 17. Stdlib

> **Статус раздела:** `[PARTIAL]` — §17.1–17.3 `[ACCEPTED]`, §17.4 `[PARTIAL]`, §17.5 `[OPEN]`.

### 17.1. Философия

> `[ACCEPTED]`

Stdlib — стандартная библиотека Lefu. Публичные имена — в глобальном namespace (§2). Stdlib имеет **привилегии**, которых нет у пользовательского кода: `extends Exception` для `ThrownValue`, `fwrite(STDOUT, ...)` для `Output`, `finally` для `with`-паттерна. Эти привилегии — вынужденные заполнители (§2), требуемые PHP-рантаймом или семантикой cleanup. Они не открывают дверь для пользователя: пользовательский код не может наследовать `Exception` (R13), не может использовать `fwrite` напрямую (R5), не может писать `finally` без ограничений (§6.5.9).

Stdlib — не «ещё один способ». Где stdlib предоставляет метод, прямой доступ к встроенной функции PHP запрещён (R5, R19). `Output::write` вместо `echo`, `Files::writeString` вместо `fwrite`, `Arrays::map` вместо `array_map`.

### 17.2. Output

> `[ACCEPTED]`

Модуль вывода в стандартные потоки и отладки. Отдельный модуль, не часть `Files` (§17.4): `Files` — про файлы по пути, `Output` — про stdout/stderr/debug.

```php
#[Immutable]
final class Output
{
    #[Parameter('text', Scalar::String)]
    #[Unit]
    static function write($text);

    #[Parameter('text', Scalar::String)]
    #[Unit]
    static function error($text);

    #[Parameter('value', Special::Any)]
    #[Unit]
    static function debug($value);
}
```

- **`Output::write($text)`** — запись в stdout. Внутри — `fwrite(STDOUT, $text)` (bridge-привилегия). Ошибки вывода проглатываются.
- **`Output::error($text)`** — запись в stderr. Внутри — `fwrite(STDERR, $text)`.
- **`Output::debug($value)`** — отладочный вывод структуры значения. Внутри — `var_dump($value)`.

**Форматирование** — через `Strings::format` (отдельный модуль).

**Логирование** — через `Logger` (отдельный модуль, в разработке).

### 17.3. Привилегии stdlib

> `[ACCEPTED]`

| Привилегия | Где | Обоснование |
|---|---|---|
| `extends Exception` | `ThrownValue` (§6.3) | PHP-рантайм требует `extends Exception` для `Throwable`. |
| `fwrite(STDOUT, ...)` | `Output` (§17.2) | Прямая запись в поток. |
| `var_dump` | `Output::debug` (§17.2) | Отладочный вывод. |
| `finally` без ограничений | `Files::with`, `Transactions::with` (§6.5.9) | Cleanup в stdlib-методах. |
| `require`/`include` | `Files::requirePhp` (§15.17) | Загрузка PHP-файлов. `[OPEN]`. |

Привилегии stdlib **не наследуются** пользовательским кодом. Закрытый список.
