## 1. Назначение и связь с диалектом

`lefu/attributes` — runtime-пакет, который делает **синтаксис Lefu возможным**. Без него нельзя написать ни одну строку на Lefu: атрибуты `#[Property]`, `#[Returns]`, дескрипторы `Scalar::Int`, `ObjectOf(...)` — всё это определено здесь.

Пакет содержит:
- **Дескрипторы типов** — `Type` (интерфейс), `Scalar`, `Special`, `Visibility` (enum'ы), `ObjectOf`, `ListOf`, `Map`, `Union` (классы), `Types` (runtime type guard).
- **Атрибуты** — `Property`, `Parameter`, `Variable`, `Returns`, `Unit`, `Nothing`, `Immutable`, `Cloneable`, `VisibleAs`, `Throws`, `Doc`.
- **Маркер-интерфейс** — `ThrowablePayload` (для `#[Throws]`).
- **Контракты** — `Equatable`, `Hashable`, `Comparable` (интерфейсы).

**Семантика** (что означает `ListOf(T)`, как работает narrowing, какие правила R0–R20) — в `Lefu — Specification`. Этот документ описывает **реализацию**: PHP-код, сигнатуры, runtime-поведение.

**Все имена — в глобальном namespace** (без префикса `Lefu\`). Это осознанное решение: имена диалекта — часть синтаксиса, не API пакета. См. `Lefu — Specification` §1.4.

**Пакет написан на обычном PHP 8.5, не на Lefu.** Это bootstrap: Lefu ещё не может анализировать сам себя. Пользовательский код на Lefu использует эти атрибуты. Внутри пакета допустимы нативные функции (`is_int`, `instanceof`) — это runtime-привилегия (§10).


## 2. Установка и autoloading

### 2.1. Установка

```bash
composer require lefu/attributes
```

Пакет — **runtime-зависимость** (не `--dev`). Он нужен в production: атрибуты читаются через рефлексию при boot-check, DI, генерации документации.

Анализатор (`lefu/analyzer`) устанавливается отдельно как dev-зависимость:

```bash
composer require --dev lefu/analyzer
```

### 2.2. Autoloading

**Classmap, не PSR-4.** Причина: все имена в глобальном namespace, PSR-4 требует namespace-префикс.

`composer.json` пакета:

```json
{
  "name": "lefu/attributes",
  "description": "Lefu dialect runtime: type descriptors, attributes, contracts",
  "type": "library",
  "license": "MIT",
  "require": {
    "php": ">=8.5"
  },
  "autoload": {
    "classmap": ["src/"]
  }
}
```

Структура `src/`:

```
src/
├── Type.php
├── Scalar.php
├── Special.php
├── Visibility.php
├── ObjectOf.php
├── ListOf.php
├── Map.php
├── Union.php
├── Types.php
├── Property.php
├── Parameter.php
├── Variable.php
├── Returns.php
├── Unit.php
├── Nothing.php
├── Immutable.php
├── Cloneable.php
├── VisibleAs.php
├── Throws.php

```

Каждый файл — один класс/enum/интерфейс, `declare(strict_types=1);`, глобальный namespace.

### 2.3. Конфликты имён

Имена в глобальном namespace (`Map`, `Union`, `Property`, `Parameter`, `Variable`, `Types`) — высокорисковые. Если PHP core или третий пакет введёт одно из них — конфликт. Решение — по мере поступления (см. `Lefu — Specification` §15.15). Пре-флайт проверка — `lefu/conflict-checker` (рекомендуется, вне scope).


## 3. Зависимости

**Runtime-зависимости:** только `php: >=8.5`.

**Почему не меньше:** нужны enum'ы (8.1), `new` в аргументах атрибутов (8.1), `#[\DelayedTargetValidation]` (8.5), `TARGET_ALL` со значением 127 (8.5).

**Dev-зависимости:** нет. Пакет не содержит тестов в этом документе (тесты — отдельная задача реализации).

**Зависимость от `lefu/stdlib`:** **нет.** `lefu/attributes` — фундамент. `lefu/stdlib` зависит от `lefu/attributes`, не наоборот. `ThrowablePayload` (маркер для `#[Throws]`) — в attributes, потому что `#[Throws]` — часть языка. `Result`/`ThrownValue` — в stdlib, потому что модель ошибок опциональна.


## 4. Пространство типов (реализация)

> Семантика (подтипизация, narrowing, что означает `Special::Any` как top type) — в `Lefu — Specification` §4. Здесь — PHP-код.

### 4.1. Type (интерфейс)

```php
<?php
declare(strict_types=1);

interface Type
{
    public function describe(): string;
    public function accepts(mixed $value): bool;
}
```

**Контракт:**
- `describe(): string` — человекочитаемое описание типа (для диагностики, логов). `Scalar::Int` → `"int"`, `ListOf(Scalar::Int)` → `"list<int>"`.
- `accepts(mixed $value): bool` — runtime-проверка: соответствует ли значение типу. Используется в `Types::matches()`.

**`mixed` в сигнатуре `accepts`** — нативный `mixed`, не `Special::Any`. Это runtime-метод, принимает любое значение. Нативный `mixed` здесь — вынужденный заполнитель (пакет написан на PHP, не на Lefu).

### 4.2. Scalar (enum)

```php
<?php
declare(strict_types=1);

enum Scalar: string implements Type
{
    case Int    = 'int';
    case String = 'string';
    case Bool   = 'bool';
    case Float  = 'float';
    case Null   = 'null';

    public function describe(): string
    {
        return $this->value;
    }

    public function accepts(mixed $value): bool
    {
        return match ($this) {
            self::Int    => is_int($value),
            self::String => is_string($value),
            self::Bool   => is_bool($value),
            self::Float  => is_float($value),
            self::Null   => $value === null,
        };
    }
}
```

**`case Int` / `case Bool` / `case Null`** — проверены на PHP 8.5 (см. `Lefu — Specification` §15.1). Работают.

### 4.3. Special (enum)

```php
<?php
declare(strict_types=1);

enum Special: string implements Type
{
    case Any    = 'Any';
    case Object = 'object';
    case Array  = 'array';

    public function describe(): string
    {
        return $this->value;
    }

    public function accepts(mixed $value): bool
    {
        return match ($this) {
            self::Any    => true,
            self::Object => is_object($value),
            self::Array  => is_array($value),
        };
    }
}
```

### 4.4. ObjectOf

```php
<?php
declare(strict_types=1);

final class ObjectOf implements Type
{
    public function __construct(public readonly string $className) {}

    public function describe(): string
    {
        return $this->className;
    }

    public function accepts(mixed $value): bool
    {
        return $value instanceof $this->className;
    }
}
```

**`$className`** — FQCN класса **или** интерфейса. Если интерфейс — `accepts()` проверяет `instanceof` (объект реализует контракт). Интерфейс — номинальный тип, не структурный.

**`public readonly string $className`** — `readonly` здесь допустим: пакет написан на обычном PHP, `readonly` — нативный модификатор. В пользовательском Lefu-коде `readonly` запрещён (R8), но внутри stdlib-пакета — привилегия.

### 4.5. ListOf

```php
<?php
declare(strict_types=1);

final class ListOf implements Type
{
    public function __construct(public readonly Type $item) {}

    public function describe(): string
    {
        return "list<{$this->item->describe()}>";
    }

    public function accepts(mixed $value): bool
    {
        if (!is_array($value) || !array_is_list($value)) {
            return false;
        }
        foreach ($value as $item) {
            if (!$this->item->accepts($item)) {
                return false;
            }
        }
        return true;
    }
}
```

**`array_is_list`** (PHP 8.1+) — проверяет, что массив — list (ключи 0..n-1, без пропусков). Если не list — `ListOf` не принимает (это `Map`, не `ListOf`).

**Инвариантность:** `ListOf(T)` не ковариантен. `ListOf(Scalar::Int) ⊆ ListOf(Scalar::Int)` — только если `T` совпадает точно. Это описано в `Lefu — Specification` §9.3.

### 4.6. Map

```php
<?php
declare(strict_types=1);

final class Map implements Type
{
    public function __construct(
        public readonly Type $key,
        public readonly Type $value,
    ) {}

    public function describe(): string
    {
        return "array<{$this->key->describe()}, {$this->value->describe()}>";
    }

    public function accepts(mixed $value): bool
    {
        if (!is_array($value)) {
            return false;
        }
        foreach ($value as $k => $v) {
            if (!$this->key->accepts($k) || !$this->value->accepts($v)) {
                return false;
            }
        }
        return true;
    }
}
```

**`Map` принимает любой массив**, включая list. `Map(Scalar::Int, Scalar::String)` примет `[0 => 'a', 1 => 'b']` (list с int-ключами). Если нужен именно list — `ListOf`.

### 4.7. Union

```php
<?php
declare(strict_types=1);

final class Union implements Type
{
    /** @var Type[] */
    public readonly array $types;

    public function __construct(Type ...$types)
    {
        if (count($types) < 2) {
            throw new \InvalidArgumentException(
                'Union must have at least 2 types'
            );
        }
        $this->types = $types;
    }

    public function describe(): string
    {
        return implode('|', array_map(
            static fn(Type $t): string => $t->describe(),
            $this->types,
        ));
    }

    public function accepts(mixed $value): bool
    {
        foreach ($this->types as $type) {
            if ($type->accepts($value)) {
                return true;
            }
        }
        return false;
    }
}
```

**`\InvalidArgumentException`** — нативное исключение. Внутри пакета допустимо (runtime-привилегия, §10). Пользовательский Lefu-код не может бросать нативные исключения (R18.throw-not-thrownvalue), но пакет — не Lefu-код.

**`Union` с < 2 типами** — ошибка конструирования. Анализатор не допустит `Union(Scalar::Int)` (нужно минимум 2), но runtime-защита тоже есть.

**Правила использования** (что разрешено, что запрещено — `Union` объектов, вложенные `Union`) — в `Lefu — Specification` §4.6.

### 4.8. Types (runtime type guard)

```php
<?php
declare(strict_types=1);

final class Types
{
    public static function matches(mixed $value, Type $type): bool
    {
        return $type->accepts($value);
    }
}
```

**Единственный type guard в closed-мире.** Пользовательский код использует только `Types::matches($x, $literalType)`. Внутри — делегирует `$type->accepts($value)`.

**Narrowing** (сужение типа в flow analysis) — семантика анализатора, не runtime. `Types::matches` возвращает `bool`, narrowing делает анализатор на основе литеральности второго аргумента. См. `Lefu — Specification` §4.8, §9.4.


## 5. Атрибуты

> Семантика атрибутов (что означает `#[Property]`, `#[Throws]`, `#[Immutable]`) — в `Lefu — Specification` §5. Здесь — PHP-реализация.

Все атрибуты:
- `#[Attribute(...)]` с явными target'ами.
- Конструктор с `public readonly` параметрами (позиционные аргументы).
- `final class` (не наследуются).

### 5.1. Property

```php
<?php
declare(strict_types=1);

#[Attribute(Attribute::TARGET_PROPERTY)]
final class Property
{
    public function __construct(public readonly Type $type) {}
}
```

Target — только `PROPERTY`. На параметре — `R7.invalid-target` (анализатор).

### 5.2. Parameter

```php
<?php
declare(strict_types=1);

#[Attribute(Attribute::TARGET_PARAMETER)]
final class Parameter
{
    public function __construct(
        public readonly string $name,
        public readonly Type $type,
    ) {}
}
```

Target — только `PARAMETER`. `$name` — имя параметра (строка, без `$`).

### 5.3. Variable

```php
<?php
declare(strict_types=1);

#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Variable
{
    public function __construct(
        public readonly string $name,
        public readonly Type $type,
    ) {}
}
```

Target — `METHOD`, `FUNCTION`. `$name` — имя локальной переменной (строка, без `$`).

### 5.4. Returns

```php
<?php
declare(strict_types=1);

#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Returns
{
    public function __construct(public readonly Type $type) {}
}
```

Target — `METHOD`, `FUNCTION`.

### 5.5. Unit

```php
<?php
declare(strict_types=1);

#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Unit {}
```

Target — `METHOD`, `FUNCTION`. Пустой маркер (нет конструктора).

### 5.6. Nothing

```php
<?php
declare(strict_types=1);

#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Nothing {}
```

Target — `METHOD`, `FUNCTION`. Пустой маркер.

### 5.7. Immutable

```php
<?php
declare(strict_types=1);

#[Attribute(Attribute::TARGET_PROPERTY | Attribute::TARGET_CLASS)]
final class Immutable {}
```

Target — `PROPERTY`, `CLASS`. На классе — все свойства immutable. Per-property на `#[Immutable]`-классе — `R8.redundant-marker`.

### 5.8. Cloneable

```php
<?php
declare(strict_types=1);

#[Attribute(Attribute::TARGET_CLASS)]
final class Cloneable {}
```

Target — только `CLASS`. Маркер: класс разрешает `clone`.

### 5.9. VisibleAs

```php
<?php
declare(strict_types=1);

#[Attribute(
    Attribute::TARGET_PROPERTY
    | Attribute::TARGET_METHOD
    | Attribute::TARGET_CLASS_CONSTANT
)]
final class VisibleAs
{
    public function __construct(public readonly Visibility $visibility) {}
}
```

Target — `PROPERTY`, `METHOD`, `CLASS_CONSTANT`. На параметре — `R7.invalid-target`. Константы: `Public` или `Private` (`Protected` — `R14.protected-constant-forbidden`).

### 5.10. Throws

```php
<?php
declare(strict_types=1);

#[Attribute(Attribute::TARGET_METHOD | Attribute::TARGET_FUNCTION)]
final class Throws
{
    public function __construct(public readonly ObjectOf $exception) {}
}
```

Target — `METHOD`, `FUNCTION`. Принимает `ObjectOf(FQCN)` — класс, реализующий `ThrowablePayload`. Может быть несколько `#[Throws]` на одном методе.

**Почему `ObjectOf`, не `string`:** `#[Throws(new ObjectOf(OrderNotFound::class))]` — рефакторинг-безопасно (`::class` резолвится на этапе компиляции). Строка `'OrderNotFound'` не обновится при переименовании класса.

**Почему не `ThrowablePayload` напрямую:** атрибут принимает **дескриптор типа** (`ObjectOf`), не значение. Семантика — в `Lefu — Specification` §5.8.

### 5.11. Doc

```php
<?php
declare(strict_types=1);

#[Attribute(
    Attribute::TARGET_CLASS
    | Attribute::TARGET_METHOD
    | Attribute::TARGET_FUNCTION
    | Attribute::TARGET_PROPERTY
    | Attribute::TARGET_CLASS_CONSTANT
)]
final class Doc
{
    public function __construct(public readonly string $text) {}
}
```

Target — `CLASS`, `METHOD`, `FUNCTION`, `PROPERTY`, `CLASS_CONSTANT`. Принимает `string`. Многострочный текст — `\n` или heredoc.


## 6. Visibility (enum)

```php
<?php
declare(strict_types=1);

enum Visibility: string
{
    case Private   = 'private';
    case Protected = 'protected';
    case Public    = 'public';
}
```

**Отдельно от `Type`.** `Visibility` — не тип значения, это модификатор видимости. Используется в `#[VisibleAs]`. Не реализует `Type` (не принимает значения, не описывает тип).

**`Protected`** — разрешён в `#[VisibleAs]` для методов и свойств, но не для констант (`R14.protected-constant-forbidden`).


## 7. ThrowablePayload

```php
<?php
declare(strict_types=1);

interface ThrowablePayload {}
```

**Пустой маркер-интерфейс.** Класс реализует `ThrowablePayload`, если его экземпляр может быть payload для `ThrownValue` (stdlib).

**Почему в attributes, не в stdlib:** `#[Throws]` (атрибут языка) принимает `ObjectOf(ThrowablePayload::class)`. Если `ThrowablePayload` в stdlib, то attributes зависит от stdlib — нарушение слоёв. `ThrowablePayload` — часть языка, не часть модели ошибок.

**Payload — данные, не поведение.** Не имеет методов. Никаких `recover()`, `describe()`. Семантика — в `Lefu — Specification` §6.2.

**Payload — `#[Immutable]`-класс** (рекомендация, не требование runtime). Ошибка не меняется после создания. Анализатор проверяет, что payload-классы `#[Immutable]`? Нет — это рекомендация, не правило. Пользователь может сделать mutable payload, но это против философии.


## 8. Контракты

> Семантика (ручная реализация, без `With*`-трейтов, семантическая доказуемость невозможна) — в `Lefu — Specification` §15.2. Здесь — PHP-интерфейсы.

**Контракты — только интерфейсы.** Без трейтов. Без автоматической реализации. Пользователь пишет `equals`/`hashCode`/`compareTo` вручную в каждом классе.

**Почему в attributes, не в stdlib:** `Types::matches($x, Equatable::class)` — narrowing работает с контрактами. `Equatable` — часть языка (как `Type`), не часть stdlib. `Result`/`ThrownValue` — stdlib, потому что опциональны.

### 8.1. Equatable

```php
<?php
declare(strict_types=1);

interface Equatable
{
    public function equals(mixed $other): bool;
}
```

**`mixed $other`** — нативный `mixed`, не `Special::Any`. `equals` принимает любой тип (для сравнения с разными классами). Сужение — через `Types::matches($other, new ObjectOf(self::class))` в теле.

### 8.2. Hashable

```php
<?php
declare(strict_types=1);

interface Hashable
{
    public function hashCode(): int;
}
```

**`int`** — нативный `int`. Identity hash через `spl_object_id($this)` — легитимно для identity-семантики. Value hash — комбинация хешей полей, вручную.

### 8.3. Comparable

```php
<?php
declare(strict_types=1);

interface Comparable
{
    public function compareTo(mixed $other): int;
}
```

**Возврат `int`:** `< 0` — меньше, `0` — равно, `> 0` — больше. Консистентность с `Equatable` — на усмотрение пользователя (если класс реализует оба, `compareTo($x) === 0` должно соответствовать `equals($x) === true`). Анализатор не проверяет это — семантика.


## 9. Что НЕ входит в пакет

Эти компоненты — в `Lefu Stdlib — Specification`:
- `Result` — модель ошибок (значение).
- `ThrownValue` — контейнер payload, наследует `Exception`.
- `Output` — вывод в stdout/stderr/debug.
- `Files`, `Arrays`, `Strings`, `DI`, `Logger` — `[OPEN]` / `[DEFERRED]`.

**Почему `Result`/`ThrownValue` в stdlib:** модель ошибок **опциональна**. Пользователь может писать без `Result` (только нативные исключения в bridge) или без `ThrownValue` (только `Result`). Но `#[Throws]` (часть языка) требует `ThrowablePayload` — маркер в attributes, не в stdlib.

**Почему `Output` в stdlib:** вывод — не часть языка. Пользователь может не использовать `Output` (хотя `echo` запрещён в closed, `Output` — единственный способ вывода в v1). Это stdlib-привилегия, не язык.


## 10. Привилегии runtime-пакета

`lefu/attributes` написан на **обычном PHP 8.5**, не на Lefu. Внутри пакета допустимо то, что запрещено пользовательскому коду:

| Привилегия | Где | Почему |
|---|---|---|
| `is_int`, `is_string`, `is_bool`, `is_float`, `is_array`, `is_object` | `Scalar::accepts`, `Special::accepts` | Runtime-проверка типа значения. |
| `instanceof` | `ObjectOf::accepts` | Runtime-проверка класса/интерфейса. |
| `array_is_list` | `ListOf::accepts` | Runtime-проверка list. |
| `\InvalidArgumentException` | `Union::__construct` | Защита от некорректного конструирования. |
| `public readonly` | Все классы | Нативный модификатор, допустим в пакете. |
| `declare(strict_types=1)` | Все файлы | Обязателен (как в любом closed-файле). |

**Привилегии не наследуются пользовательским кодом.** Пользовательский Lefu-код не может использовать `is_int` (R14.native-typeguard-forbidden), `instanceof` (R14.instanceof-forbidden), `readonly` (R8.readonly-forbidden). Пакет — bootstrap, не пример для подражания.


## 11. Версионирование и стабильность

**Semantic versioning.**

- **Major** (1.0.0 → 2.0.0) — breaking changes: удаление класса/enum/атрибута, изменение сигнатуры, изменение runtime-поведения (`accepts`).
- **Minor** (1.0.0 → 1.1.0) — добавление: новый атрибут, новый метод, новый enum-case (осторожно: добавление case в `Scalar`/`Special` — breaking для `match` без `default`).
- **Patch** (1.0.0 → 1.0.1) — bugfix: исправление `accepts`, `describe`, без изменения API.

**Стабильность имён:** имена классов/enum'ов/атрибутов — **часть синтаксиса диалекта**. Переименование — major breaking change. Пользовательский код сломается. Поэтому имена фиксируются в `Lefu — Specification` §1.4 и здесь.

**Конфликты с PHP core:** если PHP введёт `Map`/`Union`/`Property`/`Parameter`/`Variable`/`Types` — major breaking change, решение по мере поступления (см. `Lefu — Specification` §15.15).

**Версия PHP:** `>=8.5`. Понижение невозможно (нужны `#[\DelayedTargetValidation]`, `TARGET_ALL` = 127). Повышение — по мере выхода новых версий, если нужны новые фичи.
