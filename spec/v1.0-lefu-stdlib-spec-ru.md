## 1. Назначение и связь с диалектом

`lefu/stdlib` — стандартная библиотека Lefu. Содержит **опциональные** компоненты, которые делают код на Lefu практичным, но не являются частью синтаксиса языка.

**Что в stdlib:**
- **Модель ошибок** — `Result` (значение), `ThrownValue` (контейнер payload). Семантика — в `Lefu — Specification` §6.
- **Вывод** — `Output` (stdout/stderr/debug). Семантика — в `Lefu — Specification` §17.2.
- **`[OPEN]`/`[DEFERRED]`** — `Files`, `Arrays`, `Strings`, `DI`, `Logger`. API не спроектирован.

**Что НЕ в stdlib (в attributes):**
- `ThrowablePayload` — маркер-интерфейс для `#[Throws]`. Часть языка, не модель ошибок.
- `Equatable`, `Hashable`, `Comparable` — контракты. Часть языка.
- `Type`, `Scalar`, `Special`, `ObjectOf`, `ListOf`, `Map`, `Union`, `Types` — пространство типов. Часть языка.

**Почему `ThrowablePayload` в attributes, а `Result`/`ThrownValue` в stdlib:** `#[Throws]` (часть языка) требует `ThrowablePayload`. `Result`/`ThrownValue` — опциональны: пользователь может писать без `Result` (только нативные исключения в bridge) или без `ThrownValue` (только `Result`). Это модель ошибок, не синтаксис.

**Все имена — в глобальном namespace** (без префикса `Lefu\`). См. `Lefu — Specification` §1.4.

**Пакет написан на обычном PHP 8.5, не на Lefu.** Bootstrap: Lefu ещё не может анализировать сам себя. Внутри пакета допустимы привилегии (§7).


## 2. Установка и autoloading

### 2.1. Установка

```bash
composer require lefu/stdlib
```

Пакет — **runtime-зависимость**. Он нужен в production: `Result`, `ThrownValue`, `Output` используются в пользовательском коде.

`lefu/attributes` устанавливается автоматически как зависимость (см. §3).

### 2.2. Autoloading

**Classmap, не PSR-4.** Причина та же, что в attributes: глобальный namespace.

`composer.json` пакета:

```json
{
  "name": "lefu/stdlib",
  "description": "Lefu standard library: Result, ThrownValue, Output",
  "type": "library",
  "license": "MIT",
  "require": {
    "php": ">=8.5",
    "lefu/attributes": "^1.0"
  },
  "autoload": {
    "classmap": ["src/"]
  }
}
```

Структура `src/` (на v1):

```
src/
├── Result.php
├── ThrownValue.php
└── Output.php
```

Будущие модули (`Files`, `Arrays`, `Strings`, `DI`, `Logger`) — `[OPEN]`, появятся в `src/` по мере спецификации.

### 2.3. Конфликты имён

`Result`, `Output` — высокорисковые имена. Если PHP core введёт одно из них — конфликт. Решение — по мере поступления (см. `Lefu — Specification` §15.15).


## 3. Зависимости

**Runtime-зависимости:**
- `php: >=8.5` — нужны enum'ы, `new` в аргументах атрибутов, `#[\DelayedTargetValidation]`.
- `lefu/attributes: ^1.0` — `Result` использует `ThrowablePayload`, `ThrownValue`; `Output` не использует attributes напрямую, но пакет зависит от фундамента.

**Dev-зависимости:** нет.

**Направление зависимости:** `lefu/stdlib` → `lefu/attributes`. Не наоборот. Attributes — фундамент, stdlib — надстройка.

**`lefu/analyzer`** — dev-зависимость пользовательского проекта, не stdlib. Анализатор проверяет Lefu-код, stdlib — runtime.


## 4. Result (модель ошибок)

> Семантика (два мира, catch только для `ThrownValue`, bridge возвращает `Result`) — в `Lefu — Specification` §6. Здесь — PHP-код.

```php
<?php
declare(strict_types=1);

#[Immutable]
final class Result
{
    #[Property(new Union(new ObjectOf(ThrowablePayload::class), Scalar::Null))]
    #[VisibleAs(Visibility::Private)]
    var $error;

    #[Property(Special::Any)]
    #[VisibleAs(Visibility::Private)]
    var $value;

    #[Parameter('error', new Union(new ObjectOf(ThrowablePayload::class), Scalar::Null))]
    #[Parameter('value', Special::Any)]
    #[VisibleAs(Visibility::Private)]
    function __construct($error, $value)
    {
        $this->error = $error;
        $this->value = $value;
    }

    #[Parameter('value', Special::Any)]
    #[Returns(new ObjectOf(self::class))]
    static function ok($value)
    {
        return new self(null, $value);
    }

    #[Parameter('payload', new ObjectOf(ThrowablePayload::class))]
    #[Returns(new ObjectOf(self::class))]
    static function fail($payload)
    {
        return new self($payload, null);
    }

    #[Returns(Scalar::Bool)]
    function isOk()
    {
        return $this->error === null;
    }

    #[Returns(Scalar::Bool)]
    function isErr()
    {
        return $this->error !== null;
    }

    #[Returns(Special::Any)]
    #[Throws(new ObjectOf(ThrowablePayload::class))]
    function unwrap()
    {
        if ($this->error !== null) {
            throw new ThrownValue($this->error);
        }
        return $this->value;
    }

    #[Parameter('default', Special::Any)]
    #[Returns(Special::Any)]
    function unwrapOr($default)
    {
        if ($this->error !== null) {
            return $default;
        }
        return $this->value;
    }

    #[Returns(new Union(new ObjectOf(ThrowablePayload::class), Scalar::Null))]
    function error()
    {
        return $this->error;
    }
}
```

### 4.1. Почему `#[Immutable]`

`Result` — `#[Immutable]`-класс. Все свойства set в конструкторе, не переприсваиваются. Это **критично** для property narrowing в `unwrap()`: `$this->error !== null` сужает `$this->error` до `ObjectOf(ThrowablePayload)` **только потому**, что `Result` immutable (см. `Lefu — Specification` §9.4.1). Для mutable-класса narrowing не работал бы.

### 4.2. Почему один класс, не `Ok`/`Err`

Без дженериков `Ok`/`Err` не выразить тип значения. Один класс с `error: Union(Payload, Null)` и `value: Special::Any` — минимально достаточно. Семантика — в `Lefu — Specification` §6.4.

### 4.3. `value: Special::Any`

Требует сужения через `Types::matches` вне catch. Альтернатива — дженерики, которых нет. Сужение `value` — ответственность пользователя:

```php
$result = findOrder($id);
if ($result->isOk()) {
    $value = $result->unwrap();
    if (Types::matches($value, new ObjectOf(Order::class))) {
        // $value: ObjectOf(Order)
    }
}
```

### 4.4. `map` — `[DEFERRED]` (v2)

`Result::map(callable-object): Result` не реализован в v1. Без дженериков `map` — синтаксический сахар, скрывающий `Special::Any`. Пользователь пишет `if ($r->isOk()) { ... }` явно. См. `Lefu — Specification` §6.4.

### 4.5. Привилегии в реализации

`Result` использует:
- `new self(...)` — `new` с известным классом, не динамический. OK.
- `$this->error === null` / `!== null` — strict comparison, разрешён (R17).
- `$this->error` после `!== null` — property narrowing (работает, т.к. `#[Immutable]`).

Нативных функций (`is_int` и т.д.) нет. `throw new ThrownValue(...)` — разрешено (stdlib-привилегия, §7).


## 5. ThrownValue (контейнер payload)

> Семантика (payload — данные, не поведение; `getMessage()` = FQCN; bridge не бросает `ThrownValue`) — в `Lefu — Specification` §6.3. Здесь — PHP-код.

```php
<?php
declare(strict_types=1);

final class ThrownValue extends \Exception
{
    #[Property(new ObjectOf(ThrowablePayload::class))]
    #[VisibleAs(Visibility::Private)]
    #[Immutable]
    var $payload;

    #[Parameter('payload', new ObjectOf(ThrowablePayload::class))]
    function __construct($payload)
    {
        parent::__construct(get_class($payload));
        $this->payload = $payload;
    }

    #[Returns(new ObjectOf(Result::class))]
    function toResult()
    {
        return Result::fail($this->payload);
    }
}
```

### 5.1. Почему `extends \Exception`

**Вынужденный заполнитель.** PHP-рантайм требует `extends Exception` (или `extends Error`) для `Throwable`. Пользовательский Lefu-код не может наследовать `Exception` (`R13.extends-forbidden`). Stdlib — может (привилегия, §7).

**`\Exception`** — нативное исключение, FQCN с ведущим `\`. Это не `ObjectOf(Exception::class)`, а нативный `extends`. Внутри пакета — допустимо.

### 5.2. `getMessage()` = FQCN

`parent::__construct(get_class($payload))` — `getMessage()` возвращает FQCN payload'а. Например, `"App\Model\OrderNotFound"`. Машиночитаемо, уникально. Читаемый текст — через `#[Doc]` на payload-классе или `Logger` (stdlib, `[OPEN]`). См. `Lefu — Specification` §6.3.

**Почему не `describe()` в payload:** payload — данные, не поведение. `describe()` был бы поведением. FQCN — достаточно для логов.

### 5.3. Почему не `#[Cloneable]`

Клонирование исключений — ошибка дизайна. `ThrownValue` не `#[Cloneable]`. `clone $e` — `R17.clone-not-cloneable` (если пользователь попытается).

### 5.4. Привилегии в реализации

`ThrownValue` использует:
- `extends \Exception` — вынужденный заполнитель (stdlib-привилегия).
- `parent::__construct(...)` — вызов родительского конструктора (привилегия, только для stdlib-исключений).
- `get_class($payload)` — нативная функция, возвращает FQCN. Runtime-привилегия пакета.
- `new self(...)` — в `toResult()` нет, но `Result::fail` использует `new self`. OK.

`throw new ThrownValue(...)` в `Result::unwrap()` — stdlib-привилегия (§7).


## 6. Output (вывод)

> Семантика (stdout/stderr/debug, проглатывание ошибок, `Output` — не часть `Files`) — в `Lefu — Specification` §17.2. Здесь — PHP-код.

```php
<?php
declare(strict_types=1);

#[Immutable]
final class Output
{
    #[Parameter('text', Scalar::String)]
    #[Unit]
    static function write($text)
    {
        fwrite(STDOUT, $text);
    }

    #[Parameter('text', Scalar::String)]
    #[Unit]
    static function error($text)
    {
        fwrite(STDERR, $text);
    }

    #[Parameter('value', Special::Any)]
    #[Unit]
    static function debug($value)
    {
        var_dump($value);
    }
}
```

### 6.1. Почему `fwrite`, не `echo`

`fwrite(STDOUT, $text)` — явная запись в поток. `echo` — языковая конструкция, в closed-файлах запрещена (`R5.echo-forbidden`). Внутри stdlib — `fwrite` (привилегия, §7).

**`STDOUT` / `STDERR`** — предопределённые константы PHP (открытые потоки). Не суперглобалы. Доступны в CLI и в web (с ограничениями).

### 6.2. Проглатывание ошибок

`fwrite` возвращает `int|false`. `Output::write` **игнорирует** возврат. Причина: вывод в stdout — не бизнес-операция; если pipe закрыт — приложение всё равно падает. Для строгого контроля — `Files::writeString` с `Result` (`[OPEN]`). См. `Lefu — Specification` §17.2.

**Почему не `#[Throws]`:** вывод не бросает. Ошибка `fwrite` — `false`, не исключение. Игнорируется.

### 6.3. `var_dump` в `debug`

`Output::debug` использует `var_dump($value)`. `Special::Any` — потому что отладка не типизируется. Пользовательский Lefu-код не может использовать `var_dump` (`R5.dynamic-construct-forbidden`), но stdlib — может (привилегия, §7).

**Формат `var_dump`:** нативный, не кастомный. Если нужен читаемый формат — `[OPEN]` (см. `Lefu — Specification` §17.5).

### 6.4. `Strings::format` — `[OPEN]`

`Output::write` не форматирует. Форматирование — через `Strings::format` (`[OPEN]`). Пример:

```php
Output::write(Strings::format('Hello, %s!', [$name]));
```

`Strings` — `[OPEN]`, API не спроектирован. До появления — конкатенация строк:

```php
Output::write('Hello, ' . $name . '!');
```

### 6.5. Привилегии в реализации

`Output` использует:
- `fwrite(STDOUT, ...)`, `fwrite(STDERR, ...)` — прямая запись в поток (stdlib-привилегия).
- `var_dump($value)` — отладочный вывод (stdlib-привилегия).

Пользовательский Lefu-код не может использовать `fwrite` (R5.dynamic-construct-forbidden), `var_dump` (R5.dynamic-construct-forbidden). `Output` — единственный способ вывода в v1.


## 7. Привилегии stdlib

Stdlib-классы имеют привилегии, которых нет у пользовательского кода. Привилегии — **закрытый список**, не наследуются.

| Привилегия | Где | Обоснование |
|---|---|---|
| `extends Exception` | `ThrownValue` (§5) | PHP-рантайм требует `extends Exception` для `Throwable`. Вынужденный заполнитель. |
| `parent::__construct(...)` | `ThrownValue` (§5) | Вызов родительского конструктора. Только для stdlib-исключений. |
| `get_class($payload)` | `ThrownValue` (§5) | FQCN payload'а для `getMessage()`. Runtime-привилегия пакета. |
| `throw new ThrownValue(...)` | `Result::unwrap()` (§4) | Бросок `ThrownValue` из `Result`. Stdlib — может, пользователь — только в месте throw с payload. |
| `fwrite(STDOUT, ...)` | `Output` (§6) | Прямая запись в поток. Пользователь использует `Output::write`. |
| `fwrite(STDERR, ...)` | `Output` (§6) | Прямая запись в stderr. Пользователь использует `Output::error`. |
| `var_dump` | `Output::debug` (§6) | Отладочный вывод. Пользователь использует `Output::debug`. |
| `finally` без ограничений | stdlib-методы с `with`-паттерном (§6.5.9 `Lefu — Specification`) | Cleanup в stdlib. Конкретные методы (`Files::with`, `Transactions::with`) — `[OPEN]`. |
| `require`/`include` | `Files::requirePhp` (§15.17 `Lefu — Specification`) | Загрузка PHP-файлов. `[OPEN]`. |

**Привилегии не наследуются пользовательским кодом.** Пользователь не может «стать stdlib» и получить `fwrite` напрямую. Это закрытый список.

**Как анализатор проверяет, что класс — stdlib:** по namespace? По конфигу? — `[OPEN]` (см. `Lefu — Specification` §17.5). В v1 — анализатор знает FQCN stdlib-классов (`Result`, `ThrownValue`, `Output`) и разрешает привилегии только для них.

## 9. Что НЕ входит (OPEN/DEFERRED)

### 9.1. Files — `[OPEN]`

`Files::requirePhp(string $path): Special::Any` — альтернатива `include`/`require` (запрещены в closed, `R5.include-forbidden`). API не спроектирован. Спецификация `Files` — отдельный документ. **Приоритет для stdlib:** без `Files::requirePhp` `R5.include-forbidden` создаёт неудобство.

Другие методы `Files` (`open`, `writeString`, `readString`, `with`) — `[OPEN]`.

### 9.2. Arrays — `[OPEN]`

`Arrays::map`, `Arrays::filter`, `Arrays::reduce` — принимают callable-object, не замыкание (R9). Сигнатуры не спроектированы. Пример:

```php
Arrays::map($values, new DoubleInt());
```

`DoubleInt` — callable-object с `__invoke`. Типизация — через `#[Parameter]`/`#[Returns]` в `__invoke`.

### 9.3. Strings — `[OPEN]`

`Strings::format` — `sprintf`-совместимый? Или свой? Не спроектирован. `Strings::replace` — сигнатура не спроектирована.

### 9.4. DI — `[OPEN]`

Контейнер, `[#finalize]` — application-level cleanup. `[#finalize]` — `[DEFERRED]` (зависит от DI). См. `Lefu — Specification` §11.8.

### 9.5. Logger — `[OPEN]`

Уровни, формат, вывод через `Output`? Не спроектирован. `Output::debug` — для отладки, не для логирования.


## 10. Версионирование и стабильность

**Semantic versioning.**

- **Major** (1.0.0 → 2.0.0) — breaking changes: удаление класса/метода, изменение сигнатуры `Result`/`ThrownValue`/`Output`.
- **Minor** (1.0.0 → 1.1.0) — добавление: новый метод, новый модуль (`Files`, `Arrays`), новый `[ACCEPTED]` компонент.
- **Patch** (1.0.0 → 1.0.1) — bugfix: исправление `unwrap`, `getMessage`, без изменения API.

**Стабильность имён:** `Result`, `ThrownValue`, `Output` — **часть stdlib API**. Переименование — major breaking change.

**Зависимость от attributes:** `lefu/stdlib ^1.0` требует `lefu/attributes ^1.0`. Major-версия attributes → major-версия stdlib.

**Конфликты с PHP core:** `Result`, `Output` — высокорисковые. Если PHP введёт одно из них — major breaking change (см. `Lefu — Specification` §15.15).

**Версия PHP:** `>=8.5`. Понижение невозможно (нужен `lefu/attributes` ^1.0, который требует 8.5).
